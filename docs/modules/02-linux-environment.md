# Модуль 2. Підготовка Linux-середовища та основи віддаленого доступу

## 1. Мета модуля

Мета модуля — навчитися підготувати робоче середовище Linux для подальшого вивчення операційної системи, виконувати початкове налаштування Ubuntu, перевіряти стан системи та мережі, а також ознайомитися з принципами віддаленого доступу через SSH.

Під час вивчення модуля студент створить або підготує Linux-середовище, перевірить його конфігурацію, навчиться отримувати інформацію про мережеві інтерфейси та за потреби підключатиметься до віддаленого Linux-сервера.

Основний сценарій передбачає використання Ubuntu у віртуальній машині VirtualBox. Якщо Linux уже встановлено на комп'ютері, дозволяється використовувати наявну систему. Доступ до віддаленого сервера розглядається як додатковий варіант практичної роботи.

## 2. Результати навчання

Після опрацювання модуля студент зможе:

- пояснювати призначення віртуалізації під час організації навчального Linux-середовища;
- розрізняти локальну операційну систему, віртуальну машину та віддалений сервер;
- обґрунтовувати вибір дистрибутива Linux для навчальних завдань;
- створювати віртуальну машину з Ubuntu та визначати її основні параметри;
- виконувати початкове налаштування операційної системи;
- перевіряти версію дистрибутива, ядра та основні системні ресурси;
- визначати мережеві інтерфейси, IP-адреси, маршрут за замовчуванням і DNS-сервери;
- пояснювати відмінності між мережевими режимами NAT, Bridged Adapter та Host-only Adapter у VirtualBox;
- пояснювати призначення SSH та принципи його використання;
- перевіряти доступність SSH-сервера та встановлювати SSH-з'єднання з дозволеним віддаленим вузлом;
- виконувати базову діагностику Linux-середовища;
- дотримуватися основних правил безпеки під час налаштування системи та віддаленого доступу.

## 3. Варіанти організації Linux-середовища

Для практичного вивчення Linux потрібне середовище, у якому студент може виконувати команди, змінювати конфігурацію, встановлювати програмне забезпечення та спостерігати за роботою операційної системи.

Існує декілька способів організації такого середовища.

### 3.1. Linux, встановлений безпосередньо на комп'ютері

У цьому випадку Linux є основною операційною системою комп'ютера або встановлений поряд з іншою операційною системою.

Переваги:

- безпосередній доступ до апаратних ресурсів;
- відсутність додаткового шару віртуалізації;
- можливість досліджувати роботу операційної системи на фізичному обладнанні.

Недоліки:

- зміни конфігурації можуть впливати на робоче середовище;
- експерименти з дисками, завантаженням і мережевими налаштуваннями потребують особливої обережності;
- відновлення системи після помилки може бути складнішим.

Такий варіант підходить студентам, які вже використовують Linux і розуміють принципи роботи з операційною системою.

### 3.2. Linux у віртуальній машині

Віртуальна машина — програмно створене середовище, яке імітує роботу окремого комп'ютера.

На фізичному комп'ютері працює основна операційна система, а всередині віртуальної машини запускається гостьова операційна система.

Наприклад:

- основна операційна система — Windows, Linux або macOS;
- програмне забезпечення віртуалізації — Oracle VirtualBox;
- гостьова операційна система — Ubuntu Linux.

Переваги:

- ізоляція навчальної системи від основної ОС;
- можливість створювати знімки стану віртуальної машини;
- можливість експериментувати з налаштуваннями;
- відносно просте відновлення початкового стану;
- можливість створювати окремі віртуальні машини для різних лабораторних робіт.

Недоліки:

- частина ресурсів фізичного комп'ютера виділяється віртуальній машині;
- продуктивність залежить від характеристик обладнання;
- конфігурація мережі може бути складнішою, ніж на фізичному комп'ютері.

**Для цього курсу віртуальна машина є рекомендованим середовищем навчання.**

### 3.3. Віддалений Linux-сервер

Віддалений сервер — це комп'ютер, до якого користувач підключається через мережу.

Віддалений Linux-сервер може бути:

- фізичним сервером в університетській лабораторії;
- віртуальною машиною на сервері навчального закладу;
- хмарним віртуальним сервером;
- іншим Linux-комп'ютером у локальній мережі.

Для взаємодії з таким сервером часто використовується протокол SSH.

Переваги:

- можливість працювати з Linux без встановлення системи на власний комп'ютер;
- знайомство з типовим середовищем системного адміністрування;
- можливість виконувати команди на іншому комп'ютері;
- можливість використовувати централізоване навчальне середовище.

Недоліки:

- необхідність мати мережеве підключення;
- залежність від доступності сервера;
- необхідність отримати обліковий запис і дозвіл на підключення;
- обмеження прав користувача, установлені адміністратором.

Підключатися можна лише до власних серверів або вузлів, доступ до яких надано адміністратором.

### 3.4. Порівняння варіантів

| Критерій | Linux на комп'ютері | Віртуальна машина | Віддалений сервер |
|---|---|---|---|
| Потрібне локальне встановлення Linux | Так | Потрібно встановити гостьову ОС | Ні |
| Ізоляція від основної ОС | Залежить від конфігурації | Висока за належного налаштування | Зазвичай висока |
| Потрібне стабільне мережеве з'єднання | Не завжди | Не для всіх локальних завдань | Так |
| Можливість створення знімків стану | Залежить від інструментів | Так | Залежить від платформи |
| Доступ до системних ресурсів | Безпосередній | Виділені ресурси хоста | Ресурси сервера |
| Рекомендований варіант для початківця | Можливо | Так | Як додатковий варіант |

У межах курсу можна використовувати будь-який із цих варіантів, якщо він забезпечує виконання практичних завдань.

## 4. Вибір дистрибутива Linux

Для навчальних завдань доцільно використовувати дистрибутив, який має стабільні випуски, доступну документацію та підтримку основних засобів адміністрування.

### 4.1. Ubuntu Desktop

Ubuntu Desktop — дистрибутив Linux із графічним середовищем.

Він підходить для початкового вивчення Linux, оскільки дозволяє одночасно працювати з графічним інтерфейсом і командним рядком.

Переваги:

- графічний інсталятор;
- зручне початкове налаштування;
- доступ до великої кількості пакетів;
- значний обсяг навчальної документації;
- можливість поступово переходити до адміністрування через термінал.

### 4.2. Ubuntu Server

Ubuntu Server призначений для серверних сценаріїв використання.

Типова інсталяція не потребує повноцінного графічного робочого середовища.

Переваги:

- менші вимоги до ресурсів за відсутності графічного середовища;
- практична орієнтація на адміністрування серверів;
- можливість відразу працювати з командним рядком;
- придатність для подальшого вивчення SSH, служб і мережевих налаштувань.

Ubuntu Server рекомендований студентам, які вже мають базовий досвід роботи з командним рядком.

### 4.3. Debian

Debian — дистрибутив Linux, відомий увагою до стабільності та широким використанням у серверних середовищах.

Він підходить для вивчення адміністрування, роботи з пакетами, службами, користувачами та мережевими налаштуваннями.

### 4.4. Рекомендації щодо вибору

| Дистрибутив | Типове призначення | Рекомендація |
|---|---|---|
| Ubuntu Desktop LTS | Навчання, робочі станції | Основний варіант для початківців |
| Ubuntu Server LTS | Сервери, адміністрування | Для практики командного рядка |
| Debian Stable | Сервери, навчальні та інфраструктурні системи | Альтернативний варіант |

LTS означає Long Term Support — тривалу підтримку відповідного випуску.

Під час вибору версії слід користуватися офіційною документацією та перевіряти актуальний статус підтримки.

**Важливо:** для цього курсу не потрібно встановлювати найновіший дистрибутив за будь-яку ціну. Перевагу варто надавати версії, яка підтримується, сумісна з обладнанням і відповідає вимогам навчальних завдань.

## 5. Основи віртуалізації

### 5.1. Основні поняття

Віртуалізація дозволяє запускати декілька ізольованих операційних систем на одному фізичному комп'ютері.

Основні поняття:

- **Хостова система (host OS)** — операційна система фізичного комп'ютера.
- **Гостьова система (guest OS)** — операційна система, запущена у віртуальній машині.
- **Гіпервізор** — програмне забезпечення, яке забезпечує створення та виконання віртуальних машин.
- **Віртуальний диск** — файл або набір файлів, які використовуються як диск віртуальної машини.
- **Віртуальна мережа** — програмно організоване мережеве підключення віртуальної машини.
- **Знімок стану (snapshot)** — збережений стан віртуальної машини, до якого можна повернутися за підтримки відповідного програмного забезпечення.

### 5.2. Приклади програмного забезпечення для віртуалізації

| Програмне забезпечення | Призначення |
|---|---|
| Oracle VirtualBox | Запуск віртуальних машин на персональному комп'ютері |
| VMware Workstation | Створення та запуск віртуальних машин |
| KVM/QEMU | Віртуалізація в Linux |
| Hyper-V | Віртуалізація у відповідних редакціях Windows |
| Proxmox VE | Платформа віртуалізації серверів |

У цьому модулі основний сценарій передбачає використання Oracle VirtualBox. Якщо на комп'ютері вже налаштоване інше середовище віртуалізації, його також можна використовувати.

### 5.3. Ресурси віртуальної машини

Під час створення віртуальної машини необхідно визначити:

- кількість віртуальних процесорів;
- обсяг оперативної пам'яті;
- розмір віртуального диска;
- мережевий режим;
- тип гостьової операційної системи.

Віртуальна машина використовує ресурси фізичного комп'ютера. Виділення надмірної кількості ресурсів може негативно вплинути на роботу хостової системи.

Приклад початкової конфігурації Ubuntu Desktop:

| Параметр | Рекомендоване значення для навчання |
|---|---|
| Віртуальні процесори | 2 |
| Оперативна пам'ять | 4 ГБ, якщо дозволяють ресурси хоста |
| Віртуальний диск | 25–40 ГБ |
| Формат диска | Динамічний або фіксований |
| Мережа | NAT |
| ISO-образ | Офіційний образ Ubuntu відповідної архітектури |

Це орієнтовна конфігурація, а не універсальна вимога. Точні параметри залежать від версії Ubuntu та можливостей фізичного комп'ютера.

Для Ubuntu Server без графічного середовища часто достатньо меншого обсягу пам'яті та дискового простору.

**Не виділяйте віртуальній машині всю оперативну пам'ять або всі процесорні ресурси комп'ютера.** Залишайте достатньо ресурсів для роботи хостової системи.

### 5.4. Знімки стану

Знімок стану дає змогу зберегти певний стан віртуальної машини.

Наприклад, до виконання лабораторної роботи можна створити знімок:

`Ubuntu — початковий стан`

Після невдалого експерименту знімок може допомогти повернутися до попереднього стану.

Проте знімок не замінює резервне копіювання:

- файли знімків можуть зберігатися на тому самому фізичному диску;
- пошкодження фізичного диска може призвести до втрати і віртуальної машини, і знімків;
- знімки можуть займати значний обсяг дискового простору;
- деякі операції відновлення можуть втратити зміни, зроблені після створення знімка.

Перед виконанням ризикованих операцій потрібно розуміти, який саме стан буде відновлено.

## 6. Підготовка VirtualBox

### 6.1. Перевірка готовності комп'ютера

Перед створенням віртуальної машини потрібно переконатися, що комп'ютер має достатньо ресурсів.

У Linux можна використати такі команди:

```bash
lscpu
free -h
df -h
```

Призначення команд:

| Команда | Призначення |
|---|---|
| `lscpu` | Інформація про процесор |
| `free -h` | Стан оперативної пам'яті |
| `df -h` | Використання файлових систем |

Якщо хостовою системою є Windows, для перевірки ресурсів можна використати диспетчер завдань і системні засоби керування дисками.

Для macOS інформацію про ресурси можна отримати через системні налаштування та системні утиліти.

### 6.2. Завантаження VirtualBox

Завантажуйте інсталяційні файли лише з офіційного сайту:

- [Oracle VirtualBox](https://www.virtualbox.org/)

Для деяких систем можуть бути потрібні додаткові компоненти або налаштування віртуалізації.

Якщо VirtualBox не запускає віртуальну машину, причиною можуть бути:

- вимкнена апаратна віртуалізація;
- несумісність із конфігурацією гіпервізора;
- проблеми з драйверами або модулями ядра;
- нестача оперативної пам'яті;
- недостатній вільний простір на диску.

Налаштування апаратної віртуалізації залежать від моделі комп'ютера та його прошивки. Не змінюйте параметри BIOS/UEFI без розуміння призначення відповідних опцій.

### 6.3. Завантаження Ubuntu

Офіційний сайт Ubuntu:

- [Завантаження Ubuntu Desktop](https://ubuntu.com/download/desktop)
- [Завантаження Ubuntu Server](https://ubuntu.com/download/server)

Після завантаження інсталяційного ISO-образу перевірте, що файл відповідає потрібній архітектурі та версії системи.

Для підвищення надійності можна перевірити контрольну суму ISO-образу, використовуючи інструкції на офіційному сайті Ubuntu.

Приклад перевірки SHA-256 у Linux:

```bash
sha256sum ubuntu.iso
```

У цьому прикладі `ubuntu.iso` — умовна назва файлу. Замість неї потрібно вказати фактичну назву завантаженого образу.

Отримане значення необхідно порівняти з офіційною контрольною сумою відповідного образу.

## 7. Створення віртуальної машини

Нижче наведено загальну послідовність дій для створення навчальної віртуальної машини в VirtualBox.

Назви окремих пунктів інтерфейсу можуть відрізнятися залежно від версії VirtualBox.

### 7.1. Створення нової машини

1. Запустіть VirtualBox.
2. Створіть нову віртуальну машину.
3. Укажіть зрозумілу назву, наприклад `Ubuntu-Linux-Course`.
4. Виберіть тип операційної системи Linux.
5. Укажіть ISO-образ Ubuntu.
6. Визначте обсяг оперативної пам'яті.
7. Виділіть кількість віртуальних процесорів.
8. Створіть віртуальний диск.
9. Перевірте параметри конфігурації перед запуском.

Якщо версія VirtualBox пропонує автоматизоване встановлення, студент повинен розуміти, які параметри задаються автоматично. Для навчання корисно ознайомитися з основними етапами інсталяції вручну.

### 7.2. Вибір оперативної пам'яті

Обсяг оперативної пам'яті визначається потребами гостьової системи та можливостями хоста.

Наприклад, якщо фізичний комп'ютер має 8 ГБ оперативної пам'яті, виділення 6–7 ГБ віртуальній машині може залишити недостатньо ресурсів для основної операційної системи.

Потрібно враховувати:

- ресурси, необхідні хостовій ОС;
- ресурси, потрібні гостьовій ОС;
- інші програми, які працюють одночасно;
- характер навчальних завдань.

### 7.3. Вибір віртуального диска

Віртуальний диск може бути динамічним або фіксованого розміру.

**Динамічний диск** поступово займає фізичний простір у міру запису даних, але має встановлене обмеження максимального розміру.

**Фіксований диск** зазвичай займає виділений обсяг фізичного простору вже під час створення.

Наприклад, динамічний диск із максимальною місткістю 30 ГБ спочатку може займати менше місця, але його фактичний розмір збільшуватиметься в міру заповнення.

Потрібно стежити за вільним простором на фізичному диску хоста.

### 7.4. Початкові мережеві налаштування

Для першого запуску Ubuntu зазвичай достатньо режиму NAT.

У цьому режимі віртуальна машина може використовувати мережеве підключення хоста для виходу в інтернет, але не обов'язково буде безпосередньо доступною з інших пристроїв локальної мережі.

Детальніше мережеві режими розглянуто в розділі 10.

## 8. Встановлення Ubuntu

### 8.1. Запуск інсталятора

Після підготовки віртуальної машини:

1. Запустіть віртуальну машину.
2. Переконайтеся, що завантаження відбувається з ISO-образу.
3. Запустіть інсталятор Ubuntu.
4. Виберіть мову інтерфейсу.
5. Виберіть параметри клавіатури.
6. Налаштуйте мережу, якщо цього вимагає інсталятор.
7. Виберіть тип інсталяції.
8. Визначте параметри диска відповідно до інструкцій інсталятора.
9. Створіть користувача.
10. Завершіть інсталяцію та перезапустіть віртуальну машину.

Інтерфейс інсталятора може змінюватися між випусками Ubuntu. Орієнтуйтеся на актуальні інструкції офіційної документації.

### 8.2. Створення користувача

Під час інсталяції необхідно створити обліковий запис користувача.

Вибирайте зрозуміле ім'я користувача, яке відповідає правилам системи.

Для навчальної роботи важливо розрізняти:

- ім'я користувача;
- пароль користувача;
- домашній каталог;
- звичайні права користувача;
- адміністративні повноваження.

Не використовуйте один і той самий пароль для різних систем. Не зберігайте паролі у відкритому вигляді у звітах або репозиторіях.

### 8.3. Перше завантаження

Після завершення інсталяції увійдіть у систему.

Відкрийте термінал і виконайте:

```bash
whoami
hostname
pwd
```

Команди показують:

- `whoami` — ім'я поточного користувача;
- `hostname` — ім'я комп'ютера;
- `pwd` — поточний робочий каталог.

Потім перевірте версію операційної системи:

```bash
cat /etc/os-release
uname -r
```

Перша команда показує інформацію про дистрибутив, а друга — версію ядра Linux.

### 8.4. Оновлення системи

Після інсталяції бажано перевірити наявність оновлень.

В Ubuntu для цього використовується менеджер пакетів APT.

Спочатку оновіть інформацію про доступні пакети:

```bash
sudo apt update
```

Потім за потреби встановіть доступні оновлення:

```bash
sudo apt upgrade
```

Команда `sudo` дозволяє виконати команду з адміністративними повноваженнями, якщо користувач має відповідні права.

Під час виконання команди може знадобитися введення пароля. У терміналі символи пароля зазвичай не відображаються — це нормальна поведінка.

Перед підтвердженням операції прочитайте список змін, які пропонує менеджер пакетів.

Не переривайте встановлення оновлень без необхідності.

### 8.5. Перевірка ресурсів

Після інсталяції перевірте основні характеристики системи:

```bash
lscpu
free -h
df -h
```

Для перевірки використання дискового простору домашнім каталогом:

```bash
du -sh ~
```

Для перевірки ідентифікатора користувача та груп:

```bash
id
```

Запишіть отримані результати у звіт.

## 9. Початкова перевірка Linux-середовища

Після встановлення операційної системи потрібно переконатися, що вона працює коректно.

### 9.1. Основні команди перевірки

| Команда | Що перевіряє |
|---|---|
| `whoami` | Поточного користувача |
| `hostname` | Ім'я комп'ютера |
| `cat /etc/os-release` | Інформацію про дистрибутив |
| `uname -r` | Версію ядра |
| `uname -m` | Архітектуру системи |
| `lscpu` | Інформацію про процесор |
| `free -h` | Використання оперативної пам'яті |
| `df -h` | Заповнення файлових систем |
| `ip addr` | Мережеві інтерфейси та адреси |
| `ip route` | Таблицю маршрутів |
| `cat /etc/resolv.conf` | Поточну конфігурацію DNS-резолвера |

Важливо розуміти, що деякі команди можуть показувати інформацію, яка залежить від конкретної конфігурації системи.

Наприклад, `/etc/resolv.conf` у сучасних системах може бути символічним посиланням або містити параметри, які формуються іншими службами. Його вміст не завжди відображає повну конфігурацію DNS у зручному для користувача вигляді.

### 9.2. Перевірка вільного простору

Виконайте:

```bash
df -h
```

Приклад умовного результату:

```text
Filesystem      Size  Used Avail Use% Mounted on
/dev/sda2        28G  8.1G   18G  32% /
```

Це лише приклад. Реальні назви пристроїв, розміри та точки монтування можуть відрізнятися.

Основні стовпці:

- `Filesystem` — файлова система або пристрій;
- `Size` — загальний розмір;
- `Used` — використаний простір;
- `Avail` — доступний простір;
- `Use%` — відсоток використання;
- `Mounted on` — точка монтування.

### 9.3. Перевірка оперативної пам'яті

Виконайте:

```bash
free -h
```

Команда показує обсяг пам'яті, використання та доступні ресурси.

Не слід автоматично вважати, що вся пам'ять, яка відображається як `used`, зайнята програмами без можливості повторного використання. Linux активно використовує пам'ять для кешування, щоб прискорити роботу системи.

Під час аналізу звертайте увагу на показник `available`, якщо він присутній у виведенні.

## 10. Основи мережевої конфігурації

Мережа потрібна для завантаження оновлень, доступу до зовнішніх ресурсів, підключення до інших комп'ютерів і роботи із серверами.

Для базової діагностики важливо розуміти призначення IP-адреси, маршруту за замовчуванням і DNS.

### 10.1. Основні поняття

**IP-адреса** — адреса мережевого інтерфейсу, яка використовується для передавання пакетів у мережі.

**Мережевий інтерфейс** — фізичний або віртуальний компонент, через який система взаємодіє з мережею.

**Шлюз за замовчуванням** — маршрутизатор, якому система передає пакети, якщо для адреси призначення немає точнішого маршруту.

**DNS** — система, яка допомагає перетворювати доменні імена, наприклад `ubuntu.com`, на IP-адреси.

**DHCP** — протокол, який може автоматично надавати мережеві параметри клієнту.

### 10.2. Перегляд мережевих інтерфейсів

Виконайте:

```bash
ip addr
```

Або:

```bash
ip -br addr
```

Друга команда показує коротший перелік інтерфейсів та їхніх адрес.

Приклад умовного результату:

```text
lo               UNKNOWN        127.0.0.1/8
enp0s3           UP             10.0.2.15/24
```

Назви інтерфейсів залежать від системи.

`lo` — локальний інтерфейс loopback, який використовується для локальної мережевої взаємодії.

`enp0s3` у цьому прикладі — мережевий інтерфейс віртуальної машини.

Адреса `10.0.2.15` наведена як приклад. Не очікуйте, що у вашій системі буде саме така адреса.

### 10.3. Перегляд таблиці маршрутизації

Виконайте:

```bash
ip route
```

Приклад умовного результату:

```text
default via 10.0.2.2 dev enp0s3
10.0.2.0/24 dev enp0s3 proto kernel scope link src 10.0.2.15
```

Пояснення:

- `default` — маршрут за замовчуванням;
- `via` — адреса наступного вузла, через який передаються пакети;
- `dev` — мережевий інтерфейс;
- `src` — адреса джерела, яка може використовуватися для відповідного маршруту.

Цей приклад характерний для деяких конфігурацій VirtualBox із NAT, але фактичні значення залежать від налаштувань.

### 10.4. Перевірка доступності мережі

Для перевірки доступності вузла можна використати `ping`.

Наприклад:

```bash
ping -c 4 1.1.1.1
```

Команда надсилає чотири ICMP-запити до вказаної IP-адреси.

Потім перевірте доступність доменного імені:

```bash
ping -c 4 ubuntu.com
```

Якщо перша команда працює, а друга — ні, можливо, проблема пов'язана з DNS. Однак це не єдиний можливий варіант: конкретний вузол може блокувати ICMP-запити або бути недоступним.

Якщо не працюють обидві команди, перевірте мережевий інтерфейс, маршрут за замовчуванням, конфігурацію віртуальної мережі та доступність мережі хоста.

**Важливо:** відсутність відповіді на `ping` не доводить, що вузол повністю недоступний. ICMP може блокуватися правилами мережі або налаштуваннями вузла.

### 10.5. Перевірка DNS

Якщо в системі встановлено `resolvectl`, можна виконати:

```bash
resolvectl status
```

Для перевірки перетворення доменного імені на IP-адресу можна скористатися:

```bash
getent hosts ubuntu.com
```

Якщо встановлена утиліта `dig`, додатково можна виконати:

```bash
dig ubuntu.com
```

Наявність `dig` залежить від установлених пакетів.

Якщо команда відсутня, не потрібно встановлювати додаткові пакети лише заради цього завдання. Достатньо скористатися `getent hosts` і доступними засобами системи.

### 10.6. Мережеві режими VirtualBox

VirtualBox підтримує декілька способів підключення віртуальної машини до мережі.

| Режим | Принцип роботи | Типове використання |
|---|---|---|
| NAT | Віртуальна машина використовує мережеве підключення хоста через механізм NAT | Початкове налаштування, доступ до інтернету |
| Bridged Adapter | Віртуальна машина підключається до фізичної мережі через відповідний інтерфейс хоста | Робота з VM як з окремим вузлом локальної мережі |
| Host-only Adapter | Створюється мережа для взаємодії хоста з віртуальними машинами | Ізольовані лабораторні роботи |
| Internal Network | Віртуальні машини взаємодіють між собою в окремій віртуальній мережі | Лабораторні мережі без прямого підключення до хоста через цей інтерфейс |

Фактична доступність цих режимів і параметри їх налаштування залежать від версії VirtualBox та конфігурації хостової системи.

#### NAT

Режим NAT є зручним початковим варіантом.

Віртуальна машина зазвичай може отримувати доступ до зовнішніх ресурсів, використовуючи мережеве підключення хоста.

Проте інші пристрої локальної мережі зазвичай не можуть безпосередньо ініціювати з'єднання з віртуальною машиною через NAT без додаткового налаштування, наприклад перенаправлення портів.

Для виконання основних завдань цього модуля NAT зазвичай достатньо.

#### Bridged Adapter

У режимі Bridged Adapter віртуальна машина підключається до фізичної мережі через мережевий інтерфейс хоста.

Віртуальна машина може отримати адресу від DHCP-сервера локальної мережі та стати доступною для інших вузлів цієї мережі.

Однак це залежить від політик мережі, підтримки відповідного режиму та налаштувань маршрутизатора.

Не використовуйте цей режим у чужій або корпоративній мережі без дозволу адміністратора.

#### Host-only Adapter

Host-only Adapter призначений для організації мережі між хостом і віртуальними машинами.

Це корисно для лабораторних робіт, де потрібно ізолювати навчальні системи від зовнішньої мережі.

Сам по собі Host-only Adapter зазвичай не забезпечує доступу до інтернету.

### 10.7. Який режим вибрати?

Для початку навчання рекомендується:

1. Налаштувати NAT.
2. Перевірити, чи має Ubuntu доступ до мережі.
3. Ознайомитися з командами `ip addr` та `ip route`.
4. Порівняти результати після зміни режиму лише за наявності відповідних умов.

Не потрібно змінювати мережеві режими, якщо для виконання завдання достатньо поточної конфігурації.

## 11. Основи SSH

### 11.1. Що таке SSH?

SSH (Secure Shell) — протокол для захищеного віддаленого доступу до іншого комп'ютера.

SSH широко використовується для:

- адміністрування Linux-серверів;
- виконання команд на віддаленому вузлі;
- копіювання файлів;
- автоматизації адміністративних завдань;
- керування інфраструктурою.

SSH забезпечує шифрування мережевого з'єднання та механізми автентифікації.

Однак безпека залежить не лише від протоколу, а й від налаштувань сервера, способу автентифікації та дотримання правил доступу.

### 11.2. Клієнт і сервер SSH

Під час SSH-з'єднання взаємодіють дві сторони:

- **SSH-клієнт** — програма на комп'ютері, з якого здійснюється підключення;
- **SSH-сервер** — служба на комп'ютері, до якого підключаються.

Приклад:

- студент працює у віртуальній машині або на власному комп'ютері;
- на іншому комп'ютері працює Linux-сервер;
- студент запускає SSH-клієнт і підключається до сервера.

Для підключення потрібні:

- адреса сервера або його мережеве ім'я;
- ім'я користувача на сервері;
- дозволений спосіб автентифікації;
- мережевий доступ до SSH-сервера;
- відповідні права доступу.

Стандартний порт SSH — TCP/22, але адміністратор може налаштувати інший порт.

### 11.3. Перевірка наявності SSH-клієнта

У Linux виконайте:

```bash
ssh -V
```

Команда показує версію SSH-клієнта, якщо він установлений.

Якщо команда відсутня, в Ubuntu клієнт зазвичай можна встановити пакетом `openssh-client`:

```bash
sudo apt update
sudo apt install openssh-client
```

Виконуйте встановлення лише за потреби.

### 11.4. Перевірка наявності SSH-сервера

Якщо потрібно приймати SSH-підключення до власної Ubuntu-системи, перевірте, чи встановлений сервер OpenSSH.

У системах Ubuntu серверний компонент зазвичай надається пакетом `openssh-server`.

Перевірка встановлення пакета:

```bash
dpkg -l openssh-server
```

Якщо пакет не встановлений і вам потрібно організувати SSH-доступ до цієї системи, можна виконати:

```bash
sudo apt update
sudo apt install openssh-server
```

Після встановлення перевірте стан служби:

```bash
systemctl status ssh
```

Якщо служба не запущена, її запуск можна виконати так:

```bash
sudo systemctl start ssh
```

Для автоматичного запуску служби під час завантаження системи:

```bash
sudo systemctl enable ssh
```

Не потрібно встановлювати або запускати SSH-сервер, якщо ви лише підключаєтеся до іншого вузла та не плануєте приймати вхідні з'єднання.

### 11.5. Перевірка IP-адреси сервера

На сервері виконайте:

```bash
hostname
hostname -I
ip addr
```

Команда `hostname -I` показує IP-адреси, призначені системі, якщо вони доступні.

У системі може бути декілька адрес. Не кожна з них придатна для підключення з конкретного клієнта.

Наприклад:

- адреса `127.0.0.1` призначена для локальної взаємодії та не використовується як адреса віддаленого сервера для іншого комп'ютера;
- адреса інтерфейсу NAT у VirtualBox може бути доступною з гостьової системи для вихідних з'єднань, але не бути безпосередньо доступною з локальної мережі;
- адреса, отримана в режимі Bridged Adapter, може бути доступною з інших пристроїв тієї самої мережі, якщо це дозволяють її налаштування.

Перед підключенням визначте, звідки саме буде виконуватися SSH-з'єднання.

### 11.6. Підключення до віддаленого сервера

Загальний синтаксис:

```bash
ssh username@server_ip
```

де:

- `username` — ім'я користувача на сервері;
- `server_ip` — IP-адреса сервера.

Наприклад:

```bash
ssh student@192.168.1.50
```

Це умовний приклад. Адреса `192.168.1.50` не є реальною адресою навчального сервера.

Якщо використовується нестандартний порт, його можна вказати параметром `-p`:

```bash
ssh -p 2222 student@192.168.1.50
```

Порт має відповідати конфігурації сервера.

Під час першого підключення SSH може показати відомості про ключ вузла та попросити підтвердити його автентичність.

Не підтверджуйте ключ автоматично, якщо не впевнені, до якого сервера підключаєтеся. Для навчального сервера перевірте відбиток ключа за інформацією, наданою адміністратором.

Після встановлення з'єднання може знадобитися автентифікація користувача.

### 11.7. Як зрозуміти, що ви працюєте на віддаленому сервері?

Після підключення виконайте:

```bash
whoami
hostname
pwd
uname -r
cat /etc/os-release
```

Зверніть увагу на те, що команди виконуються на віддаленому вузлі, а не на вашому локальному комп'ютері.

Для завершення SSH-сеансу виконайте:

```bash
exit
```

Після завершення з'єднання ви повернетеся до локального термінала.

### 11.8. Важливі правила безпеки SSH

Під час роботи із SSH:

- підключайтеся лише до вузлів, доступ до яких вам дозволено;
- не використовуйте чужі облікові записи;
- не передавайте пароль іншим користувачам;
- перевіряйте ключ вузла під час першого підключення;
- не відкривайте SSH-порт у зовнішній мережі без обґрунтованої потреби;
- не змінюйте налаштування SSH-сервера без дозволу адміністратора;
- використовуйте ключову автентифікацію, коли це передбачено політикою системи;
- не зберігайте приватні SSH-ключі у відкритих репозиторіях;
- не копіюйте приватні ключі на чужі комп'ютери.

Для навчальних завдань достатньо підключення в локальному або спеціально підготовленому навчальному середовищі.

**Не потрібно налаштовувати переадресацію портів на домашньому маршрутизаторі або відкривати SSH у публічний інтернет для виконання цього модуля.**

## 12. Базова діагностика Linux-середовища

Діагностика — це послідовна перевірка системи для виявлення причин несправності.

Замість випадкової зміни налаштувань потрібно спочатку зібрати інформацію, визначити проблему, перевірити можливі причини та лише після цього вносити зміни.

### 12.1. Система не має доступу до мережі

Рекомендована послідовність перевірки:

1. Переконайтеся, що мережевий інтерфейс існує.
2. Перевірте його стан та IP-адресу.
3. Перегляньте таблицю маршрутизації.
4. Перевірте доступність шлюзу, якщо його можна визначити.
5. Перевірте доступність зовнішньої IP-адреси.
6. Перевірте перетворення доменного імені на IP-адресу.
7. Перевірте налаштування мережі VirtualBox.

Використовуйте:

```bash
ip -br addr
ip route
getent hosts ubuntu.com
```

За потреби перевірте доступність вузла:

```bash
ping -c 4 1.1.1.1
```

Не змінюйте відразу всі параметри мережі. Кожна перевірка має допомагати звузити коло можливих причин.

### 12.2. Віртуальна машина працює повільно

Можливі причини:

- недостатньо оперативної пам'яті;
- надмірне навантаження на процесор;
- нестача вільного простору на диску;
- одночасна робота багатьох віртуальних машин;
- використання ресурсомісткого графічного середовища;
- повільний фізичний диск.

Для початкової перевірки виконайте:

```bash
free -h
df -h
uptime
```

Команда `uptime` показує час роботи системи, кількість користувачів і середнє навантаження за певні проміжки часу.

Саме по собі високе середнє навантаження не завжди означає проблему. Результат потрібно оцінювати з урахуванням кількості процесорних ядер, поточних завдань та інших показників.

### 12.3. SSH-з'єднання не встановлюється

Можливі причини:

- неправильна IP-адреса;
- неправильне ім'я користувача;
- відсутність мережевого маршруту;
- SSH-сервер не встановлений;
- служба SSH не запущена;
- з'єднання блокується міжмережевим екраном;
- клієнт і сервер перебувають у різних мережах без потрібної маршрутизації;
- використовується неправильний порт;
- сервер недоступний.

Спочатку перевірте:

```bash
ip addr
ip route
```

На сервері, якщо у вас є адміністративний доступ, перевірте:

```bash
systemctl status ssh
```

Потім перевірте параметри підключення.

Не вимикайте міжмережевий екран повністю лише для того, щоб перевірити SSH. Краще з'ясувати, яке саме правило або мережеве обмеження впливає на з'єднання.

### 12.4. Системний підхід до діагностики

Для будь-якої проблеми дотримуйтеся такої послідовності:

1. Сформулюйте проблему.
2. Визначте, які компоненти можуть бути причиною.
3. Зберіть фактичні дані за допомогою команд.
4. Сформулюйте гіпотезу.
5. Виконайте одну контрольовану перевірку.
6. Проаналізуйте результат.
7. За потреби внесіть зміну.
8. Перевірте, чи усунено проблему.
9. Зафіксуйте результати.

Цей підхід буде використовуватися і в наступних модулях курсу.

## 13. Безпека навчального середовища

Навчальна Linux-система є середовищем для експериментів, але це не означає, що її безпекою можна нехтувати.

### 13.1. Принцип найменших привілеїв

Принцип найменших привілеїв передбачає надання користувачам і процесам лише тих повноважень, які потрібні для виконання їхніх завдань.

У повсякденній роботі не слід без необхідності виконувати всі команди з адміністративними повноваженнями.

Використовуйте `sudo` лише тоді, коли команда справді потребує підвищених привілеїв.

### 13.2. Робота з паролями

Рекомендації:

- створюйте достатньо стійкі паролі;
- не використовуйте однаковий пароль для всіх навчальних систем;
- не передавайте паролі у звітах;
- не зберігайте паролі у відкритому вигляді;
- не використовуйте обліковий запис адміністратора для звичайних завдань, якщо це не потрібно.

### 13.3. Ізоляція віртуальних машин

Віртуальна машина допомагає відокремити навчальну систему від хоста, але ізоляція не є абсолютною.

На рівень ризику впливають:

- налаштування мережі;
- спільні каталоги;
- спільний буфер обміну;
- передавання файлів між хостом і гостьовою системою;
- додаткові інтеграційні компоненти;
- уразливості програмного забезпечення віртуалізації.

Не підключайте навчальні віртуальні машини до критично важливих мереж без дозволу та належної ізоляції.

### 13.4. Знімки та резервні копії

Перед експериментами, які можуть суттєво змінити конфігурацію, доцільно створювати знімок стану віртуальної машини.

Для важливих даних додатково використовуйте резервні копії, які зберігаються окремо від основного диска.

### 13.5. Відповідальне використання мережі

Під час навчання:

- не скануйте сторонні мережі без дозволу;
- не намагайтеся підключатися до чужих серверів;
- не змінюйте конфігурацію мережевого обладнання, яке вам не належить;
- не відкривайте навчальні служби в публічний інтернет без погодження;
- виконуйте перевірки лише у власному або дозволеному середовищі.

## 16. Типові помилки початківців

### Помилка 1. Виділення надмірних ресурсів віртуальній машині

**Проблема:** хостова система починає працювати повільно або не має достатньо пам'яті для інших програм.

**Причина:** віртуальній машині виділено занадто багато оперативної пам'яті або процесорних ресурсів.

**Рішення:** переглянути конфігурацію та залишити достатньо ресурсів хостовій системі.

### Помилка 2. Відсутність вільного простору на диску

**Проблема:** не вдається встановлювати пакети або виконувати оновлення.

**Причина:** заповнений віртуальний диск або фізичний диск хоста.

**Рішення:** перевірити `df -h` усередині Linux і вільний простір на хості.

### Помилка 3. Неправильне розуміння мережевого режиму NAT

**Проблема:** віртуальна машина має доступ до інтернету, але інші комп'ютери не можуть безпосередньо підключитися до неї.

**Причина:** NAT не забезпечує автоматичної доступності всіх служб віртуальної машини з локальної мережі.

**Рішення:** визначити, звідки саме має здійснюватися підключення, і вибрати відповідний мережевий режим або дозволений спосіб доступу.

### Помилка 4. Плутанина між локальним і віддаленим терміналом

**Проблема:** команда виконується не на тій системі, яку студент очікує змінити.

**Причина:** після підключення через SSH користувач забуває, що працює на віддаленому вузлі.

**Рішення:** перед адміністративними операціями перевіряти `whoami` та `hostname`.

### Помилка 5. Встановлення SSH-сервера без потреби

**Проблема:** у системі з'являється додаткова служба, яка не потрібна для виконання завдання.

**Причина:** студент плутає SSH-клієнт і SSH-сервер.

**Рішення:** встановлювати `openssh-client` для вихідних підключень, а `openssh-server` — лише тоді, коли система повинна приймати SSH-з'єднання.

### Помилка 6. Ігнорування попередження про ключ вузла

**Проблема:** користувач без перевірки довіряє невідомому SSH-серверу.

**Причина:** попередження сприймається як формальність.

**Рішення:** перевіряти відбиток ключа сервера за надійним джерелом, особливо під час першого підключення або після попередження про зміну ключа.

### Помилка 7. Спроба усунути проблему шляхом випадкової зміни налаштувань

**Проблема:** початкова несправність залишається, а конфігурація стає складнішою.

**Причина:** студент не збирає діагностичні дані перед внесенням змін.

**Рішення:** послідовно перевіряти інтерфейси, IP-адреси, маршрути, DNS і доступність вузлів.

## 18. Додаткові завдання

### Завдання 1. Порівняння системних ресурсів

Порівняйте доступні ресурси фізичного комп'ютера та віртуальної машини.

Визначте:

- кількість процесорних ресурсів, доступних віртуальній машині;
- обсяг оперативної пам'яті;
- доступний дисковий простір;
- відмінності між ресурсами хоста та гостьової системи.

Поясніть, чому показники двох систем не обов'язково збігаються.

### Завдання 2. Дослідження мережевих режимів

Якщо конфігурація навчального середовища це дозволяє, порівняйте NAT і Bridged Adapter.

Зафіксуйте:

- IP-адресу віртуальної машини;
- мережевий інтерфейс;
- маршрут за замовчуванням;
- доступність мережевих ресурсів.

Не змінюйте мережеву конфігурацію без дозволу, якщо комп'ютер підключений до корпоративної або навчальної мережі з обмеженнями.

### Завдання 3. Аналіз помилки SSH

Опишіть можливі причини ситуації, коли команда:

```bash
ssh student@192.168.1.50
```

не встановлює з'єднання.

Розгляньте щонайменше чотири різні причини та запропонуйте спосіб перевірки кожної з них.

Адреса та ім'я користувача в прикладі умовні.

### Завдання 4. Віддалена система та локальна система

Якщо є доступ до віддаленого Linux-сервера, порівняйте результати команд:

```bash
hostname
whoami
uname -r
cat /etc/os-release
free -h
df -h
```

Виконайте команди локально та на сервері.

Поясніть, чому назви систем, версії ядра та обсяги ресурсів можуть відрізнятися.

Якщо доступу до сервера немає, опишіть очікувані відмінності на основі теоретичних відомостей.

### Завдання 5. План відновлення навчальної системи

Розробіть короткий план відновлення віртуальної машини після невдалого експерименту.

План має містити:

- підготовку до експерименту;
- створення знімка стану;
- визначення важливих даних;
- порядок відновлення;
- перевірку працездатності після відновлення;
- обмеження знімків стану та необхідність резервних копій.
