# Модуль 5. Файли та каталоги

## 1. Навчальні цілі

Після опрацювання модуля студент повинен уміти:

- створювати каталоги й файли та наповнювати файли текстом;
- переглядати вміст і метадані файлів за допомогою `cat`, `less`, `head`, `tail`, `wc`, `file`, `stat`;
- копіювати, переміщувати й перейменовувати файли та каталоги, розуміючи різницю між цими операціями;
- безпечно видаляти файли й каталоги та пояснювати, чому в командному рядку немає «кошика»;
- створювати жорсткі й символічні посилання та пояснювати їхні відмінності;
- шукати файли за іменем, типом, розміром і часом змінення за допомогою `find`, а текст у файлах — за допомогою `grep`;
- визначати розмір файлів і каталогів за допомогою `du` та порівнювати результат із `df`;
- створювати, переглядати й розпаковувати архіви `tar` та `gzip`;
- застосовувати безпечні прийоми роботи з деструктивними командами.

## 2. Вступ

Робота з файлами й каталогами — найпоширеніша діяльність у командному рядку. У модулі 3 ви дослідили структуру файлової системи та навчилися орієнтуватися в ній, а в модулі 4 — використовувати можливості оболонки. Тепер ці знання поєднуються: ви навчитеся **створювати, змінювати, копіювати, шукати й видаляти** файли та каталоги.

Більшість команд цього модуля змінюють дані й не мають функції скасування. Тому вправи виконуються лише в навчальному каталозі `~/files-practice`, а перед кожною небезпечною командою ми будемо перевіряти, на що саме вона вплине.

Матеріал рекомендується опрацьовувати безпосередньо в навчальній Ubuntu 24.04 VM. Приклади виведення є умовними: у вашому середовищі результати можуть відрізнятися.

Для підготовки до вправ створіть робочий каталог:

```bash
mkdir -p ~/files-practice
cd ~/files-practice
pwd
```

## 3. Створення каталогів і файлів

### 3.1. Створення каталогів: `mkdir`

```bash
mkdir projects
mkdir -v reports
mkdir -p projects/linux/notes
```

- `mkdir назва` створює каталог у поточному місці;
- `-v` виводить повідомлення про кожен створений каталог;
- `-p` створює всі відсутні проміжні каталоги й не повертає помилку, якщо каталог уже існує.

Без `-p` команда `mkdir a/b/c` завершиться помилкою, якщо `a/b` ще не існує.

### 3.2. Розкриття фігурних дужок

Оболонка підтримує **розкриття фігурних дужок** (brace expansion): запис `{a,b,c}` розгортається в окремі слова ще до запуску команди.

```bash
mkdir -p project/{docs,src,tests}
echo file-{1,2,3}.txt
echo {1..5}
```

Перша команда створює три каталоги, друга виводить `file-1.txt file-2.txt file-3.txt`, третя — числа від 1 до 5. Це розкриття, яке виконує оболонка, а не `mkdir`; воно відрізняється від шаблонів `*` і `?` (модуль 4), які вибирають **наявні** файли.

### 3.3. Створення файлів і оновлення часу: `touch`

```bash
touch notes.txt
touch a.txt b.txt c.txt
ls -l notes.txt
touch notes.txt
ls -l notes.txt
```

Якщо файла не існує, `touch` створює порожній файл. Якщо файл існує, команда лише оновлює час змінення та доступу, не змінюючи вміст.

За допомогою параметра `-d` можна задати довільний час:

```bash
touch -d "2024-01-15 10:30" old.txt
ls -l old.txt
```

### 3.4. Наповнення файлів текстом

Перенаправлення (модуль 4) дає змогу записати текст у файл:

```bash
printf 'Перший рядок\n' > list.txt
printf 'Другий рядок\n' >> list.txt
```

Нагадування: `>` перезаписує файл, `>>` додає в кінець.

**Багаторядковий текст** зручно вводити через конструкцію here-document:

```bash
cat > greeting.txt <<'EOF'
Привіт, Linux!
Це файл із кількох рядків.
EOF
cat greeting.txt
```

Усе між `<<'EOF'` і рядком `EOF` потрапляє в файл. Лапки навколо `EOF` вимикають підстановку змінних усередині тексту.

**Текстовий редактор `nano`** — простий редактор, який є в Ubuntu за замовчуванням:

```bash
nano notes.txt
```

Керування в `nano` здійснюється комбінаціями клавіш (`^` означає `Ctrl`):

| Комбінація | Дія |
|---|---|
| `Ctrl+O`, `Enter` | Зберегти файл |
| `Ctrl+X` | Вийти |
| `Ctrl+W` | Знайти текст |
| `Ctrl+K` | Вирізати поточний рядок |
| `Ctrl+U` | Вставити вирізаний рядок |
| `Ctrl+G` | Довідка |

У системі також може бути інший редактор, наприклад `vim`. Якщо ви випадково відкрили `vim`, вийти без збереження можна командою `:q!` (натисніть `Esc`, потім введіть її й `Enter`).

## 4. Перегляд вмісту файлів

### 4.1. `cat`

```bash
cat greeting.txt
cat -n greeting.txt
cat list.txt greeting.txt
```

`cat` виводить файл повністю; `-n` нумерує рядки; кілька файлів виводяться один за одним. Для великих файлів зручніше `less`.

### 4.2. `less`

```bash
less /etc/services
```

`less` показує файл посторінково, не завантажуючи його повністю. Основні клавіші:

| Клавіша | Дія |
|---|---|
| `Space` | Наступна сторінка |
| `b` | Попередня сторінка |
| `↓`, `↑` | Рядок вниз і вгору |
| `g`, `G` | Початок і кінець файла |
| `/слово` | Пошук уперед |
| `n`, `N` | Наступний і попередній збіг |
| `q` | Вихід |

Якщо файла `/etc/services` немає, використайте будь-який великий текстовий файл, наприклад `/etc/passwd`.

### 4.3. `head` і `tail`

```bash
head /etc/passwd
head -n 3 /etc/passwd
tail -n 3 /etc/passwd
tail -f журнал.log
```

- `head` показує початок файла (за замовчуванням 10 рядків);
- `tail` показує кінець файла;
- `-n N` задає кількість рядків;
- `tail -f` продовжує показувати нові рядки, які з'являються у файлі (корисно для журналів). Для зупинки натисніть `Ctrl+C`.

У `tail -f` замість `журнал.log` вказують файл, який поповнюється, зазвичай журнал служби. Багато файлів у `/var/log` недоступні звичайному користувачу: причини розглянуто в модулі 6.

### 4.4. `wc`

```bash
wc -l /etc/passwd
wc -w greeting.txt
wc -c greeting.txt
wc greeting.txt
```

`wc` рахує рядки (`-l`), слова (`-w`), байти (`-c`) або символи (`-m`). Без параметрів виводить усі три значення. З конвеєрами команда зручна для підрахунку: `ls /etc | wc -l`.

### 4.5. Визначення типу та метаданих: `file`, `stat`

```bash
file greeting.txt
file /usr/bin/ls
stat greeting.txt
```

`file` визначає тип за вмістом, а не за розширенням. `stat` показує докладні метадані:

```text
  File: greeting.txt
  Size: 56        	Blocks: 8          IO Block: 4096   regular file
Device: 802h/2050d	Inode: 1311234     Links: 1
Access: (0664/-rw-rw-r--)  Uid: ( 1000/ student)   Gid: ( 1000/ student)
Access: 2026-10-12 10:15:03.000000000 +0300
Modify: 2026-10-12 10:15:01.000000000 +0300
Change: 2026-10-12 10:15:01.000000000 +0300
 Birth: 2026-10-12 10:15:01.000000000 +0300
```

Важливі поля:

- `Size` — розмір у байтах;
- `Inode` — унікальний номер об'єкта у файловій системі;
- `Links` — кількість жорстких посилань на цей об'єкт;
- `Access` — права доступу, власник і група (модуль 6);
- `Modify` — час останнього змінення **вмісту**;
- `Change` — час останнього змінення **метаданих** (права, власник, імена);
- `Birth` — час створення (залежить від файлової системи).

### 4.6. Пошук тексту у файлах: `grep`

```bash
grep root /etc/passwd
grep -n root /etc/passwd
grep -i linux greeting.txt
grep -c bash /etc/passwd
grep -v nologin /etc/passwd
grep -rn "Linux" ~/files-practice
```

| Параметр | Дія |
|---|---|
| `-n` | Показувати номери рядків |
| `-i` | Не розрізняти регістр |
| `-v` | Показати рядки, які **не** збігаються |
| `-c` | Лише кількість збіжних рядків |
| `-r` | Рекурсивний пошук у каталозі |
| `-l` | Лише імена файлів зі збігом |

Шаблон слід брати в лапки, якщо він містить спеціальні символи (`*`, `?`, пробіли), щоб їх не розгорнула оболонка.

## 5. Копіювання

```bash
cp notes.txt notes-copy.txt
cp notes.txt projects/
cp -r project project-backup
cp -i notes.txt notes-copy.txt
cp -v a.txt b.txt c.txt projects/
```

Синтаксис: `cp джерело призначення`. Якщо джерел кілька, **останній аргумент має бути каталогом**.

| Параметр | Дія |
|---|---|
| `-r` (`-R`) | Копіювати каталоги разом із вмістом |
| `-i` | Запитувати підтвердження перед перезаписом |
| `-n` | Не перезаписувати наявні файли |
| `-v` | Докладний вивід |
| `-p` | Зберегти права, власника та час змінення |
| `-a` | «Архівне» копіювання: рекурсивно, зі збереженням метаданих і посилань |

Поведінка `cp -r джерело призначення`:

- якщо `призначення` не існує, воно стає копією `джерела`;
- якщо `призначення` — наявний каталог, копія створюється **всередині нього**: `призначення/джерело`.

Без `-i` або `-n` команда `cp` мовчки перезаписує наявний файл з тим самим іменем.

## 6. Переміщення та перейменування

Команда `mv` виконує і переміщення, і перейменування:

```bash
mv notes.txt notes-old.txt          # перейменування
mv notes-old.txt projects/          # переміщення в каталог
mv projects/notes-old.txt ./notes.txt
mv -i a.txt b.txt                    # із запитом перед перезаписом
mv -v c.txt projects/linux/
mv reports reports-2026
```

- `mv старе нове` — якщо `нове` не є каталогом, об'єкт перейменовується;
- `mv файл каталог/` — файл переміщується всередину каталогу;
- у межах однієї файлової системи переміщення виконується зміною запису в каталозі, тому воно миттєве й зберігає inode; між різними файловими системами `mv` копіює дані, а потім видаляє оригінал.

Як і `cp`, команда `mv` без `-i` або `-n` мовчки перезаписує наявний об'єкт.

## 7. Видалення

### 7.1. `rm` і `rmdir`

```bash
rm file.txt
rm -i file.txt
rm -v a.txt b.txt
rmdir empty-dir
rm -r project-backup
```

| Команда / параметр | Дія |
|---|---|
| `rm файл` | Видаляє файл |
| `-i` | Запитує підтвердження для кожного об'єкта |
| `-I` | Одне підтвердження перед масовим або рекурсивним видаленням |
| `-r` | Видаляє каталог разом із вмістом |
| `-f` | Не запитує підтвердження й не повідомляє про відсутні файли |
| `-v` | Показує, що видалено |
| `rmdir каталог` | Видаляє **порожній** каталог |

### 7.2. Видалення незворотне

У командному рядку Linux немає «кошика»: після `rm` файл не можна повернути стандартними засобами. Тому дотримуйтеся порядку дій:

1. Перевірте поточний каталог: `pwd`.
2. Перегляньте, що саме буде видалено, тією самою командою, але з `ls`:

   ```bash
   ls *.tmp
   rm *.tmp
   ```

3. Для невеликих операцій використовуйте `rm -i` або `rm -I`.
4. Для каталогів спочатку перегляньте вміст: `ls -la каталог`.

### 7.3. Особливі випадки

Ім'я файла, що починається з `-`, команда може сприйняти як параметр. Використовуйте `--` або шлях:

```bash
rm -- -oops.txt
rm ./-oops.txt
```

GNU `rm` за замовчуванням відмовляється рекурсивно видаляти `/` (`--preserve-root`), але це не захищає від видалення вашого домашнього каталогу чи інших важливих даних.

Видалення файла вимагає не прав на сам файл, а прав на **каталог**, у якому він розташований (див. модуль 6).

## 8. Посилання: жорсткі й символічні

### 8.1. Жорсткі посилання

Файл у Linux складається з **даних** і **inode** (запису з метаданими). Ім'я файла — це запис у каталозі, який вказує на inode. **Жорстке посилання** — ще одне ім'я для того самого inode:

```bash
printf 'Hello\n' > original.txt
ln original.txt hardlink.txt
ls -li original.txt hardlink.txt
stat original.txt
```

Приклад виведення:

```text
1311300 -rw-rw-r-- 2 student student 6 Oct 12 10:20 hardlink.txt
1311300 -rw-rw-r-- 2 student student 6 Oct 12 10:20 original.txt
```

Однаковий номер inode й кількість посилань `2` показують, що це **один і той самий файл** з двома іменами. Змінення вмісту через одне ім'я видно через інше. Дані видаляються, коли зникає **останнє** ім'я та жодна програма не тримає файл відкритим.

Обмеження жорстких посилань:

- їх не можна створювати між різними файловими системами;
- зазвичай їх не створюють на каталоги.

### 8.2. Символічні посилання

**Символічне посилання** — окремий файл (тип `l`), який містить шлях до цілі:

```bash
ln -s original.txt symlink.txt
ls -l symlink.txt
readlink symlink.txt
cat symlink.txt
```

```text
lrwxrwxrwx 1 student student 12 Oct 12 10:22 symlink.txt -> original.txt
```

Символічні посилання можуть вказувати на каталоги й на інші файлові системи. Відносна ціль відраховується від каталогу, у якому лежить посилання (модуль 3).

### 8.3. Порівняння

| Властивість | Жорстке посилання | Символічне посилання |
|---|---|---|
| Що це | Ще одне ім'я того самого inode | Окремий файл зі шляхом до цілі |
| inode | Той самий | Власний |
| Якщо видалити оригінальне ім'я | Дані зберігаються | Посилання стає «битим» |
| Між файловими системами | Ні | Так |
| Для каталогів | Зазвичай ні | Так |
| Тип у `ls -l` | `-` (як звичайний файл) | `l` |

Знайти биті символічні посилання в каталозі можна командою:

```bash
find ~/files-practice -xtype l
```

## 9. Пошук файлів: `find`

Загальний синтаксис: `find де-шукати [умови] [дії]`.

```bash
find ~/files-practice
find ~/files-practice -name '*.txt'
find ~/files-practice -iname 'notes*'
find ~/files-practice -type d
find ~/files-practice -type f -size +1k
find ~/files-practice -type f -mmin -30
find ~/files-practice -maxdepth 1 -type f
find ~/files-practice -type f -empty
```

| Умова | Значення |
|---|---|
| `-name 'шаблон'` | За ім'ям (враховує регістр) |
| `-iname 'шаблон'` | За ім'ям, регістр не враховується |
| `-type f` / `d` / `l` | Звичайний файл / каталог / символічне посилання |
| `-size +1M` / `-size -10k` | Більше 1 МБ / менше 10 КБ |
| `-mtime -1` / `+7` | Змінено менше ніж 1 день тому / більше ніж 7 днів тому |
| `-mmin -30` | Змінено менше ніж 30 хвилин тому |
| `-maxdepth N` | Максимальна глибина пошуку |
| `-empty` | Порожні файли й каталоги |

**Важливо:** шаблони в `-name` слід брати в лапки. Без лапок оболонка розгорне `*.txt` ще до запуску `find`, і результат буде неправильним (модуль 4).

Умови поєднуються за логікою «і». `-maxdepth` потрібно ставити перед іншими умовами.

### 9.1. Дії над знайденим

```bash
find ~/files-practice -name '*.tmp' -print
find ~/files-practice -name '*.txt' -exec ls -l {} +
find ~/files-practice -name '*.tmp' -exec rm -i {} \;
```

- `-print` виводить знайдені шляхи (дія за замовчуванням);
- `-exec команда {} +` запускає команду для знайдених об'єктів; `{}` замінюється на шлях;
- `-exec команда {} \;` запускає команду окремо для кожного об'єкта;
- `-delete` видаляє знайдені об'єкти.

**Правило безпеки:** спочатку виконайте `find` із `-print` або `-exec ls -l {} +`, переконайтеся, що список правильний, і лише потім додавайте `-delete` або `rm`.

Під час пошуку в системних каталогах виводяться помилки «Permission denied». Їх можна відокремити так: `find /etc -name '*.conf' 2>/dev/null`. Використовуйте це лише коли повідомлення про помилки не потрібні (модуль 4).

## 10. Розмір файлів і каталогів

```bash
ls -lh
du -sh ~/files-practice
du -h --max-depth=1 ~/files-practice
du -h -d 1 ~ | sort -h
```

- `ls -lh` показує розміри файлів у зручному вигляді (`K`, `M`, `G`);
- `du -sh` показує сумарний розмір каталога;
- `du -h --max-depth=1` (або `-d 1`) показує розмір кожного підкаталогу першого рівня;
- `sort -h` сортує числа зі суфіксами `K`, `M`, `G`.

Відмінності від `df`:

| Команда | Що показує |
|---|---|
| `df -h` | Заповнення **файлових систем** (розмір, використано, вільно) |
| `du -sh` | Скільки місця займають **конкретні** файли й каталоги |

`du` показує обсяг, який об'єкти фактично займають на диску, тому результат може відрізнятися від суми розмірів у `ls -l`. Результати `df` і `du` також можуть відрізнятися через кеші, посилання й службові структури файлової системи.

## 11. Архівування та стиснення

**Архів** об'єднує кілька файлів і каталогів в один файл. **Стиснення** зменшує розмір даних. У Linux ці операції найчастіше виконують разом за допомогою `tar` і `gzip`.

```bash
tar -cvf backup.tar project
tar -czvf backup.tar.gz project
tar -tzf backup.tar.gz
mkdir -p restore
tar -xzvf backup.tar.gz -C restore
```

| Параметр | Значення |
|---|---|
| `-c` | Створити архів |
| `-x` | Розпакувати архів |
| `-t` | Показати вміст архіву без розпакування |
| `-f файл` | Ім'я файла архіву (обов'язково вказується) |
| `-v` | Докладний вивід |
| `-z` | Стиснення/розпакування `gzip` |
| `-C каталог` | Розпакувати в указаний каталог (він має існувати) |

Файли `.tar.gz` (або `.tgz`) — архіви `tar`, стиснені `gzip`.

Окремо `gzip` стискає один файл:

```bash
gzip -k notes.txt
ls -l notes.txt notes.txt.gz
gunzip notes.txt.gz
```

Без `-k` `gzip` замінює оригінал стисненим файлом. Формат `.zip` також поширений, але програми `zip` і `unzip` можуть бути не встановлені: їх установлення розглядається в модулі 9.

**Перед розпакуванням** завжди переглядайте вміст архіву командою `tar -tzf`, особливо якщо архів отримано не з довіреного джерела.

## 13. Типові помилки

1. **Перезапис файла через `>`.** Одне випадкове `>` замість `>>` стирає вміст.
2. **Копіювання каталога без `-r`.** `cp` відповість: `-r not specified; omitting directory`.
3. **Неправильне розуміння `cp -r` і `mv` для наявного каталога.** Об'єкт потрапляє всередину каталога призначення, а не замінює його.
4. **Видалення без попереднього перегляду.** `rm *` у неправильному каталозі видаляє не ті файли.
5. **Забуті лапки в `find -name`.** Без лапок оболонка розгортає шаблон до запуску `find`.
6. **Плутанина між жорстким і символічним посиланнями.** Видалення оригіналу ламає символічне посилання, але не жорстке.
7. **Очікування, що `rmdir` видаляє непорожній каталог.** Для цього потрібен `rm -r`.
8. **Використання `tail -f` на файлі без завершення.** Команду потрібно зупиняти через `Ctrl+C`.
9. **Порівняння `du` і `df` як однакових величин.** Це різні вимірювання.
10. **Розпакування архіву в неочікуване місце.** Перед розпакуванням перевіряйте вміст і використовуйте `-C`.

!!! warning "Навчальне середовище"

    Усі деструктивні вправи (`rm`, `mv`, `cp -r`, `tar -x`, `find -delete`) виконуйте лише у каталозі `~/files-practice`. Перед кожним видаленням перевіряйте `pwd` і список об'єктів.

## 14. Security Note

!!! danger

    Видалення, перезапис і переміщення файлів незворотні. Помилка в шляху, змінній або шаблоні може знищити важливі дані. Права `root` лише збільшують наслідки: команда `sudo rm -rf` не питає підтвердження й не має скасування.

Правила безпечної роботи:

1. Перед `rm`, `mv` і `cp` перевіряйте `pwd` і цільові шляхи.
2. Спершу виводьте список (`ls`, `find ... -print`), а потім видаляйте.
3. Використовуйте `-i` або `-I` для незнайомих операцій і `-v`, щоб бачити результат.
4. Не використовуйте `rm -rf` зі змінними, які можуть бути порожніми: `rm -rf "$dir"/*` за порожньої `dir` перетворюється на `rm -rf /*`. Запис `"${dir:?}"` змушує оболонку зупинитися з помилкою, якщо змінна порожня.
5. Не виконуйте `rm -rf` від імені `root` без крайньої потреби й без резервної копії.
6. Не розпаковуйте архіви з невідомих джерел у важливі каталоги; спочатку перегляньте вміст `tar -tzf`.
7. Пам'ятайте, що символічне посилання може вказувати на інше місце: операція над посиланням може зачепити ціль.
8. Перед важливими змінами створюйте резервну копію (`cp -a`, `tar`) і перевіряйте її.
9. Не зберігайте паролі та секрети у файлах із відкритими правами (див. модуль 6).

## 19. Ключові висновки

1. `mkdir -p`, `touch` і перенаправлення — основа створення структури та даних; розкриття фігурних дужок прискорює створення кількох об'єктів.
2. `cat`, `less`, `head`, `tail`, `wc`, `file`, `stat` і `grep` дають змогу швидко дослідити файл без його редагування.
3. `cp`, `mv` і `rm` змінюють дані без скасування; `-i`, `-v` та попередній перегляд списку знижують ризик.
4. Копіювання й переміщення каталога залежать від того, чи існує каталог призначення.
5. Жорстке посилання — додаткове ім'я того самого inode; символічне — окремий файл зі шляхом до цілі.
6. `find` шукає за іменем, типом, розміром і часом; шаблони в `-name` слід брати в лапки; видаляти знайдене можна лише після перегляду списку.
7. `du` показує розмір конкретних об'єктів, а `df` — заповнення файлових систем.
8. `tar` і `gzip` створюють архіви; перед розпакуванням слід переглядати вміст.
9. Безпечна робота з файлами вимагає перевірки шляху, робочого каталога та вмісту змінних перед кожною деструктивною командою.
