# Модуль 6. Права доступу

## 1. Навчальні цілі

Після опрацювання модуля студент повинен уміти:

- пояснювати, навіщо в багатокористувацькій системі потрібні права доступу;
- розрізняти власника, групу й інших користувачів та визначати їх за виведенням `ls -l` і `stat`;
- читати рядок прав (`-rwxr-xr--`) і переводити його в числовий вигляд;
- пояснювати, що означають права `r`, `w`, `x` для файлів і для каталогів;
- змінювати права за допомогою `chmod` у символьному й числовому записі;
- розуміти призначення `chown` і `chgrp` та обмеження на їх використання;
- пояснювати дію `umask` і розраховувати права нових файлів і каталогів;
- розпізнавати спеціальні біти `setuid`, `setgid` і `sticky`;
- робити файл виконуваним і запускати його;
- діагностувати помилку `Permission denied` за визначеним порядком перевірок;
- застосовувати принцип найменших привілеїв.

## 2. Вступ

Linux — багатокористувацька операційна система. Одночасно на ній можуть працювати різні користувачі, служби й процеси, кожен зі своїми даними. **Права доступу** визначають, хто й що може робити з кожним файлом і каталогом: читати, змінювати, виконувати, переглядати вміст, створювати чи видаляти об'єкти.

Без цього механізму будь-який користувач міг би прочитати чужі документи, змінити конфігурацію системи або видалити системні файли. Права доступу є однією з основ безпеки Linux і причиною більшості повідомлень `Permission denied`, які бачать початківці.

Модуль спирається на модулі 3 (файлова система, типи об'єктів, монтування) і 5 (команди роботи з файлами). Створення користувачів і груп розглядається в модулі 7; тут групи використовуються лише в обсязі, потрібному для розуміння прав.

Усі вправи виконуються в навчальному каталозі `~/perm-practice`:

```bash
mkdir -p ~/perm-practice
cd ~/perm-practice
pwd
```

Приклади виведення є умовними: у вашому середовищі результати можуть відрізнятися.

## 3. Основні поняття

### 3.1. Власник, група й інші

З кожним файлом і каталогом пов'язано:

- **власника** (owner) — користувача, якому належить об'єкт;
- **групу** (group) — групу користувачів, пов'язану з об'єктом;
- **права** для трьох категорій: власник (`u`, user), група (`g`, group), інші (`o`, others). Для всіх трьох разом використовують `a` (all).

Система перевіряє категорії **по черзі**: якщо користувач є власником, застосовуються права власника; інакше, якщо він належить до групи об'єкта, — права групи; інакше — права «інших». Права наступної категорії не додаються до попередньої.

### 3.2. Перегляд власника, групи та прав

```bash
ls -l /etc/passwd /etc/shadow
```

```text
-rw-r--r-- 1 root root   2915 Oct 12 09:00 /etc/passwd
-rw-r----- 1 root shadow 1450 Oct 12 09:00 /etc/shadow
```

Розбір рядка `-rw-r----- 1 root shadow 1450 Oct 12 09:00 /etc/shadow`:

| Частина | Значення |
|---|---|
| `-` | Тип об'єкта (звичайний файл) |
| `rw-` | Права власника |
| `r--` | Права групи |
| `---` | Права інших |
| `1` | Кількість жорстких посилань |
| `root` | Власник |
| `shadow` | Група |
| `1450` | Розмір у байтах |
| `Oct 12 09:00` | Час останнього змінення |
| `/etc/shadow` | Ім'я |

Інші способи переглянути права:

```bash
stat /etc/shadow
stat -c '%A %a %U:%G %n' /etc/shadow
```

Формат `%A` показує права текстом (`-rw-r-----`), `%a` — числом (`640`), `%U` і `%G` — власника та групу, `%n` — ім'я.

### 3.3. Визначення поточного користувача та його груп

```bash
whoami
id
groups
id -Gn
```

Команда `id` показує UID, основну групу й усі групи користувача. Саме за цими даними система визначає, до якої категорії ви належите для кожного файла.

### 3.4. Права `r`, `w`, `x`

Для **звичайних файлів**:

| Право | Значення |
|---|---|
| `r` (read) | Читати вміст файла |
| `w` (write) | Змінювати вміст файла |
| `x` (execute) | Запускати файл як програму |

Для **каталогів**:

| Право | Значення |
|---|---|
| `r` | Переглядати перелік імен у каталозі (`ls`) |
| `w` | Створювати, видаляти й перейменовувати об'єкти в каталозі (разом із `x`) |
| `x` | «Проходити» через каталог: переходити в нього (`cd`) і звертатися до об'єктів у ньому за іменем |

Важливі наслідки:

- щоб прочитати файл `/home/student/docs/notes.txt`, потрібне право `r` на файл і право `x` на **кожен** каталог шляху (`/`, `/home`, `/home/student`, `docs`);
- **видалення файла** залежить від прав на **каталог** (`w` та `x`), а не на сам файл;
- каталог без `x` — «закритий»: навіть якщо ви знаєте ім'я файла всередині, звернутися до нього не вийде;
- каталог із `x`, але без `r` — «прохідний»: перелік імен переглянути не можна, але файл за відомим іменем відкрити можна.

Щоб побачити права на кожному компоненті шляху, використовують `namei`:

```bash
namei -l /etc/shadow
```

```text
f: /etc/shadow
dr-xr-xr-x root root /
drwxr-xr-x root root etc
-rw-r----- root shadow shadow
```

### 3.5. Символічні посилання та користувач `root`

- Права символічного посилання завжди показуються як `rwxrwxrwx` і не використовуються; для доступу застосовуються права **цілі**.
- Користувач `root` (адміністратор) обходить більшість перевірок прав. Саме тому робота від імені `root` небезпечна: помилка не зупиняється системою.

## 4. Числовий запис прав

Кожне право має числову вагу:

| Право | Значення |
|---|---|
| `r` | 4 |
| `w` | 2 |
| `x` | 1 |
| `-` | 0 |

Сума для кожної категорії дає одну цифру, а три цифри — права `власник, група, інші`:

| Запис | Числовий вигляд | Розрахунок |
|---|---|---|
| `rw-r--r--` | `644` | 4+2, 4, 4 |
| `rwxr-xr-x` | `755` | 4+2+1, 4+1, 4+1 |
| `rw-------` | `600` | 4+2, 0, 0 |
| `rwx------` | `700` | 4+2+1, 0, 0 |
| `rw-rw-r--` | `664` | 4+2, 4+2, 4 |
| `rwxrwxrwx` | `777` | 4+2+1 у кожній категорії |
| `rw-r-----` | `640` | 4+2, 4, 0 |

Типові значення:

| Права | Типове застосування |
|---|---|
| `644` | Звичайні файли, доступні для читання всім |
| `600` | Приватні файли (ключі, паролі) |
| `640` | Файли для власника та групи |
| `755` | Програми й загальнодоступні каталоги |
| `700` | Приватні каталоги |
| `775` | Каталоги, у які може писати група |

## 5. Зміна прав: `chmod`

Змінювати права може **власник** об'єкта (або `root`).

### 5.1. Символьний запис

Формат: `chmod [кому][дія][права] файл`.

| Кому | Дія | Права |
|---|---|---|
| `u` — власник | `+` — додати | `r`, `w`, `x` |
| `g` — група | `-` — прибрати | `X` — `x` лише для каталогів і вже виконуваних файлів |
| `o` — інші | `=` — задати точно | `s`, `t` — спеціальні біти (розділ 8) |
| `a` — усі | | |

```bash
cd ~/perm-practice
touch report.txt
chmod u+x report.txt
chmod go-rwx report.txt
chmod a+r report.txt
chmod u=rw,g=r,o= report.txt
chmod g+w,o-r report.txt
ls -l report.txt
```

Якщо категорію не вказано, дія застосовується до `a`, але з урахуванням `umask` (розділ 7). Тому для чіткості категорію краще вказувати явно.

### 5.2. Числовий запис

```bash
chmod 644 report.txt
chmod 600 report.txt
chmod 755 ~/perm-practice
ls -l report.txt
ls -ld ~/perm-practice
```

Числовий запис задає **усі** права точно: решта попередніх прав скидається.

### 5.3. Рекурсивна зміна

```bash
mkdir -p tree/sub
touch tree/a.txt tree/sub/b.txt
chmod -R go-rwx tree
chmod -R u+rwX,go-w tree
```

- `-R` застосовує зміну до каталогу та всього вмісту;
- велика `X` надає `x` лише каталогам і файлам, які вже мають `x` — це безпечніше, ніж `+x` для всього дерева;
- перед `chmod -R` завжди перевіряйте шлях.

### 5.4. Чому не `chmod 777`

Права `777` дозволяють **будь-якому користувачу** читати, змінювати й виконувати файл. Це майже ніколи не є правильним розв'язанням проблеми `Permission denied`: воно приховує причину та створює ризик безпеки. Замість цього визначте, кому саме потрібен доступ, і надайте мінімально необхідні права.

## 6. Власник і група: `chown`, `chgrp`

```bash
chgrp група файл
chown :група файл
sudo chown користувач файл
sudo chown користувач:група файл
```

Ці команди наведено для ознайомлення: замість `група`, `користувач` і `файл` підставляються реальні значення. У практичних вправах цього модуля `sudo` не потрібен.

| Команда | Дія |
|---|---|
| `chown користувач файл` | Змінити власника |
| `chown користувач:група файл` | Змінити власника та групу |
| `chown :група файл` | Змінити лише групу |
| `chgrp група файл` | Змінити групу |
| `-R` | Застосувати рекурсивно |

Обмеження:

- змінювати **власника** може лише `root` (зазвичай через `sudo`);
- змінювати **групу** може власник файла, але лише на групу, до якої він сам належить;
- групи та користувачів можна вказувати іменем або числовим ідентифікатором.

Команда `sudo` виконує одну команду з правами адміністратора й вимагає пароль користувача. Детально вона розглядається в наступних модулях; у цьому курсі застосовуйте `sudo` лише тоді, коли завдання цього вимагає прямо.

## 7. Маска створення файлів: `umask`

Коли програма створює файл або каталог, система виходить із початкових прав (`666` для файлів і `777` для каталогів) і **вилучає** з них біти, указані в `umask`.

```bash
umask
umask -S
```

```text
0002
u=rwx,g=rwx,o=rx
```

Розрахунок:

| `umask` | Права нових файлів | Права нових каталогів |
|---|---|---|
| `002` | `664` (`rw-rw-r--`) | `775` (`rwxrwxr-x`) |
| `022` | `644` (`rw-r--r--`) | `755` (`rwxr-xr-x`) |
| `027` | `640` (`rw-r-----`) | `750` (`rwxr-x---`) |
| `077` | `600` (`rw-------`) | `700` (`rwx------`) |

Файли за замовчуванням не стають виконуваними: початкові `666` не містять `x`.

У Ubuntu звичайно діє `umask 0002`, у багатьох інших дистрибутивах — `0022`. Змінити маску для поточного сеансу:

```bash
umask 027
touch masked.txt
mkdir masked-dir
ls -ld masked.txt masked-dir
umask 002
```

Така зміна діє лише в поточній оболонці й зникає після закриття терміналу. Постійне значення задається в конфігураційних файлах оболонки або системи; у цьому модулі їх змінювати не потрібно.

## 8. Спеціальні біти

Окрім звичайних дев'яти бітів існують три спеціальні:

| Біт | Числове значення | Позначення | Для файла | Для каталогу |
|---|---|---|---|---|
| `setuid` | 4000 | `s` у позиції `x` власника | Програма виконується з правами власника файла | Ігнорується |
| `setgid` | 2000 | `s` у позиції `x` групи | Програма виконується з правами групи файла | Нові об'єкти успадковують групу каталогу |
| `sticky` | 1000 | `t` у позиції `x` інших | Ігнорується | У каталозі видаляти об'єкти може лише їх власник (або власник каталогу, `root`) |

Приклади в системі:

```bash
ls -l /usr/bin/passwd
ls -ld /tmp
```

```text
-rwsr-xr-x 1 root root 59976 Oct 12 09:00 /usr/bin/passwd
drwxrwxrwt 18 root root 4096 Oct 12 10:30 /tmp
```

- `passwd` має `setuid`: звичайний користувач змінює власний пароль, хоча для цього потрібно записати дані у файл, недоступний для запису звичайним користувачам;
- `/tmp` має `sticky`: у цьому каталозі можуть писати всі, але видалити чужий файл не можна.

Великі літери `S` і `T` означають, що спеціальний біт установлено, а відповідного `x` немає.

Установлення:

```bash
mkdir shared
chmod g+s shared      # установити setgid
chmod 2775 shared     # те саме числом: setgid і rwxrwxr-x
chmod +t shared       # додати sticky
ls -ld shared
```

`setgid` на каталозі корисний для спільних робочих каталогів: нові файли автоматично отримують групу каталогу.

Список програм із `setuid` у каталозі `/usr/bin`:

```bash
find /usr/bin -maxdepth 1 -type f -perm -4000
```

Тут `-perm -4000` означає «біт `setuid` установлено». Програми з `setuid` потенційно небезпечні, тому їх кількість контролюють і не створюють власних без крайньої потреби.

## 9. Виконувані файли та скрипти

Файл можна запустити як програму, якщо він має право `x`:

```bash
cd ~/perm-practice
printf '#!/bin/bash\necho "Hello from script"\n' > hello.sh
ls -l hello.sh
./hello.sh
chmod u+x hello.sh
ls -l hello.sh
./hello.sh
```

Перший запуск завершиться помилкою `Permission denied`, бо файл не має права `x`. Після `chmod u+x` скрипт запускається.

Перший рядок `#!/bin/bash` (shebang) вказує, яким інтерпретатором виконувати скрипт. Докладно скрипти розглядаються в модулі 14.

Пошук команд у `PATH` (модуль 4) не включає поточний каталог, тому потрібен префікс `./`:

```bash
hello.sh
./hello.sh
```

Перша команда видасть `command not found`, друга — виконає скрипт. **Не додавайте `.` або домашні каталоги до `PATH` без розуміння ризиків.**

Права `x` недостатньо, якщо файлову систему змонтовано з параметром `noexec` (модуль 3): запуск програм із такого розділу заборонено незалежно від прав.

## 10. Перевірка доступу та діагностика `Permission denied`

### 10.1. Перевірка прав командою `test`

```bash
test -r report.txt; echo $?
test -w report.txt; echo $?
test -x report.txt; echo $?
```

Код `0` означає, що право є для **поточного** користувача; ненульовий код — що його немає. Така перевірка враховує і права власника/групи, і шлях.

### 10.2. Порядок діагностики

Повідомлення `Permission denied` означає, що доступ заборонено, а `No such file or directory` — що об'єкта за шляхом не існує. Це різні проблеми.

Якщо виникла помилка `Permission denied`, перевірте по черзі:

1. **Хто я?** `whoami`, `id` — користувач і групи.
2. **Що це за об'єкт?** `ls -ld шлях` — тип, власник, група, права.
3. **Чи є потрібне право?** Для читання потрібне `r`, для запису — `w`, для запуску — `x`.
4. **Чи є доступ до всього шляху?** `namei -l шлях` — права `x` на кожному каталозі.
5. **Чи є право на каталог для створення, видалення, перейменування?** Потрібні `w` і `x` на каталозі.
6. **Чи не заважають інші механізми?** Монтування `ro` або `noexec` (`findmnt -T шлях`), `sticky`-біт, обмеження системи безпеки.
7. **Чи достатньо мінімального виправлення?** Змініть лише потрібні права, а не ставте `777`.

### 10.3. Додаткові механізми

Окрім класичних прав, Linux підтримує **ACL** (списки контролю доступу) та системи мандатного контролю на кшталт AppArmor, яка використовується в Ubuntu. Наявність ACL показує символ `+` в кінці рядка прав у `ls -l`; переглянути їх можна командою `getfacl`. Ці механізми виходять за межі курсу, але їх слід пам'ятати під час діагностики складних випадків.

## 11. Практичні рекомендації

| Об'єкт | Рекомендовані права |
|---|---|
| Звичайні документи | `644` або `640` |
| Приватні файли, паролі, токени | `600` |
| Каталог `~/.ssh` | `700` |
| Приватний SSH-ключ | `600` |
| Публічний SSH-ключ | `644` |
| Скрипти й програми | `755` або `700` (для особистих) |
| Каталоги загального доступу | `755` |
| Спільні каталоги групи | `2775` або `770` із `setgid` |

OpenSSH відмовляється використовувати приватний ключ, якщо його права надто відкриті, і виводить повідомлення `WARNING: UNPROTECTED PRIVATE KEY FILE!`. Це приклад того, як права доступу безпосередньо впливають на безпеку.

У Ubuntu домашні каталоги нових користувачів зазвичай мають права `750`, тобто інші користувачі не можуть переглядати їх вміст. У інших дистрибутивах значення може відрізнятися.

## 12. Типові помилки

1. **Використання `chmod 777` для «виправлення» помилки.** Це відкриває доступ усім і приховує справжню причину.
2. **Забуті права на каталог.** Файл доступний, але каталог без `x` не дає до нього дійти.
3. **Плутанина прав на файл і на каталог.** Видалення файла залежить від прав каталогу, а не файла.
4. **Спроба змінити права чужого файла.** `chmod` дозволений власнику й `root`: інакше буде `Operation not permitted`.
5. **Спроба змінити власника без `sudo`.** `chown` вимагає прав адміністратора.
6. **Неправильне розуміння `umask`.** Маска **вилучає** права, а не додає їх.
7. **Запуск скрипта без `./`.** Поточний каталог не входить у `PATH`.
8. **Рекурсивне `chmod -R` у неправильному каталозі.** Змінює права всього дерева; після помилки відновити початкові права важко.
9. **Припущення, що права символічного посилання впливають на доступ.** Працюють права цілі.
10. **Відсутність перевірки шляху.** Недоступний каталог у середині шляху блокує доступ до всіх об'єктів нижче.

!!! warning "Навчальне середовище"

    Експериментуйте з правами лише у файлах і каталогах, створених вами в `~/perm-practice`. Не змінюйте права та власників системних файлів, не використовуйте `chmod -R` і `chown -R` за межами навчального каталогу.

## 13. Security Note

!!! danger

    Помилки в правах доступу можуть відкрити конфіденційні дані стороннім або зламати роботу системи й служб. Права `root` надають повний контроль над системою: використовуйте принцип найменших привілеїв.

Правила безпечної роботи:

1. Надавайте лише ті права, які справді потрібні, і лише тим, кому вони потрібні.
2. Не використовуйте `chmod 777` і `chmod -R 777`.
3. Приватні дані (паролі, токени, ключі) зберігайте з правами `600`, а їхні каталоги — `700`.
4. Не змінюйте права та власників системних файлів (`/etc`, `/usr`, `/boot`, `/var`) без чіткого розуміння наслідків.
5. Перед `chmod -R` і `chown -R` перевіряйте шлях за допомогою `pwd` і `ls -ld`.
6. Не встановлюйте `setuid` і `setgid` на власні програми й скрипти без крайньої потреби: помилка в такій програмі може дозволити підвищення привілеїв.
7. Не запускайте сторонні скрипти, не перевіривши їх вміст і права.
8. Не використовуйте `sudo`, якщо достатньо прав звичайного користувача.
9. Не вимикайте засоби захисту лише для усунення помилки доступу.
10. Пам'ятайте про `/tmp`: не зберігайте там секрети, бо каталог доступний усім для запису.

## 14. Практичні вправи

Усі вправи виконуються в каталозі `~/perm-practice`.

### Вправа 1. Читання прав

```bash
ls -l /etc/passwd /etc/shadow /usr/bin/passwd

```

Завдання:

1. Для кожного об'єкта визначте тип, власника, групу та числовий запис прав.
2. Поясніть, чому `/etc/passwd` читається всіма, а `/etc/shadow` — ні.
3. Поясніть значення `s` у `/usr/bin/passwd` і `t` у `/tmp`.

### Вправа 2. Спроба порушити доступ

```bash

cat /etc/shadow
echo "$?"
ls /root

```

Завдання:

1. Запишіть повідомлення про помилки та коди завершення.
2. Поясніть, чому `Permission denied` не означає, що файла не існує.

### Вправа 3. `chmod` для файла

```bash

printf 'secret\n' > note.txt
ls -l note.txt
chmod 600 note.txt
chmod g+r note.txt
chmod u=rw,g=,o= note.txt
chmod 000 note.txt
cat note.txt
test -r note.txt; echo $?
chmod 644 note.txt
cat note.txt
```

Завдання:

1. Перед кожною командою `chmod` запишіть очікувані права, а потім перевірте їх `ls -l`.
2. Поясніть, чому власник файла з правами `000` не може його прочитати, але може змінити права.

### Вправа 4. Права на каталог

```bash

```

Завдання:

1. Запишіть результат кожної команди та повідомлення про помилки.
2. Поясніть різницю між правами `r` і `x` на каталозі.
3. Який набір прав потрібен, щоб створювати файли в каталозі?

### Вправа 5. `umask`

Завдання:

### Вправа 6. Виконуваний скрипт

Завдання:

1. Поясніть кожну помилку та кожен успішний запуск.

### Вправа 7. Спільний каталог і `setgid`

Завдання:

### Вправа 8. Діагностика

Створіть ситуацію:


Завдання:

### Прибирання

## 18. Ключові висновки

1. Кожен файл і каталог має власника, групу та права для трьох категорій: власник, група, інші; система перевіряє категорії по черзі.
2. Права `r`, `w`, `x` мають різне значення для файлів і каталогів; для доступу до файла потрібне `x` на кожному каталозі шляху.
3. Видалення, створення й перейменування залежать від прав на **каталог**.
4. Права записуються текстом (`rwxr-xr--`) і числом (`754`): `r`=4, `w`=2, `x`=1.
5. `chmod` змінює права в символьному й числовому записі; `chown` змінює власника (лише `root`), `chgrp` — групу (на групу, до якої належить власник).
6. `umask` вилучає біти з початкових прав `666` і `777` для нових файлів і каталогів.
7. `setuid`, `setgid` і `sticky` змінюють поведінку програм і каталогів; їх слід використовувати обережно.
8. Файл запускається, якщо має `x` і файлову систему змонтовано без `noexec`; поточний каталог не входить у `PATH`.
9. Помилку `Permission denied` діагностують за порядком: користувач, об'єкт, права, шлях, каталог, інші механізми.
10. Принцип найменших привілеїв: надавайте мінімально необхідні права; `chmod 777` і зайве `sudo` — ознаки неправильного розв'язання.
