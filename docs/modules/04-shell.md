# Модуль 4. Термінал і командна оболонка Linux

## 1. Навчальні цілі

Після опрацювання модуля студент повинен уміти:

- пояснювати різницю між терміналом, командною оболонкою та командою;
- виконувати команди з аргументами й параметрами;
- користуватися довідкою та історією команд;
- розуміти змінні оболонки й змінні середовища;
- правильно використовувати лапки та спеціальні символи;
- застосовувати перенаправлення вводу/виводу й конвеєри;
- пояснювати логічні оператори та код завершення команди;
- безпечно працювати в командному рядку.

## 2. Вступ

Командний рядок — один з основних інтерфейсів керування Linux. Він дає змогу запускати програми, досліджувати систему, обробляти дані й автоматизувати повторювані завдання. Командна оболонка особливо важлива під час адміністрування серверів, діагностики несправностей, роботи з DevOps-інструментами та виконання завдань кібербезпеки.

У модулі використовується переважно **Bash** (Bourne Again SHell). Інші оболонки, наприклад Zsh, Fish і Dash, можуть мати інші можливості або синтаксис.

## 3. Основні поняття

### 3.1. Термінал і командна оболонка

**Термінал** — інтерфейс для введення команд і перегляду текстового результату. У графічному Linux це зазвичай окрема програма.

**Командна оболонка (shell)** — програма, яка читає введені команди, обробляє спеціальні конструкції та запускає відповідні програми або виконує вбудовані операції.

Перевірте оболонку, задану для користувача, і поточний процес оболонки:

```bash
echo "$SHELL"
ps -p "$$" -o pid=,comm=
```

`$SHELL` зазвичай містить шлях до оболонки користувача за замовчуванням; він не обов'язково точно вказує на поточний процес. `$$` у Bash — PID поточної оболонки.

### 3.2. Команда, параметр та аргумент

Типова схема командного рядка:

```text
команда [параметри] [аргументи]
```

Наприклад:

```bash
ls -l /etc
```

- `ls` — команда;
- `-l` — параметр, що вмикає детальний формат;
- `/etc` — аргумент, який указує на каталог.

Квадратні дужки у схемах синтаксису зазвичай позначають необов'язкові елементи й не вводяться буквально.

### 3.3. Запрошення командного рядка

Приклад prompt:

```text
student@linux-pc:~$
```

Зазвичай він містить ім'я користувача, ім'я вузла та поточний каталог. `~` зазвичай позначає домашній каталог. Символ `$` традиційно використовується для звичайного користувача, а `#` — для адміністративної оболонки, але prompt можна налаштувати. Права користувача перевіряйте командами `whoami` або `id`, а не лише за виглядом prompt.

## 4. Довідка та визначення типу команди

Багато програм підтримують коротку довідку:

```bash
ls --help
cp --help
grep --help
```

Для перегляду довідкової сторінки використовується `man`:

```bash
man ls
man bash
man grep
```

У переглядачі `man` клавіша `Space` переходить уперед, `b` — назад, `/слово` починає пошук, `n` переходить до наступного збігу, `q` завершує перегляд.

Вбудовані команди Bash, наприклад `cd`, `export` і `history`, можна досліджувати через `help`:

```bash
help cd
help export
help history
```

Команда `type` показує, як оболонка інтерпретує назву:

```bash
type cd
type ls
type python3
```

`whatis ls` показує короткий опис, а `apropos network` шукає довідкові сторінки за ключовими словами. Результат залежить від наявності й актуальності індексу довідки.

## 5. Історія команд і клавіатурні скорочення

Перегляд історії:

```bash
history
history 10
```

Корисні клавіатурні скорочення:

| Скорочення | Призначення |
|---|---|
| `Tab` | Доповнення назви команди, файла або каталогу |
| `Ctrl+C` | Надсилання сигналу переривання foreground-процесу в типовій конфігурації термінала |
| `Ctrl+D` | Передавання ознаки кінця вводу; на порожньому рядку часто завершує інтерактивну оболонку |
| `Ctrl+L` | Очищення видимої області термінала в Bash |
| `Ctrl+A` / `Ctrl+E` | Перехід на початок / кінець поточного рядка |
| `Ctrl+U` / `Ctrl+K` | Видалення тексту від курсора до початку / кінця рядка |
| `Ctrl+R` | Пошук у історії команд |
| `↑` / `↓` | Перегляд команд в історії |

`Ctrl+C` не гарантує скасування вже виконаних змін. Перед повторним запуском команди з історії перевірте її аргументи та шляхи.

## 6. Змінні оболонки та середовища

Змінна зберігає значення, пов'язане з певним ім'ям. У Bash присвоєння виконується без пробілів навколо `=`:

```bash
course="Linux Basics"
echo "$course"
```

Запис `course = "Linux Basics"` не є правильним присвоєнням у Bash.

Для отримання значення перед ім'ям змінної ставлять `$`. Фігурні дужки чітко відокремлюють її ім'я:

```bash
prefix="lab"
echo "${prefix}_04"
```

Поширені змінні середовища:

| Змінна | Типове призначення |
|---|---|
| `HOME` | Домашній каталог користувача |
| `USER` | Ім'я користувача в середовищі |
| `SHELL` | Зазвичай шлях до оболонки користувача за замовчуванням |
| `PATH` | Каталоги, у яких оболонка шукає виконувані команди |
| `PWD` | Поточний каталог, який відстежує оболонка |
| `LANG` | Налаштування локалі за замовчуванням |
| `TERM` | Тип термінала для програм, які використовують його можливості |

Перегляд значень:

```bash
echo "$HOME"
echo "$USER"
echo "$PATH"
printenv LANG
printenv
```

Звичайне присвоєння створює змінну поточної оболонки. Команда `export` позначає її для передавання в середовище дочірніх процесів:

```bash
course="Linux Basics"
export course
export COURSE_NAME="Linux Basics"
```

Змінні, створені дочірнім процесом, самі по собі не змінюють середовище батьківської оболонки.

`PATH` містить список каталогів, розділених двокрапками. Перевірити, яку команду оболонка знайде, можна так:

```bash
command -v ls
command -v python3
```

Не додавайте до `PATH` невідомі каталоги або каталоги, доступні для запису стороннім користувачам: це може призвести до запуску небажаної програми замість очікуваної.

## 7. Лапки, екранування та підстановки

### 7.1. Подвійні й одинарні лапки

Подвійні лапки зберігають пробіли в одному аргументі, але зазвичай дозволяють підстановку змінних:

```bash
name="Linux student"
echo "Hello, $name"
printf '<%s>\n' "$name"
```

Одинарні лапки зберігають буквальне значення більшості символів усередині них:

```bash
echo '$name'
echo "$name"
```

Перша команда виводить буквальний текст `$name`, друга — значення змінної. Для значень змінних зазвичай використовуйте подвійні лапки, якщо навмисно не потрібне розбиття на слова.

### 7.2. Екранування

Зворотна скісна риска `\` може надати наступному символу буквального значення:

```bash
echo "Ціна: \$10"
```

Щоб передати рядок із пробілами як один аргумент, використовуйте лапки:

```bash
file_name="my report.txt"
printf '%s\n' "$file_name"
```

### 7.3. Шаблони імен файлів

Bash може розгортати шаблони до запуску команди:

| Шаблон | Значення |
|---|---|
| `*` | Будь-яка послідовність символів, зокрема порожня |
| `?` | Один будь-який символ |
| `[abc]` | Один символ із набору `a`, `b` або `c` |
| `[0-9]` | Один символ із заданого діапазону |

Приклади:

```bash
printf '%s\n' *.txt
printf '%s\n' file?.log
printf '%s\n' report[12].txt
printf '%s\n' "*.txt"
```

Останній приклад передає `*.txt` буквально, без розгортання шаблону. Якщо шаблон не відповідає жодному імені, Bash за типовими налаштуваннями може передати його як буквальний рядок; поведінку можна змінити налаштуваннями оболонки.

### 7.4. Підстановка команд

Підстановка команд дає змогу використати результат іншої команди як частину аргументу:

```bash
current_user="$(whoami)"
echo "Користувач: $current_user"
```

Синтаксис `$(...)` зазвичай читабельніший за старіший варіант зі зворотними лапками. Підстановка команд видаляє кінцеві символи нового рядка з результату.

## 8. Стандартні потоки вводу та виводу

Більшість програм використовують три стандартні потоки:

| Потік | Дескриптор | Призначення |
|---|---:|---|
| `stdin` | 0 | Стандартний ввід |
| `stdout` | 1 | Стандартний вивід |
| `stderr` | 2 | Повідомлення про помилки та діагностика |

### 8.1. Перенаправлення в файл

Оператор `>` записує stdout у файл, замінюючи його попередній вміст. `>>` додає дані в кінець файла:

```bash
printf 'First line\n' > ~/shell-demo.txt
printf 'Second line\n' >> ~/shell-demo.txt
cat ~/shell-demo.txt
```

**Увага:** `>` може перезаписати наявний файл. Перед використанням перевірте шлях і назву.

Оператор `<` спрямовує вміст файла на stdin:

```bash
wc -l < ~/shell-demo.txt
```

### 8.2. Перенаправлення помилок

Оператор `2>` спрямовує stderr у файл:

```bash
ls /directory-that-does-not-exist 2> ~/shell-errors.txt
cat ~/shell-errors.txt
```

`2>>` додає повідомлення до наявного файла. У Bash запис `command > output.txt 2>&1` спрямовує stdout у файл, а потім stderr туди, куди на цей момент спрямовано stdout. Порядок перенаправлень має значення.

Bash також підтримує скорочення:

```bash
command &> output.txt
```

`/dev/null` відкидає записані в нього дані. Наприклад, `command 2>/dev/null` приховує повідомлення про помилки. Не використовуйте це як універсальне виправлення: повідомлення stderr часто потрібні для діагностики.

## 9. Конвеєри команд

Конвеєр (pipeline) передає stdout однієї команди на stdin іншої. Для цього використовується оператор `|`:

```bash
printf 'apple\nbanana\napricot\n' | grep '^a'
history | tail -n 10
printenv | sort
```

У першому прикладі `grep` відбирає рядки, що починаються з `a`. У другому `tail` показує останні десять рядків історії. У третьому змінні середовища сортуються.

Різниця між `|` і `>`:

- `|` передає вивід іншій команді;
- `>` записує вивід у файл.

Наприклад:

```bash
printenv | sort
printenv > ~/environment.txt
```

У конвеєрі stdout попередньої команди підключається до stdin наступної, а stderr зазвичай залишається окремим, якщо його не перенаправити.

## 10. Послідовність команд і логічні оператори

Крапка з комою `;` розділяє команди, які виконуються послідовно незалежно від результату попередньої:

```bash
pwd; whoami; date
```

Оператор `&&` запускає наступну команду лише після успішного завершення попередньої:

```bash
mkdir -p ~/shell-practice && echo "Каталог готовий"
```

Оператор `||` запускає наступну команду, якщо попередня завершилася з ненульовим кодом:

```bash
cd ~/directory-that-does-not-exist || echo "Не вдалося перейти до каталогу"
```

Порівняйте:

```bash
command1; command2
command1 && command2
command1 || command2
```

## 11. Код завершення команди

Більшість команд повертають код завершення. `0` зазвичай означає успіх, ненульове значення — помилку або інший результат, визначений конкретною програмою.

У Bash параметр `$?` містить код завершення останньої виконаної команди:

```bash
true
echo "$?"
false
echo "$?"
```

`true` завершується з кодом `0`, а `false` — з кодом `1`. Для перевірки реальних команд:

```bash
ls /etc
echo "$?"
ls /directory-that-does-not-exist
echo "$?"
```

Не покладайтеся на конкретний ненульовий код без перевірки документації відповідної програми. Перевіряйте `$?` одразу після потрібної команди, оскільки інша команда змінить це значення.

## 12. Псевдоніми команд

Псевдонім (`alias`) — це скорочення або заміна тексту команди, яку оболонка застосовує під час інтерактивної роботи.

```bash
alias
alias ll='ls -lah'
ll
unalias ll
```

Псевдонім зазвичай діє лише в поточній оболонці, якщо його не визначено в конфігурації оболонки. Не слід припускати, що певний псевдонім існує на кожній системі. У сценаріях автоматизації краще використовувати явні команди.

## 13. Типові помилки

1. **Пропущені лапки.** Змінна з пробілами може розділитися на кілька аргументів. Використовуйте `"$variable"`, якщо розбиття не потрібне.
2. **Пробіли в присвоєнні.** Правильно `course="Linux Basics"`, а не `course = "Linux Basics"`.
3. **Перезапис файла.** `>` замінює попередній вміст, а `>>` додає дані.
4. **Неправильне розуміння логічних операторів.** `&&` продовжує після успіху, `||` — після невдачі.
5. **Запізніла перевірка `$?`.** Код змінюється після виконання наступної команди.
6. **Припущення, що всі команди є окремими програмами.** Наприклад, `cd` має змінювати робочий каталог самої оболонки, тому зазвичай є її вбудованою командою.
7. **Сліпе копіювання команд.** Невідома команда може видалити дані або змінити систему. Спершу перевірте її призначення та аргументи.

## 14. Безпека роботи в командній оболонці

1. Перед виконанням команди перевіряйте синтаксис, аргументи й цільові шляхи.
2. Не запускайте невідомі команди з підвищеними привілеями.
3. Не вставляйте команди з неперевірених джерел без розуміння їхньої дії.
4. Будьте уважні з `>` — він може перезаписати файл.
5. Не приховуйте повідомлення про помилки, якщо вони потрібні для діагностики.
6. Не додавайте до `PATH` невідомі або небезпечні каталоги.
7. Виконуйте навчальні вправи в домашньому каталозі з тестовими файлами.
8. Не використовуйте `sudo`, якщо достатньо прав звичайного користувача.
9. Перевіряйте код завершення важливих команд.
10. Перед повторним запуском команди з історії перевірте її актуальність.

!!! warning "Безпека"
    У цьому модулі не потрібно видаляти системні файли, змінювати права системних каталогів або запускати невідомі скрипти. Практичні вправи виконуються без `sudo` та використовують тестові дані в домашньому каталозі.

## 15. Практичні вправи

### Вправа 1. Оболонка та довідка

Виконайте:

```bash
echo "$SHELL"
ps -p "$$" -o pid=,comm=
type cd
type ls
help cd
ls --help
```

Завдання:

1. Визначте оболонку користувача за замовчуванням і назву поточного процесу оболонки.
2. З'ясуйте, чим `cd` відрізняється від `ls` за типом команди.
3. Знайдіть параметр `ls` для детального виведення.

### Вправа 2. Змінні та лапки

```bash
course="Linux Basics"
student="student"
echo "$course"
echo "Курс: $course; користувач: $student"
echo '$course'
printf '<%s>\n' "$course"
```

Завдання:

1. Поясніть різницю між одинарними й подвійними лапками.
2. Перевірте значення `HOME`, `USER` і `PATH`.
3. Поясніть, чому навколо `=` у присвоєнні не ставлять пробіли.

### Вправа 3. Шаблони

```bash
printf '%s\n' *.txt
printf '%s\n' "*.txt"
printf '%s\n' file?.log
```

Завдання:

1. Поясніть різницю між `*.txt` і `"*.txt"`.
2. Поясніть призначення `?`.
3. Опишіть поведінку оболонки, якщо шаблон не відповідає жодному імені.

### Вправа 4. Перенаправлення

```bash
printf 'First line\n' > ~/module4-demo.txt
printf 'Second line\n' >> ~/module4-demo.txt
cat ~/module4-demo.txt
wc -l < ~/module4-demo.txt
```

Завдання:

1. Поясніть різницю між `>` і `>>`.
2. Визначте кількість рядків.
3. Поясніть призначення `<`.
4. Перевірте, що файл створено у домашньому каталозі.

### Вправа 5. Конвеєри

```bash
printf 'pear\napple\nplum\napricot\n' | sort
printf 'pear\napple\nplum\napricot\n' | grep '^a'
printenv | sort | head -n 5
```

Завдання:

1. Поясніть, як дані передаються між командами.
2. Визначте роль `sort`, `grep` і `head`.

## 19. Ключові висновки

1. Термінал забезпечує інтерфейс вводу й виводу, а оболонка інтерпретує команди.
2. Bash обробляє змінні, лапки, шаблони, підстановки, перенаправлення та конвеєри.
3. `--help`, `man`, `help` і `type` допомагають досліджувати команди.
4. Змінні середовища передають налаштування дочірнім процесам; `PATH` впливає на пошук виконуваних команд.
5. Лапки допомагають зберігати пробіли та контролювати підстановку спеціальних символів.
6. `stdin`, `stdout` і `stderr` дають змогу будувати гнучкі командні ланцюжки.
7. Конвеєри передають дані між командами, а `>`, `>>` і `<` перенаправляють потоки.
8. Код завершення допомагає оцінити результат виконання команди.
9. Безпечна робота в оболонці вимагає перевірки команд, аргументів і шляхів перед виконанням.
