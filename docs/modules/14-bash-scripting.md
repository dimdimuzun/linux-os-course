# Модуль 14. Bash-скриптинг

## 1. Навчальні цілі

Після опрацювання модуля студент повинен уміти:

- пояснювати, що таке скрипт, shebang, і запускати скрипти різними способами;
- використовувати змінні, параметри (`$1`, `$#`, `"$@"`), значення за замовчуванням і підстановку параметрів;
- виконувати арифметику, читати введення (`read`), використовувати here-document і підстановку команд;
- записувати умови (`if`, `case`) за допомогою `[[ ]]`, перевіряти файли, рядки й числа;
- використовувати цикли `for`, `while`, `until`, `break`, `continue` та безпечно обробляти списки файлів;
- створювати функції з локальними змінними та передавати результат через код завершення й вивід;
- працювати з масивами;
- повертати правильні коди завершення, виводити помилки у `stderr`, застосовувати `set -euo pipefail` і `trap`;
- обробляти опції командного рядка за допомогою `getopts`;
- планувати виконання скриптів за допомогою `cron` і розуміти зв'язок із таймерами `systemd`;
- налагоджувати скрипти за допомогою `bash -n`, `bash -x`, `set -x`;
- застосовувати безпечні практики: лапки, перевірка введення, `mktemp`, захист від небезпечного видалення;
- створювати практичні скрипти для автоматизації завдань адміністратора.

## 2. Вступ

Адміністратор багаторазово виконує однакові послідовності команд: перевірка дискового простору, архівування каталогів, очищення журналів, створення користувачів. Замість того щоб вводити їх щоразу, послідовність записують у файл — **скрипт**. Скрипт виконується однаково, не залежить від пам'яті й уважності людини, його можна запланувати за розкладом, перевірити, зберегти й поділитися ним.

Усе, що ви вивчили в модулі 4, — змінні, лапки, підстановки, перенаправлення, конвеєри, коди завершення, `&&` і `||` — працює і в скриптах. Скрипт — це по суті ті самі команди, але з **логікою**: умовами, циклами, функціями й обробкою помилок. Модуль спирається також на файли й права доступу (модулі 5–6), процеси й сигнали (модуль 8), служби й таймери (модуль 10), диски (модуль 13) та мережеві інструменти (модуль 12).

Скрипти працюють з реальними даними, тому одна помилка — незакрита змінна, зайвий пробіл — може видалити не те. У модулі ми приділяємо особливу увагу **безпеці**: правильним лапкам, перевірці введення, обережному видаленню.

Усі вправи виконуються в каталозі `~/scripts-practice`, не потребують `sudo` і не змінюють систему. Приклади виведення є умовними: у вашому середовищі результати можуть відрізнятися.

## 3. Перший скрипт

### 3.1. Структура й запуск

Скрипт — це текстовий файл із командами. Перший рядок `#!/bin/bash` (**shebang**) указує інтерпретатор, який ядро використає для виконання файла:

```bash
mkdir -p ~/scripts-practice
cd ~/scripts-practice
cat > hello.sh <<'EOF'
#!/bin/bash
# Простий скрипт-вітання
echo "Hello, $USER!"
echo "Сьогодні: $(date +%F)"
EOF
```

Рядки, що починаються з `#` (крім shebang), — коментарі.

| Варіант shebang | Особливості |
|---|---|
| `#!/bin/bash` | Явно вказує Bash; передбачуваний шлях |
| `#!/usr/bin/env bash` | Шукає `bash` у `PATH`; зручніше для переносимості |
| `#!/bin/sh` | Спрощена POSIX-оболонка (в Ubuntu — `dash`); не підтримує розширень Bash (`[[ ]]`, масиви) |

Запуск:

```bash
bash hello.sh
chmod u+x hello.sh
./hello.sh
echo "$?"
```

- `bash hello.sh` — інтерпретатор читає файл; право `x` не потрібне;
- `./hello.sh` — запуск як програми: потрібне право `x` (модуль 6), а `./` — бо поточного каталогу немає в `PATH` (модуль 4);
- код завершення скрипта дорівнює коду останньої виконаної команди або значенню `exit`.

Щоб викликати скрипт за ім'ям, його поміщають у каталог із `PATH` (наприклад, `~/bin` або `/usr/local/bin`; модуль 3) і надають право `x`.

### 3.2. Перевірка й налагодження запуску

```bash
bash -n hello.sh
bash -x hello.sh
```

- `bash -n` перевіряє **синтаксис** без виконання;
- `bash -x` виконує скрипт, виводячи кожну команду після підстановок (рядки починаються з `+`). Всередині скрипта те саме дає `set -x` (увімкнути) та `set +x` (вимкнути).

## 4. Змінні та параметри

### 4.1. Змінні

```bash
name="Linux"
count=5
today="$(date +%F)"
readonly VERSION="1.0"
echo "Курс: $name, кількість: $count, дата: $today"
echo "${name}-course"
```

Правила (модуль 4):

- присвоєння без пробілів навколо `=`;
- значення зі спеціальними символами та змінні беруть у **подвійні лапки**;
- фігурні дужки `${name}` відокремлюють ім'я змінної від тексту;
- `readonly` забороняє змінювати значення;
- імена змінних — літери, цифри й `_`; константи зазвичай пишуть великими літерами.

Результат команди зберігають за допомогою підстановки `$(...)`.

### 4.2. Позиційні параметри

Аргументи, з якими запущено скрипт, доступні як спеціальні змінні:

| Змінна | Значення |
|---|---|
| `$0` | Ім'я скрипта (як його було викликано) |
| `$1`, `$2`, … | Перший, другий… аргументи |
| `$#` | Кількість аргументів |
| `"$@"` | Усі аргументи як окремі слова (**рекомендовано**) |
| `"$*"` | Усі аргументи одним рядком |
| `$?` | Код завершення останньої команди |
| `$$` | PID поточного скрипта |
| `$!` | PID останнього фонового процесу |

```bash
cat > params.sh <<'EOF'
#!/bin/bash
echo "Скрипт: $0"
echo "Кількість аргументів: $#"
echo "Перший: $1"
for arg in "$@"; do
  echo "  [$arg]"
done
EOF
chmod +x params.sh
./params.sh one "two words" three
```

Різниця між `"$@"` і `"$*"`: перший зберігає межі аргументів (`"two words"` лишається одним словом), другий об'єднує їх в один рядок. У майже всіх випадках потрібен `"$@"`.

Команда `shift` відкидає перший аргумент і зсуває решту: `$2` стає `$1`. Використовується при обробці аргументів у циклі.

### 4.3. Значення за замовчуванням і операції над рядками

| Запис | Дія |
|---|---|
| `${var:-значення}` | Якщо `var` порожня або не задана — підставити `значення` |
| `${var:=значення}` | Те саме й присвоїти `var` |
| `${var:?повідомлення}` | Якщо порожня — вивести повідомлення й **завершити скрипт** |
| `${#var}` | Довжина рядка |
| `${var%суфікс}` | Видалити найкоротший збіг суфікса |
| `${var#префікс}` | Видалити найкоротший збіг префікса |
| `${var%%шаблон}`, `${var##шаблон}` | Видалити найдовший збіг |
| `${var/старе/нове}` | Замінити перше входження |
| `${var^^}`, `${var,,}` | Перетворити на великі / малі літери |

```bash
file="/home/user/report.final.txt"
echo "${file##*/}"
echo "${file%.*}"
echo "${file%.txt}.md"
name="${1:-World}"
dir="${TARGET_DIR:?Не задано TARGET_DIR}"
```

Запис `${dir:?…}` — один із найважливіших захисників від помилок: якщо змінну не задано, скрипт зупиниться з повідомленням і не виконає небезпечну команду (розділ 12).

Для імені файла й каталогу існують також `basename` і `dirname` (модуль 3).

### 4.4. Арифметика

Bash виконує **цілочислові** обчислення:

```bash
a=7
b=3
echo "$(( a + b ))"
echo "$(( a * b ))"
echo "$(( a / b )) залишок $(( a % b ))"
n=$(( n + 1 ))
(( a > b )) && echo "a більше"
```

Дробові числа Bash не підтримує (для них використовують `bc` або `awk`).

Вираз `(( ... ))` повертає код `0`, якщо результат ненульовий, і `1`, якщо нульовий. Тому `(( n++ ))` при `n=0` має код `1` і може несподівано зупинити скрипт із `set -e`; безпечніше `n=$(( n + 1 ))`.

## 5. Введення

```bash
read -r -p "Ваше ім'я: " name
echo "Привіт, $name"
```

| Параметр `read` | Дія |
|---|---|
| `-r` | Не інтерпретувати зворотні скісні риски (використовуйте завжди) |
| `-p "текст"` | Показати запрошення |
| `-s` | Не відображати введення |
| `-t N` | Тайм-аут у секундах |

Скрипти адміністратора мають працювати **без запитів** (щоб їх можна було запускати за розкладом), тому дані краще передавати параметрами. Введення зі `stdin` читають також у циклах (розділ 7.4).

**Here-document** задає багаторядковий текст (модуль 5), **here-string** `<<< "рядок"` передає рядок на `stdin`:

```bash
cat <<EOF
Користувач: $USER
EOF
read -r first second <<< "alpha beta"
echo "$second"
```

## 6. Умови

### 6.1. Команда `[[ ]]` і `[ ]`

Умова в Bash — це **команда**, що повертає код завершення (`0` — істина). Для перевірок використовують `[[ ... ]]` (рекомендовано в Bash) або `[ ... ]` (`test`, POSIX):

| Особливість | `[ ]` / `test` | `[[ ]]` |
|---|---|---|
| Стандарт | POSIX | Розширення Bash |
| Змінні без лапок | Потрібні лапки, інакше помилки | Безпечніше, розбиття слів немає |
| `&&`, `\|\|` усередині | Лише через `-a`, `-o` (небажано) | Підтримуються |
| Порівняння з шаблоном `==` | Ні | Так |
| Регулярні вирази `=~` | Ні | Так |

Пробіли навколо дужок та операторів **обов'язкові**: `[[ $a -eq 1 ]]`, а не `[[$a-eq1]]`.

### 6.2. Оператори перевірки

**Файли:**

| Оператор | Істинно, якщо… |
|---|---|
| `-e шлях` | Існує |
| `-f шлях` | Звичайний файл |
| `-d шлях` | Каталог |
| `-L шлях` | Символічне посилання |
| `-r`, `-w`, `-x шлях` | Є право читання, запису, виконання для поточного користувача (модуль 6) |
| `-s шлях` | Існує й не порожній |
| `f1 -nt f2` | `f1` новіший за `f2` |

**Рядки:**

| Оператор | Істинно, якщо… |
|---|---|
| `-z "$s"` | Рядок порожній |
| `-n "$s"` | Рядок не порожній |
| `"$a" == "$b"`, `!=` | Рядки збігаються / не збігаються |
| `"$s" == шаблон*` | Збіг із шаблоном (лише в `[[ ]]`, шаблон без лапок) |
| `"$s" =~ ^[0-9]+$` | Збіг із регулярним виразом (лише в `[[ ]]`) |

**Числа** (у `[[ ]]` та `[ ]`): `-eq`, `-ne`, `-lt`, `-le`, `-gt`, `-ge`. У виразі `(( ))` можна писати `==`, `!=`, `<`, `>`, `<=`, `>=`.

Логіка: `!` (НЕ), `&&` (І), `||` (АБО).

### 6.3. `if`, `elif`, `else`

```bash
#!/bin/bash
if [[ $# -ne 1 ]]; then
  echo "Використання: $0 шлях" >&2
  exit 2
fi

path="$1"
if [[ ! -e "$path" ]]; then
  echo "Не існує: $path" >&2
  exit 1
elif [[ -d "$path" ]]; then
  echo "$path — каталог"
elif [[ -f "$path" ]]; then
  echo "$path — звичайний файл"
else
  echo "$path — інший тип"
fi
```

Скорочений запис через `&&` і `||` (модуль 4):

```bash
[[ -r "$path" ]] && echo "читати можна" || echo "читати не можна"
```

Така конструкція `A && B || C` виконає `C` також тоді, коли `A` істинна, але `B` завершилася помилкою, тому для складних випадків використовують `if`.

Команду можна використовувати прямо як умову:

```bash
if grep -q root /etc/passwd; then
  echo "користувач root є"
fi
if ! command -v curl > /dev/null; then
  echo "curl не встановлено"
fi
```

Параметр `-q` у `grep` вимикає вивід і залишає лише код завершення.

### 6.4. `case`

Для вибору зі списку зразків застосовують `case`:

```bash
case "$1" in
  start)
    echo "запуск"
    ;;
  stop|halt)
    echo "зупинка"
    ;;
  *.txt|*.md)
    echo "текстовий файл"
    ;;
  *)
    echo "невідома команда: $1" >&2
    exit 2
    ;;
esac
```

Кожен варіант завершується `;;`; `*` — «усе інше»; кілька зразків розділяють `|`.

## 7. Цикли

### 7.1. `for`

```bash
for name in alice bob carol; do
  echo "Привіт, $name"
done

for i in {1..5}; do
  echo "Крок $i"
done

for ((i = 0; i < 3; i++)); do
  echo "i=$i"
done

for file in *.txt; do
  [[ -e "$file" ]] || continue
  echo "Файл: $file"
done
```

Для обходу файлів використовують **шаблон** (`*.txt`), а не `$(ls)`: розбір виводу `ls` ламається на іменах із пробілами. Перевірка `[[ -e "$file" ]] || continue` потрібна, бо коли файлів немає, шаблон лишається буквальним текстом `*.txt`.

Змінна цикла й `"$@"`:

```bash
for arg in "$@"; do
  echo "Аргумент: $arg"
done
```

### 7.2. `while` і `until`

```bash
n=3
while [[ $n -gt 0 ]]; do
  echo "Залишилось: $n"
  n=$(( n - 1 ))
done

until [[ $n -ge 3 ]]; do
  n=$(( n + 1 ))
done
```

`while` виконує тіло, поки умова істинна, `until` — поки хибна.

### 7.3. `break` та `continue`

- `break` — вийти з циклу;
- `continue` — перейти до наступної ітерації.

```bash
for i in 1 2 3 4 5; do
  [[ $i -eq 2 ]] && continue
  [[ $i -eq 4 ]] && break
  echo "$i"
done
```

### 7.4. Читання файла рядок за рядком

```bash
while IFS= read -r line; do
  echo "Рядок: $line"
done < /etc/hostname
```

Конструкція `IFS= read -r` зберігає пробіли на початку й кінці рядка та зворотні скісні риски. Перенаправлення `< файл` подається після `done`. Читання виводу команди:

```bash
while read -r user; do
  echo "Користувач: $user"
done < <(cut -d: -f1 /etc/passwd | head -n 3)
```

Запис `< <(команда)` передає вивід команди як файл (process substitution). Конвеєр `команда | while ...` теж працює, але цикл виконується в підоболонці, тому змінні, змінені в ньому, не доступні після циклу.

## 8. Функції

```bash
log() {
  printf '%s [%s] %s\n' "$(date '+%F %T')" "$1" "$2"
}

is_number() {
  [[ "$1" =~ ^[0-9]+$ ]]
}

max() {
  local a="$1" b="$2"
  if (( a > b )); then
    echo "$a"
  else
    echo "$b"
  fi
}

log INFO "початок роботи"
if is_number "42"; then log INFO "число"; fi
biggest="$(max 7 12)"
echo "$biggest"
```

Важливі правила:

- функцію потрібно **оголосити до першого виклику**;
- аргументи функції — `$1`, `$2`, … (власні, не плутати з аргументами скрипта);
- змінні всередині функції за замовчуванням **глобальні**: щоб зробити їх локальними, використовуйте `local`;
- `return N` повертає код завершення (0–255), а не значення. Результат (рядок, число) повертають **виводом** і зчитують через `$(функція)`;
- код завершення функції — це «успіх/невдача», яку можна перевірити умовою (`if is_number "$x"; then`).

## 9. Масиви

```bash
fruits=(apple banana cherry)
fruits+=(date)
echo "${fruits[0]}"
echo "${fruits[@]}"
echo "${#fruits[@]}"
echo "${fruits[@]:1:2}"
for f in "${fruits[@]}"; do
  echo "- $f"
done
```

| Запис | Значення |
|---|---|
| `arr=(a b c)` | Створити масив |
| `"${arr[0]}"` | Елемент за індексом (від 0) |
| `"${arr[@]}"` | Усі елементи як окремі слова (з лапками) |
| `${#arr[@]}` | Кількість елементів |
| `arr+=(x)` | Додати елемент |
| `"${arr[@]:N}"` | Елементи починаючи з індексу N |

Масив зручно заповнювати виводом команди:

```bash
mapfile -t files < <(ls -1t -- *.txt 2>/dev/null)
echo "Знайдено: ${#files[@]}"
```

`mapfile -t` читає рядки у масив, прибираючи символ нового рядка. **Асоціативні масиви** (ключ → значення) оголошуються `declare -A m; m[name]=value`.

## 10. Коди завершення й обробка помилок

### 10.1. `exit` і коди

```bash
exit 0
exit 1
exit 2
```

| Код | Типове значення |
|---|---|
| `0` | Успіх |
| `1` | Загальна помилка виконання |
| `2` | Неправильне використання (параметри) |
| `126` | Файл знайдено, але не можна виконати (немає `x`) |
| `127` | Команду не знайдено |
| `128 + N` | Завершення сигналом N (`130` — `Ctrl+C`, `143` — `SIGTERM`) |

Скрипт має **повертати правильні коди**: саме за ними його викликають інші скрипти, `cron`, `systemd` (модулі 4, 8, 10).

Повідомлення про помилки виводять у `stderr`: `echo "помилка" >&2`. Так їх можна відокремити від результату.

### 10.2. Пошук і обробка помилок

```bash
cd "$dir" || { echo "Не вдалося перейти до $dir" >&2; exit 1; }
mkdir -p "$out" || exit 1
if ! tar -czf "$archive" "$src"; then
  echo "Помилка архівування" >&2
  exit 1
fi
```

Фігурні дужки `{ ...; }` групують команди (`;` перед `}` обов'язкова).

### 10.3. `set -euo pipefail`

Типова «сувора» початкова конфігурація скрипта:

```bash
set -euo pipefail
```

| Параметр | Дія |
|---|---|
| `-e` | Завершити скрипт, якщо команда повертає ненульовий код |
| `-u` | Вважати помилкою використання незаданої змінної |
| `-o pipefail` | Код конвеєра — код першої команди, що завершилася помилкою, а не лише останньої |

Це допомагає не продовжувати роботу після помилки. Але є винятки, які треба знати:

- `-e` **не діє** всередині умов `if`, у лівих частинах `&&` і `||` та в командах, результат яких перевіряється;
- команда на кшталт `grep` повертає `1` при відсутності збігів, що не завжди помилка: пишіть `grep ... || true` там, де це нормально;
- `(( n++ ))` при нульовому результаті повертає `1` (розділ 4.4);
- `-u` вимагає писати `${var:-}`, якщо змінна може бути порожньою;
- `-e` не замінює явну перевірку критичних операцій.

### 10.4. `trap` і тимчасові файли

`trap` виконує команду під час події: завершення скрипта, сигналу, помилки. Основне застосування — **прибирання**:

```bash
tmp="$(mktemp -d)"
cleanup() {
  rm -rf -- "$tmp"
}
trap cleanup EXIT

echo "робочий каталог: $tmp"
```

| Подія | Коли спрацьовує |
|---|---|
| `EXIT` | Під час завершення скрипта (успішного, з помилкою й за `exit`) |
| `INT` | `Ctrl+C` |
| `TERM` | `SIGTERM` (`kill PID`) |
| `ERR` | Помилка команди (разом із `set -e`) |

`mktemp` створює **унікальний** тимчасовий файл (або каталог із `-d`) із безпечними правами. Не використовуйте передбачувані імена на кшталт `/tmp/data.txt`: інший користувач може підставити посилання (модуль 6).

## 11. Параметри командного рядка: `getopts`

Для скриптів з опціями (`-v`, `-k 3`) використовують вбудовану `getopts`:

```bash
usage() {
  echo "Використання: $0 [-v] [-k N] каталог" >&2
}

verbose=0
keep=3
while getopts ":vk:h" opt; do
  case "$opt" in
    v) verbose=1 ;;
    k) keep="$OPTARG" ;;
    h) usage; exit 0 ;;
    \?) echo "Невідома опція: -$OPTARG" >&2; usage; exit 2 ;;
    :) echo "Опція -$OPTARG потребує значення" >&2; usage; exit 2 ;;
  esac
done
shift $(( OPTIND - 1 ))

[[ $# -eq 1 ]] || { usage; exit 2; }
dir="$1"
```

Рядок `":vk:h"` описує опції: двокрапка після літери означає, що опція має значення (`k:`), початкова двокрапка — власне виведення помилок. `OPTARG` містить значення опції, `OPTIND` — номер наступного аргумента. Після `getopts` виконується `shift`, щоб лишилися лише позиційні аргументи.

## 12. Безпечні практики

### 12.1. Шаблон скрипта

```bash
#!/usr/bin/env bash
# Призначення: коротко, що робить скрипт
# Використання: script.sh [-h] АРГУМЕНТ
set -euo pipefail

usage() {
  echo "Використання: ${0##*/} АРГУМЕНТ" >&2
}

main() {
  [[ $# -eq 1 ]] || { usage; exit 2; }
  local target="$1"
  [[ -d "$target" ]] || { echo "Не каталог: $target" >&2; exit 1; }
  echo "Обробка: $target"
}

main "$@"
```

Така структура: зрозумілий опис, суворий режим, функція `usage`, логіка в `main`, виклик `main "$@"` у кінці.

### 12.2. Основні правила

1. **Завжди беріть змінні в лапки:** `"$var"`, `"$@"`. Без лапок значення з пробілами й символами `*`, `?` ламають команду (модуль 4).
2. **Перевіряйте вхідні дані:** кількість аргументів, існування каталогу, формат числа (`[[ "$n" =~ ^[0-9]+$ ]]`). Не довіряйте введенню користувача.
3. **Захищайте деструктивні команди:** `rm -rf "${dir:?}"/*` зупиниться, якщо `dir` порожня; без цього `rm -rf "$dir"/*` перетворюється на `rm -rf /*`. Використовуйте `--` перед іменами файлів: `rm -- "$file"`.
4. **Використовуйте абсолютні шляхи або явно задавайте `PATH`** у привілейованих скриптах і в `cron`.
5. **Не використовуйте `eval`** з даними, які ви не контролюєте: він виконує рядок як код.
6. **Використовуйте `mktemp`**, а не передбачувані імена.
7. **Не вводьте паролі як аргументи** й не записуйте їх у скрипт: аргументи видно в `ps` (модуль 8), а скрипти зазвичай читають багато користувачів.
8. **Не надавайте права запису на скрипт іншим** (особливо тим, що запускаються від `root` або за розкладом; модуль 6).
9. **Перевіряйте залежності:** `command -v curl > /dev/null || { echo "потрібен curl" >&2; exit 1; }`.
10. **Перевіряйте права:** для скриптів, що потребують `root`, — `[[ $EUID -eq 0 ]] || { echo "Потрібен root" >&2; exit 1; }`.

### 12.3. Приклад: ротація резервних копій

Типове завдання: створити архів з міткою часу та залишити лише `keep` останніх копій.

```bash
backup() {
  local src="$1" dest="$2" keep="$3"
  local base stamp archive
  base="$(basename -- "$src")"
  stamp="$(date +%Y%m%d-%H%M%S)"
  archive="$dest/$base-$stamp.tar.gz"

  tar -czf "$archive" -C "$(dirname -- "$src")" "$base"
  tar -tzf "$archive" > /dev/null

  local -a archives
  mapfile -t archives < <(ls -1t -- "$dest/$base"-*.tar.gz 2>/dev/null)
  if (( ${#archives[@]} > keep )); then
    local old
    for old in "${archives[@]:keep}"; do
      rm -- "$old"
    done
  fi
  echo "$archive"
}
```

Пояснення: створюється архів, його цілісність перевіряється `tar -tzf`, потім усі архіви цього каталогу сортуються за часом (найновіші першими), а зайві (починаючи з індексу `keep`) видаляються. Мітка часу в імені гарантує унікальність і впорядкованість.

## 13. Планування виконання

### 13.1. `cron`

**cron** запускає команди за розкладом. Розклад кожного користувача зберігається в його `crontab`:

```bash
crontab -l
crontab -e
```

Формат рядка:

```text
# хв  год  день  місяць  день-тижня  команда
  30  2    *     *       *           /home/user/bin/backup.sh >> /home/user/backup.log 2>&1
  */5 *    *     *       *           /usr/local/bin/check.sh
  0   9    *     *       1-5         /usr/local/bin/report.sh
```

| Поле | Діапазон |
|---|---|
| Хвилини | 0–59 |
| Години | 0–23 |
| День місяця | 1–31 |
| Місяць | 1–12 |
| День тижня | 0–7 (0 і 7 — неділя) |

`*` означає «будь-яке значення», `*/5` — кожні 5 одиниць, `1-5` — діапазон, `1,3,5` — список.

Особливості `cron`, які часто призводять до помилок:

- середовище **мінімальне**: `PATH` короткий (`/usr/bin:/bin`), змінних із вашого `~/.bashrc` немає. Використовуйте **абсолютні шляхи**;
- поточний каталог — домашній, а не каталог скрипта;
- вивід треба перенаправляти (`>> log 2>&1`), інакше він губиться або надходить поштою;
- скрипт має бути виконуваним (`chmod +x`), із коректним shebang;
- результат перевіряйте за журналом, а не лише за відсутністю помилок.

### 13.2. Таймери `systemd`

Сучасною альтернативою є таймери `systemd` (модуль 10): вони ведуть журнал, мають залежності, умови й повноцінне керування. Скрипт тоді запускається службою `Type=oneshot`, а розклад задає `.timer`. `cron` залишається поширеним, простим і доступним практично всюди; `systemd` кращий для складніших завдань. Для довгих скриптів доцільно також використовувати блокування, щоб дві копії не запускалися одночасно.

## 14. Налагодження та якість

| Засіб | Призначення |
|---|---|
| `bash -n script.sh` | Перевірити синтаксис |
| `bash -x script.sh`, `set -x` | Трасування команд |
| `PS4='+ ${LINENO}: '` | Додати номер рядка в трасування |
| `echo`/`printf` у ключових місцях | Перевірка значень змінних |
| `shellcheck script.sh` | Статичний аналіз (пакет `shellcheck`): знаходить типові помилки з лапками, умовами, змінними |
| `time script.sh` | Виміряти час виконання |

Поради: розробляйте скрипт **малими кроками**, запускайте після кожного змінення, перевіряйте крайні випадки (порожній аргумент, неіснуючий файл, пробіли в іменах, відсутні права). Розумні назви змінних і коментарі «чому», а не «що», роблять скрипт придатним до супроводу. Перед запуском чужого скрипта прочитайте його, особливо якщо він запускається з `sudo`.

## 15. Типові помилки

1. **Змінна без лапок.** Імена з пробілами розбиваються на кілька аргументів.
2. **Пробіли навколо `=` у присвоєнні** (`name = value`) або відсутність пробілів у `[[ ]]`.
3. **Обхід файлів через `for f in $(ls)`.** Використовуйте шаблони `*`.
4. **Перенаправлення в той самий файл, який читається** (`sort file > file`): файл буде знищено ще до читання.
5. **`rm -rf "$dir"/*` без перевірки `dir`.** Порожня змінна означає `rm -rf /*`.
6. **Ігнорування кодів завершення.** Скрипт продовжує роботу після помилки.
7. **Плутанина між `return` і виводом у функціях.** `return` повертає код, а не значення.
8. **Використання `A && B || C` як `if`.** `C` виконається й тоді, коли `B` не вдалася.
9. **Припущення, що `cron` має те саме середовище.** Різні `PATH`, поточний каталог, змінні.
10. **Скрипт без shebang і без права `x`.** Не запускається як програма (`126`, `Permission denied`).
11. **Використання `[ ]` з розширеннями Bash** або запуск `#!/bin/sh` скриптів із `[[ ]]`.
12. **Змінні, змінені в `while`, після конвеєра** (підоболонка).

!!! warning "Навчальне середовище"

    Скрипти виконують команди з вашими правами. Перш ніж запускати скрипт, що створює, змінює чи видаляє файли, перевірте його вміст і виконайте на тестових даних у `~/scripts-practice`. Для скриптів, які щось видаляють, спершу виведіть, що буде видалено (`echo`), а потім замініть на реальну команду.

## 16. Security Note

!!! danger

    Скрипт виконується з правами того, хто його запустив. Помилка в скрипті, який працює від `root` або за розкладом, може знищити дані чи відкрити доступ до системи. Недовірені дані (аргументи, імена файлів, змінні, вміст файлів) можуть перетворити скрипт на засіб атаки.

Правила безпечної роботи:

1. Завжди беріть змінні в подвійні лапки; використовуйте `--`, щоб відокремити опції від імен файлів.
2. Перевіряйте й «очищайте» всі вхідні дані: формат, довжину, дозволені символи.
3. Не використовуйте `eval`, а також не підставляйте недовірені дані в команди як текст.
4. Захищайте деструктивні операції: `${var:?}`, попередній перегляд списку, абсолютні шляхи, тестові каталоги.
5. Використовуйте `mktemp` і `trap` для тимчасових файлів і прибирання; не пишіть у передбачувані імена в `/tmp`.
6. Не зберігайте паролі, токени й ключі в скриптах і аргументах; використовуйте файли з правами `600` або змінні середовища, обмежені в часі життя.
7. Скрипти, що запускаються від `root`, `cron` чи `systemd`, мають належати `root` і не бути доступними для запису іншим (модуль 6); не додавайте до `PATH` каталоги, у які можуть писати звичайні користувачі.
8. Привілейовані скрипти запускайте з явним безпечним `PATH` або абсолютними шляхами.
9. Не запускайте скрипти з невідомих джерел і не виконуйте `curl ... | sudo bash` без перевірки вмісту.
10. Записуйте журнал дій скрипта й коди завершення: це допоможе під час розслідування збоїв.

### Вправа 6. Безпечний скрипт із `trap` і `getopts`

```bash
count="$(find "$dir" -maxdepth 1 -type f | wc -l)"
(( verbose )) && echo "тимчасовий каталог: $tmp"
echo "Файлів у $dir: $count"
EOF
chmod +x safe.sh
./safe.sh
echo "$?"
./safe.sh -v /etc
./safe.sh /nonexistent
echo "$?"
./safe.sh -x /etc
echo "$?"
```

## 21. Ключові висновки

1. Скрипт — текстовий файл із командами; shebang вказує інтерпретатор, а право `x` і `./` потрібні для запуску як програми; `bash -n` і `bash -x` допомагають перевіряти й налагоджувати.
2. Аргументи доступні як `$1`, `$#`, `"$@"`; значення за замовчуванням і захист задають `${var:-x}` та `${var:?msg}`; арифметика цілочислова: `$(( ))`.
3. Умови записують за допомогою `[[ ]]` та `if`/`case`; оператори перевіряють файли, рядки, числа й регулярні вирази.
4. Цикли `for`, `while`, `until`; файли обходять шаблонами, а не `$(ls)`; рядки читають через `while IFS= read -r`.
5. Функції повертають код завершення через `return`, а значення — виводом; змінні всередині роблять локальними через `local`.
6. Масиви зберігають списки; `mapfile` заповнює їх виводом команди; `"${arr[@]}"` обходить елементи без втрати меж.
7. Правильні коди завершення (`0`, `1`, `2`) і повідомлення в `stderr` роблять скрипт придатним для інших скриптів, `cron` і `systemd`.
8. `set -euo pipefail`, `trap` і `mktemp` забезпечують стійкість і прибирання, але мають винятки, які потрібно знати.
9. `cron` запускає скрипти за розкладом у мінімальному середовищі: потрібні абсолютні шляхи й перенаправлення виводу; для складних завдань є таймери `systemd`.
10. Безпека скриптів: лапки навколо змінних, перевірка введення, захист деструктивних команд (`${dir:?}`), `mktemp`, відсутність секретів в аргументах і відсутність `eval` для недовірених даних.
