# Модуль 3. Файлова система Linux

## 1. Навчальні цілі

Після опрацювання модуля студент повинен уміти:

- пояснювати, що таке файлова система, і розрізняти єдине дерево каталогів та тип файлової системи на розділі;
- описувати структуру дерева каталогів з коренем `/`;
- розрізняти абсолютні й відносні шляхи та користуватися `.`, `..`, `~`, `cd -`;
- називати призначення основних каталогів за стандартом FHS;
- визначати тип об'єкта файлової системи за виведенням `ls -l`;
- пояснювати, що таке символічне посилання та як його розпізнати;
- пояснювати поняття «точка монтування» й користуватися `findmnt`, `df` і `lsblk`;
- розрізняти звичайні й віртуальні файлові системи (`/proc`, `/sys`, `/dev`, `/run`);
- безпечно досліджувати файлову систему, не змінюючи системні каталоги й налаштування монтування.

## 2. Вступ

У Linux усе, з чим працює користувач, — програми, налаштування, журнали, документи, дані про процеси й навіть пристрої — доступне через **єдине дерево каталогів**. На відміну від Windows, де кожен диск має власну літеру (`C:`, `D:`), у Linux усі диски, розділи та знімні носії підключаються до одного дерева з коренем `/`.

Розуміння файлової системи потрібне майже для кожного адміністративного завдання: щоб знайти конфігурацію служби, переглянути журнал, зрозуміти, де закінчилося місце, або безпечно вказати шлях у команді. Цей модуль також є основою для наступних тем: файли та каталоги (модуль 5), права доступу (модуль 6), диски й сховища (модуль 13).

Матеріал рекомендується опрацьовувати безпосередньо в навчальній Ubuntu 24.04 VM. Усі команди цього модуля лише читають інформацію й не змінюють системні налаштування, якщо не сказано інше. Приклади виведення є умовними: у вашому середовищі результати можуть відрізнятися.

## 3. Основні поняття

### 3.1. Що таке файлова система

Термін «файлова система» вживається у двох близьких значеннях.

1. **Організація даних на носії.** Це спосіб зберігання файлів і каталогів на розділі диска: `ext4`, `xfs`, `btrfs`, `vfat` тощо. У цьому значенні кажуть, що розділ «відформатований у ext4».
2. **Загальна ієрархія каталогів.** Це єдине дерево каталогів, яке бачить користувач і програми, починаючи з кореня `/`.

Дерево каталогів складається з частин, які можуть належати різним файловим системам. Наприклад, `/` може розташовуватися на одному розділі, `/home` — на іншому, а `/proc` взагалі не зберігається на диску. З'єднання цих частин в одне дерево виконується через **монтування** (розділ 7).

### 3.2. Дерево каталогів і корінь

Вершиною дерева є **кореневий каталог** `/`. Усі інші файли та каталоги є його нащадками:

```text
/
├── etc
│   └── os-release
├── home
│   └── student
│       └── Documents
├── usr
│   └── bin
│       └── ls
└── var
    └── log
```

Важливо розрізняти:

- `/` — кореневий каталог, початок усієї ієрархії;
- `/root` — домашній каталог адміністратора `root`, який лежить у корені як звичайний підкаталог;
- `~` — домашній каталог поточного користувача (наприклад, `/home/student`).

У Linux у кореневого каталогу немає батьківського: `/..` вказує на той самий `/`.

Символ `/` є **роздільником** у шляхах: `/home/student/Documents`.

### 3.3. «Усе є файлом»: типи об'єктів

У Linux з багатьма системними об'єктами працюють так само, як із файлами: їх можна «відкрити», прочитати, у деякі можна записати. Тип об'єкта показує перший символ у виведенні `ls -l`:

```bash
ls -l /etc/os-release
ls -ld /etc
ls -l /dev/null
```

| Символ | Тип | Приклад |
|---|---|---|
| `-` | Звичайний файл | текстовий файл, програма |
| `d` | Каталог | `/etc`, `/home` |
| `l` | Символічне посилання | `/bin` → `usr/bin` |
| `c` | Символьний пристрій | `/dev/null`, `/dev/tty` |
| `b` | Блоковий пристрій | `/dev/sda`, `/dev/nvme0n1` |
| `s` | Сокет | службовий канал між процесами |
| `p` | Іменований канал (FIFO) | канал для обміну даними |

Параметр `-d` у `ls -ld /etc` показує відомості про сам каталог, а не про його вміст. Без нього `ls -l /etc` вивело б список файлів у каталозі.

Визначити тип за змістом файла допомагає команда `file`:

```bash
file /etc/os-release
file /usr/bin/ls
file /etc
```

Розширення імені (`.txt`, `.sh`, `.conf`) у Linux є лише домовленістю для людей і програм, а не обов'язковою ознакою типу.

### 3.4. Імена файлів

Основні правила:

- імена **чутливі до регістру**: `Report.txt`, `report.txt` і `REPORT.TXT` — три різні файли;
- ім'я не може містити `/` (це роздільник) і символ NUL;
- імена, що починаються з крапки (`.bashrc`, `.config`), вважаються **прихованими**, їх показує `ls -a`;
- пробіли та спеціальні символи в іменах допустимі, але ускладнюють роботу в оболонці (розділ 4.5);
- довжина імені одного елемента зазвичай обмежена 255 байтами.

Для навчальних вправ і сценаріїв автоматизації рекомендується використовувати імена з латинських літер, цифр, символів `-` і `_`, без пробілів.

## 4. Шляхи

### 4.1. Абсолютні й відносні шляхи

**Абсолютний шлях** починається з `/` і однозначно вказує розташування об'єкта від кореня незалежно від поточного каталогу:

```text
/etc/os-release
/home/student/Documents
/var/log
```

**Відносний шлях** не починається з `/` і відраховується від **поточного робочого каталогу**:

```text
Documents/notes.txt
../etc
./script.sh
```

Один і той самий відносний шлях в різних каталогах вказує на різні об'єкти. Тому, наприклад, команда `cd usr/share` спрацює з каталогу `/`, але завершиться помилкою з будь-якого каталогу, де немає підкаталогу `usr`.

### 4.2. Спеціальні позначення

| Запис | Значення |
|---|---|
| `/` | Кореневий каталог (на початку шляху) або роздільник |
| `.` | Поточний каталог |
| `..` | Батьківський каталог |
| `~` | Домашній каталог поточного користувача |
| `-` | Попередній каталог (використовується з `cd`) |

Символ `~` розгортає **оболонка** (див. модуль 4) до запуску команди. Це означає, що `~/lab02` перетворюється на `/home/student/lab02` ще до того, як команда його побачить. У лапках `"~/lab02"` розгортання не виконується.

Перехід за допомогою `..` можна комбінувати:

```bash
cd /var/log
cd ..          # /var
cd ../etc      # /etc
cd ../..       # /
```

### 4.3. Навігація: `pwd`, `cd`, `ls`

```bash
pwd
cd /etc
pwd
cd
pwd
cd -
pwd
```

- `pwd` — показує поточний робочий каталог;
- `cd шлях` — змінює поточний каталог;
- `cd` без аргументів — повертає до домашнього каталогу;
- `cd -` — повертає до попереднього каталогу.

Оболонка зберігає поточний і попередній каталоги у змінних:

```bash
echo "$PWD"
echo "$OLDPWD"
```

`cd` є вбудованою командою оболонки, оскільки змінює стан самої оболонки (див. модуль 4).

Для перегляду вмісту каталогу використовують `ls`:

| Команда | Результат |
|---|---|
| `ls` | Короткий список файлів у поточному каталозі |
| `ls -l` | Докладний список: тип, права, власник, розмір, дата, ім'я |
| `ls -a` | Усі елементи, зокрема приховані |
| `ls -la` | Поєднання `-l` і `-a` |
| `ls -lh` | Розміри в зручному для читання вигляді |
| `ls -ld /etc` | Відомості про сам каталог, а не про його вміст |
| `ls /etc` | Вміст указаного каталогу |

### 4.4. Аналіз шляху: `realpath`, `basename`, `dirname`

```bash
realpath .
realpath ../etc
basename /var/log/syslog
dirname /var/log/syslog
```

- `realpath` перетворює шлях на абсолютний, розв'язуючи `.`, `..` і символічні посилання;
- `basename` повертає останній елемент шляху (ім'я);
- `dirname` повертає шлях без останнього елемента (каталог).

Приклад:

```bash
cd /var/log
basename "$PWD"
dirname "$PWD"
```

Ці команди повернуть `log` і `/var`. Змінну `$PWD` слід брати в лапки, щоб значення з пробілами не розділилося на кілька аргументів.

### 4.5. Пробіли та спеціальні символи у шляхах

Якщо ім'я каталогу або файла містить пробіл, оболонка без лапок розділить його на два аргументи:

```bash
dir="$HOME/my reports"
mkdir -p "$dir"
ls -ld "$dir"
ls -ld $dir
```

Остання команда завершиться помилкою, бо оболонка передасть `ls` два окремі аргументи: `/home/student/my` і `reports`. Використовуйте подвійні лапки навколо змінних зі шляхами або екрануйте пробіл: `my\ reports`.

## 5. Стандарт ієрархії файлової системи (FHS)

### 5.1. Призначення

**FHS (Filesystem Hierarchy Standard)** — стандарт, який визначає, які каталоги мають бути в корені Linux-системи й що в них розміщують. Завдяки FHS адміністратор, який працює на іншому дистрибутиві, швидко орієнтується в системі: конфігурація зазвичай у `/etc`, журнали — у `/var/log`, програми — у `/usr`.

Реальні системи можуть відхилятися від стандарту й містити додаткові каталоги, тому FHS слід розглядати як основу для орієнтування, а не як гарантію. Довідку про ієрархію каталогів можна переглянути локально:

```bash
man hier
```

Наявність сторінки залежить від установлених пакетів довідки.

### 5.2. Основні каталоги

| Каталог | Призначення |
|---|---|
| `/` | Корінь усієї ієрархії |
| `/bin` | Основні користувацькі команди (часто посилання на `/usr/bin`) |
| `/sbin` | Основні адміністративні команди (часто посилання на `/usr/sbin`) |
| `/boot` | Файли для завантаження: ядро, початковий образ, файли завантажувача |
| `/dev` | Файли пристроїв (диски, термінали, `null` тощо) |
| `/etc` | Конфігураційні файли системи й служб |
| `/home` | Домашні каталоги звичайних користувачів |
| `/root` | Домашній каталог користувача `root` |
| `/lib`, `/lib64` | Бібліотеки (часто посилання на `/usr/lib`, `/usr/lib64`) |
| `/media` | Автоматично підключені змінні носії (флешки, диски) |
| `/mnt` | Каталог для тимчасового ручного монтування |
| `/opt` | Додаткове програмне забезпечення сторонніх постачальників |
| `/proc` | Віртуальна файлова система з відомостями про процеси й ядро |
| `/run` | Дані, які створюються під час роботи системи (тимчасові, з моменту завантаження) |
| `/srv` | Дані служб, які надає система (наприклад, веб-сервер, FTP) |
| `/sys` | Віртуальна файлова система з відомостями про пристрої й драйвери |
| `/tmp` | Тимчасові файли |
| `/usr` | Програми, бібліотеки, документація, спільні дані |
| `/var` | Змінні дані: журнали, кеші, черги, бази даних служб |

У сучасних Ubuntu в корені також можуть бути додаткові елементи, наприклад `lost+found` (фрагменти файлів, відновлені після збою в ext4), `snap`, `cdrom`, `swap.img`.

### 5.3. Каталоги `/usr` і `/var`

**`/usr`** містить основну частину встановленого програмного забезпечення:

| Підкаталог | Призначення |
|---|---|
| `/usr/bin` | Виконувані файли програм для користувачів |
| `/usr/sbin` | Виконувані файли адміністративних програм |
| `/usr/lib` | Бібліотеки та допоміжні файли програм |
| `/usr/share` | Незалежні від архітектури дані: документація, значки, шаблони |
| `/usr/local` | Програми й дані, які адміністратор установив локально, поза системою пакетів |

**`/var`** містить дані, які змінюються під час роботи:

| Підкаталог | Призначення |
|---|---|
| `/var/log` | Журнали системи та служб |
| `/var/lib` | Стан програм і служб (бази даних пакетів тощо) |
| `/var/cache` | Кеші програм |
| `/var/spool` | Черги (друк, пошта) |
| `/var/tmp` | Тимчасові файли, які мають зберігатися між перезавантаженнями |

`/tmp` і `/var/tmp` відрізняються часом життя даних: вміст `/tmp` не призначений для довготривалого зберігання й може очищуватися під час завантаження чи за політикою системи.

### 5.4. Об'єднання `/bin`, `/sbin`, `/lib` із `/usr`

Історично `/bin`, `/sbin` і `/lib` були окремими каталогами в корені. У сучасних дистрибутивах, зокрема в Ubuntu 24.04, вони є **символічними посиланнями** на відповідні каталоги в `/usr`:

```bash
ls -ld /bin /sbin /lib
readlink -f /bin
```

Приклад виведення (умовний):

```text
lrwxrwxrwx 1 root root 7 Apr 22  2024 /bin -> usr/bin
lrwxrwxrwx 1 root root 8 Apr 22  2024 /sbin -> usr/sbin
lrwxrwxrwx 1 root root 7 Apr 22  2024 /lib -> usr/lib
```

Тому команда `ls` фізично розташована в `/usr/bin/ls`, а шлях `/bin/ls` веде до того самого файла.

### 5.5. Де це шукати? Типові запитання

| Що шукаємо | Де зазвичай шукати |
|---|---|
| Конфігурацію системи чи служби | `/etc` |
| Журнали системи й служб | `/var/log` |
| Файли користувача | `/home/<користувач>` |
| Виконуваний файл команди | `/usr/bin`, `/usr/sbin`, `/usr/local/bin` |
| Ядро та файли завантаження | `/boot` |
| Відомості про процеси та ядро | `/proc` |
| Відомості про пристрої | `/sys`, `/dev` |
| Тимчасові файли | `/tmp`, `/var/tmp` |
| ПЗ сторонніх постачальників | `/opt` |
| Дані для веб-сервера або FTP | `/srv`, `/var/www` (залежить від конфігурації) |

Знайти фактичне розташування команди допомагає:

```bash
command -v ls
type ls
```

Оболонка шукає виконувані команди в каталогах, перелічених у змінній `PATH` (див. модуль 4).

## 6. Символічні посилання

**Символічне посилання (symlink)** — спеціальний файл, який містить шлях до іншого об'єкта. Він схожий на ярлик у Windows, але працює на рівні файлової системи.

У виведенні `ls -l` символічне посилання має тип `l` і показує ціль після стрілки `->`:

```bash
ls -l /etc/os-release
readlink /etc/os-release
readlink -f /etc/os-release
```

Приклад виведення:

```text
lrwxrwxrwx 1 root root 21 Apr 22  2024 /etc/os-release -> ../usr/lib/os-release
```

- `readlink` показує, на що вказує посилання;
- `readlink -f` та `realpath` розв'язують весь ланцюжок до кінцевого об'єкта.

Особливості:

- ціль посилання може бути каталогом, звичайним файлом або іншим посиланням;
- якщо ціль видалено або перейменовано, посилання залишається, але стає **«битим»** (broken) і не веде нікуди;
- відносна ціль (`../usr/lib/os-release`) відраховується від каталогу, у якому лежить посилання, а не від поточного каталогу.

Окрім символічних існують **жорсткі посилання** (hard links): кілька імен для одного й того самого вмісту файла. Їх створення та відмінності докладно розглядаються в модулі 5.

## 7. Точки монтування

### 7.1. Ідея монтування

**Монтування** — це підключення файлової системи (розділу, диска, образу, віртуальної файлової системи) до певного каталогу дерева. Цей каталог називається **точкою монтування**. Після монтування вміст підключеної файлової системи доступний як звичайний вміст цього каталогу.

Наприклад:

```text
/dev/sda2   →  /            (коренева файлова система)
/dev/sda1   →  /boot/efi    (системний розділ завантаження)
/dev/sdb1   →  /home        (окремий розділ для користувачів, якщо його створено)
```

Користувач, який виконує `ls /home`, не бачить різниці між каталогом на кореневому розділі та каталогом на окремому диску: дерево каталогів «приховує» фізичну організацію носіїв. Саме тому в Linux немає літер дисків.

Межі між файловими системами можна побачити за допомогою команд, розглянутих нижче.

### 7.2. Пристрої та розділи

Диски й розділи в Linux подаються **блоковими пристроями** у `/dev`. Назви залежать від типу контролера:

| Назва | Тип |
|---|---|
| `/dev/sda`, `/dev/sdb` | Диски SATA, SCSI, USB; у VirtualBox зазвичай `sda` |
| `/dev/sda1`, `/dev/sda2` | Розділи диска `sda` |
| `/dev/vda` | Віртуальний диск `virtio` |
| `/dev/nvme0n1`, `/dev/nvme0n1p1` | NVMe-диск і його розділ |
| `/dev/mapper/...` | Логічні томи (LVM), шифровані й інші відображені пристрої |
| `/dev/loop0` | Петльові пристрої (образи файлів; у Ubuntu використовуються, зокрема, для snap-пакетів) |

Переглянути блокові пристрої, їхню ієрархію й точки монтування:

```bash
lsblk
lsblk -f
```

Приклад виведення `lsblk` (умовний):

```text
NAME   MAJ:MIN RM  SIZE RO TYPE MOUNTPOINTS
sda      8:0    0   25G  0 disk
├─sda1   8:1    0  512M  0 part /boot/efi
└─sda2   8:2    0 24,5G  0 part /
sr0     11:0    1 1024M  0 rom
```

Параметр `-f` додатково показує тип файлової системи, мітку та UUID.

### 7.3. Перегляд змонтованих файлових систем

**`findmnt`** — зручна команда для перегляду точок монтування:

```bash
findmnt
findmnt /
findmnt -T ~
findmnt /proc
```

- `findmnt` без аргументів показує всі точки монтування у вигляді дерева;
- `findmnt /` показує файлову систему, змонтовану в `/`;
- `findmnt -T шлях` показує файлову систему, якій належить указаний файл або каталог (`-T` — «target»).

Приклад виведення `findmnt /`:

```text
TARGET SOURCE    FSTYPE OPTIONS
/      /dev/sda2 ext4   rw,relatime
```

Поля:

| Поле | Значення |
|---|---|
| `TARGET` | Точка монтування |
| `SOURCE` | Джерело: пристрій, образ або службова назва |
| `FSTYPE` | Тип файлової системи |
| `OPTIONS` | Параметри монтування (`rw`, `ro`, `noexec`, `nosuid` тощо) |

Щоб відфільтрувати службові (віртуальні) файлові системи, можна скористатися параметром `--real` (доступний у сучасних версіях `findmnt`):

```bash
findmnt --real
```

**`df -hT`** показує використання місця для кожної змонтованої файлової системи разом із її типом:

```bash
df -hT
df -hT /
df -h ~
```

Приклад виведення:

```text
Filesystem     Type   Size  Used Avail Use% Mounted on
tmpfs          tmpfs  394M  1,6M  392M   1% /run
/dev/sda2      ext4    24G  9,5G   13G  43% /
/dev/sda1      vfat   511M  6,1M  505M   2% /boot/efi
```

Команду `mount` без параметрів також можна використовувати для перегляду, але її виведення довге й менш зручне. Не виконуйте `mount` з аргументами та `umount` без чіткого розуміння наслідків: вони змінюють стан системи.

### 7.4. Перекриття каталогу

Якщо змонтувати файлову систему в **непорожній** каталог, його попередній вміст стає недоступним, поки файлову систему не буде відмонтовано. Дані при цьому не видаляються: вони лишаються на початковому носії, але «перекриті» новою файловою системою.

Це пояснює типовий випадок: файли, записані в `/home` до підключення окремого розділу, після монтування «зникають». Після `umount` вони знову стають видимими.

### 7.5. Файл `/etc/fstab`

Постійне монтування під час завантаження налаштовується у файлі `/etc/fstab`. Його можна безпечно переглядати:

```bash
cat /etc/fstab
```

Приклад рядка:

```text
UUID=1a2b3c4d-1111-2222-3333-444455556666  /  ext4  defaults  0  1
```

Поля: пристрій (часто за `UUID`), точка монтування, тип файлової системи, параметри, прапорець `dump`, порядок перевірки `fsck`.

**Не редагуйте `/etc/fstab` під час цього модуля.** Помилка в цьому файлі може призвести до того, що система не завантажиться.

### 7.6. Змінні носії

Знімні носії (USB-накопичувачі, диски) у графічному середовищі зазвичай монтуються автоматично в `/media/<користувач>/<мітка>`. Каталог `/mnt` традиційно використовують для тимчасового ручного монтування адміністратором.

Докладно створення розділів, форматування, монтування та відмонтування розглядаються в модулі 13.

## 8. Віртуальні та тимчасові файлові системи

Не всі «файли» зберігаються на диску. Ядро надає кілька **віртуальних файлових систем**, вміст яких формується під час читання:

| Каталог | Тип | Призначення |
|---|---|---|
| `/proc` | `proc` | Відомості про процеси й стан ядра |
| `/sys` | `sysfs` | Відомості про пристрої, драйвери й параметри ядра |
| `/dev` | `devtmpfs` | Файли пристроїв |
| `/run` | `tmpfs` | Службові дані поточного сеансу; зберігаються в оперативній пам'яті |

Приклади читання:

```bash
cat /proc/version
head -n 3 /proc/meminfo
ls /proc | head -n 10
ls /sys/class | head -n 5
ls /dev | head -n 10
```

`tmpfs` зберігає дані в оперативній пам'яті; після перезавантаження вони зникають. Тому каталог `/run` не підходить для довготривалого зберігання.

У каталозі `/proc` чимало записів мають числові імена: це PID запущених процесів. Докладно їх вивчатимуть у модулі 8.

## 9. Типи файлових систем

| Тип | Типове призначення |
|---|---|
| `ext4` | Стандартна журнальована файлова система для розділів Linux |
| `xfs` | Журнальована файлова система, поширена на серверах |
| `btrfs` | Файлова система зі знімками й перевіркою цілісності даних |
| `vfat` | FAT32, зокрема системний розділ завантаження UEFI та флеш-накопичувачі |
| `ntfs` | Файлова система Windows (доступ через додаткові драйвери) |
| `tmpfs` | Тимчасова файлова система в оперативній пам'яті |
| `squashfs` | Стиснений образ тільки для читання; використовується snap-пакетами |
| `overlay` | Шарувата файлова система, використовується контейнерами |

Для Ubuntu за замовчуванням тип кореневої файлової системи зазвичай `ext4`.

У Ubuntu із встановленими snap-пакетами виведення `df`, `lsblk` і `findmnt` може містити багато рядків із `squashfs` і `/dev/loopN`. Для аналізу диска їх можна відфільтрувати:

```bash
df -hT -x tmpfs -x squashfs -x devtmpfs
```

## 11. Типові помилки

1. **Плутанина між `/`, `/root` і `~`.** `/` — корінь системи, `/root` — домашній каталог адміністратора, `~` — домашній каталог поточного користувача.
2. **Змішування абсолютних і відносних шляхів.** Відносний шлях залежить від поточного каталогу; перед використанням перевіряйте `pwd`.
3. **Пропущені лапки навколо змінних зі шляхами.** Шлях із пробілом буде розділено на кілька аргументів.
4. **Припущення, що регістр не має значення.** `Notes.txt` і `notes.txt` — різні файли.
5. **Пошук виконуваних файлів лише в `/bin`.** У сучасних системах `/bin` — посилання на `/usr/bin`; фактичне розташування показує `command -v` і `realpath`.
6. **Вважати, що вміст `/proc`, `/sys` або `/run` зберігається на диску.** Це віртуальні або тимчасові файлові системи.
7. **Зберігання важливих даних у `/tmp`.** Вміст `/tmp` може бути очищено автоматично.
8. **Висновок «файли зникли» після монтування.** Можливо, їх лише перекрито змонтованою файловою системою.
9. **Ігнорування «битих» посилань.** Помилка «No such file or directory» для посилання може означати, що його ціль відсутня.
10. **Вважати, що `df` і `du` показують те саме.** `df` показує заповнення файлової системи, `du` — розмір вказаних каталогів і файлів.

!!! warning "Навчальне середовище"

    Команди, які змінюють системну конфігурацію, виконуйте лише в лабораторній VM або іншому спеціально підготовленому середовищі. У цьому модулі не потрібно змінювати системні каталоги, монтувати чи відмонтовувати файлові системи й редагувати `/etc/fstab`.

## 12. Security Note

!!! danger

    Помилки під час роботи з файловою системою можуть призвести до втрати даних або неможливості завантаження системи. Права `root` надають повний контроль над системою: дотримуйтеся принципу найменших привілеїв.

Правила безпечної роботи:

1. Перед будь-якою командою, що змінює файли, перевіряйте поточний каталог (`pwd`) і цільові шляхи.
2. Не видаляйте й не змінюйте файли в `/etc`, `/boot`, `/usr`, `/var/lib` без чіткого розуміння наслідків.
3. Ніколи не виконуйте команд видалення з коренем `/` як шляхом або з нерозгорнутими змінними, що можуть бути порожніми.
4. Не редагуйте `/etc/fstab` і не виконуйте `mount`, `umount`, а також форматування дисків поза спеціально підготовленим середовищем.
5. Не змонтовуйте невідомі носії й образи з неперевірених джерел; параметри монтування `ro`, `noexec`, `nosuid` обмежують можливі ризики.
6. Будьте уважні з символічними посиланнями: посилання може вказувати на інше місце, ніж здається, а команда, що змінює файли, зачепить ціль.
7. Не зберігайте паролі, ключі й інші секрети в `/tmp` та інших каталогах, доступних іншим користувачам.
8. Не використовуйте `sudo`, якщо достатньо прав звичайного користувача.
9. Тренуйтеся на тестових даних у домашньому каталозі.

## 13. Практичні вправи

### Вправа 1. Корінь і FHS

Виконайте:

```bash
ls /
ls -l /
ls -ld /bin /sbin /lib /usr /etc /home /root /tmp
readlink -f /bin
command -v ls
```

Завдання:

1. Визначте, які елементи кореня є символічними посиланнями.
2. Поясніть, чому `/bin/ls` і `/usr/bin/ls` можуть бути одним файлом.
3. Назвіть призначення каталогів `/etc`, `/var`, `/usr`, `/home`, `/root`, `/tmp`.
4. З'ясуйте, чому команда `ls /root` для звичайного користувача завершується помилкою доступу.

### Вправа 2. Шляхи

Перед виконанням запишіть, у якому каталозі ви опинитеся після кожної команди, а потім перевірте результат:

```bash
cd /usr/local/bin
cd ../../share
pwd
cd ~
pwd
cd -
pwd
cd /var/log
cd ../../etc
pwd
```

Завдання:

1. Порівняйте передбачення з реальним результатом.
2. Визначте, які шляхи абсолютні, а які відносні.
3. Виконайте `realpath ../log` із каталогу `/etc` і поясніть результат.

### Вправа 3. Типи об'єктів

```bash
ls -ld /etc /etc/os-release /dev/null /dev
file /etc/os-release
file /usr/bin/ls
readlink -f /etc/os-release
```

Завдання:

1. Визначте тип кожного об'єкта за першим символом `ls -l`.
2. Знайдіть, на який файл вказує `/etc/os-release`.
3. Поясніть, чим символьний пристрій `/dev/null` відрізняється від звичайного файла.

### Вправа 4. Точки монтування

```bash
findmnt /
findmnt -T ~
df -hT /
df -hT ~
lsblk -f
```

Завдання:

1. Визначте пристрій, тип файлової системи й параметри, з якими змонтовано `/`.
2. Визначте, чи розташований ваш домашній каталог на тому самому розділі, що й `/`.
3. Знайдіть у виведенні `lsblk` пристрій, на якому розміщено кореневу файлову систему.
4. Поясніть, як знайти в `df` рядок, що описує файлову систему, у якій розташований `~`.

### Вправа 5. Віртуальні файлові системи

```bash
findmnt /proc
findmnt /sys
findmnt /run
cat /proc/version
head -n 3 /proc/meminfo
ls /dev | head -n 10
```

Завдання:

1. Запишіть тип кожної віртуальної файлової системи.
2. Поясніть, звідки береться вміст `/proc/meminfo`, якщо файли на диску не зберігаються.
3. Поясніть, чому `/run` не підходить для довготривалого зберігання.

### Вправа 6. Де це лежить?

Використовуйте FHS і команди з модуля та визначте, у яких каталогах за стандартом слід шукати:

1. конфігурацію системної служби;
2. журнал помилок служби;
3. виконуваний файл команди `bash`;
4. домашній каталог користувача `student`;
5. файл ядра Linux;
6. тимчасовий файл програми, який може зникнути після перезавантаження;
7. програму сторонньої компанії, установлену вручну.

Перевірте щонайменше три відповіді командами `ls`, `command -v` або `findmnt`.

Студент повинен уміти пояснювати структуру кореневого каталогу за FHS, користуватися абсолютними й відносними шляхами, визначати точки монтування й типи файлових систем, розрізняти віртуальні та звичайні файлові системи.

Рекомендовані команди для повторення:

```bash
pwd
cd
ls -l
ls -ld
realpath
basename
dirname
readlink -f
file
command -v
findmnt
df -hT
lsblk -f
man hier
```

Основні поняття:

```text
/        ~        .        ..
FHS      /etc     /var     /usr
symlink  mount point        /proc
```

Виконайте вправи 1–6 у власній навчальній VM, переконайтеся, що розумієте результат кожної команди, і перегляньте матеріали модуля 4 (змінні, лапки, шаблони, перенаправлення, конвеєри).

## 16. Додаткові матеріали

1. [Filesystem Hierarchy Standard](https://refspecs.linuxfoundation.org/FHS_3.0/fhs/index.html) — стандарт ієрархії файлової системи.
2. [hier(7)](https://man7.org/linux/man-pages/man7/hier.7.html) — опис ієрархії каталогів Linux.
3. [GNU Coreutils Manual](https://www.gnu.org/software/coreutils/manual/coreutils.html) — документація до `ls`, `readlink`, `realpath`, `basename`, `dirname`.
4. [Linux man-pages](https://www.kernel.org/doc/man-pages/) — довідкова документація Linux.
5. [Ubuntu Documentation](https://documentation.ubuntu.com/) — офіційна документація Ubuntu.

Для локального ознайомлення можна використати:

```bash
man hier
man findmnt
man lsblk
man df
man ls
```

Наявність окремих сторінок довідки залежить від установлених пакетів документації. Посилання на зовнішні ресурси варто перевіряти на актуальність.

## 17. Ключові висновки

1. У Linux усі файли доступні в єдиному дереві з коренем `/`; диски й розділи підключаються до цього дерева через монтування.
2. Абсолютний шлях починається з `/`, відносний відраховується від поточного каталогу; `.`, `..`, `~` і `cd -` спрощують навігацію.
3. Імена файлів чутливі до регістру; шляхи зі спеціальними символами слід брати в лапки.
4. FHS визначає призначення основних каталогів: `/etc` — конфігурація, `/var/log` — журнали, `/home` — дані користувачів, `/usr` — програми.
5. У сучасних дистрибутивах `/bin`, `/sbin` і `/lib` — символічні посилання на каталоги в `/usr`.
6. Перший символ у виведенні `ls -l` показує тип об'єкта: `-`, `d`, `l`, `c`, `b` тощо.
7. Точка монтування — каталог, у якому доступна підключена файлова система; монтування може перекрити попередній вміст каталогу.
8. `findmnt`, `df -hT` і `lsblk` показують точки монтування, типи файлових систем і блокові пристрої без зміни системи.
9. `/proc`, `/sys`, `/dev` і `/run` — віртуальні або тимчасові файлові системи, дані в яких не зберігаються як звичайні файли на диску.
10. Безпечна робота з файловою системою вимагає перевірки шляхів і прав, обережності з `root`, `/etc/fstab` та командами монтування.
