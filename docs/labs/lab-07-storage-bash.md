# Лабораторна робота № 7. Сховище та Bash

## Тема

**Робота з дисками, файловими системами та Bash-скриптами. Безпечне підключення сховища на loop-пристрої, налаштування монтування, swap, діагностика місця; створення скриптів з параметрами, умовами, циклами, функціями й обробкою помилок; автоматизація резервного копіювання.**

## Пов'язані модулі

- Модуль 13. Диски та файлові системи.
- Модуль 14. Bash-скриптинг.

## Мета

Закріпити теоретичні знання про сховище Linux і Bash-скриптинг, сформувати практичні навички підключення й обслуговування файлових систем та написання надійних скриптів, а також навчитися поєднувати ці навички для автоматизації (контроль місця, резервне копіювання з ротацією).

Під час виконання лабораторної роботи студент повинен:

- досліджувати диски, розділи, файлові системи, `UUID` і заповнення за допомогою `lsblk`, `blkid`, `df`, `findmnt`;
- створювати образ диска, підключати його як loop-пристрій, розмічати за допомогою `parted` і створювати файлові системи;
- монтувати й відмонтовувати файлові системи, налаштовувати власника, права та параметри монтування;
- діагностувати `target is busy`, виконувати перевірку `fsck`, переглядати параметри `ext4`;
- перевіряти `fstab` без ризику для системи й працювати зі swap-файлом;
- писати скрипти із shebang, параметрами, умовами, циклами, функціями, `case`, масивами;
- повертати правильні коди завершення та використовувати `set -euo pipefail`, `trap`, `mktemp`;
- створити скрипт резервного копіювання з перевірками та ротацією й протестувати його;
- повністю відновити початковий стан системи.

## Вимоги

Для виконання лабораторної роботи необхідно мати:

- навчальну віртуальну машину з Ubuntu 24.04 LTS;
- обліковий запис із правом на `sudo` (член групи `sudo`);
- не менше 1 ГБ вільного місця на кореневій файловій системі;
- доступ до навчальних матеріалів модулів 13 і 14;
- результати лабораторних робіт № 1–6 для довідки.

**Рекомендація:** створіть **знімок VM** перед початком роботи (модуль 2).

Допускається використання іншого дистрибутива Linux. Імена пристроїв, склад пакетів та конфігурація swap залежать від середовища; такі відмінності необхідно зафіксувати у звіті.

**Важливо:** усі операції з розмітки, форматування й монтування виконуються **виключно на навчальному образі** `~/lab07/disk.img`, підключеному як loop-пристрій. **Заборонено** застосовувати `parted`, `mkfs`, `dd`, `wipefs` і подібні команди до реальних дисків VM (`/dev/sda`, `/dev/nvme0n1`, `/dev/vda`). Не змінюйте реальний `/etc/fstab`. `sudo` використовується лише для операцій зі сховищем із цього завдання.

## Правила виконання роботи

1. Уважно прочитайте умову кожного завдання.
2. Виконуйте команди послідовно й **в одному терміналі**: змінна `LOOP` існує лише в ньому. Якщо ви закрили термінал, відновіть її командою `LOOP="$(losetup -j ~/lab07/disk.img | cut -d: -f1)"`.
3. **Перед кожною руйнівною командою** (`parted`, `mkfs`) виконайте перевірку пристрою (див. завдання 2) і переконайтеся, що змінна `LOOP` вказує на `/dev/loopN`, а не на реальний диск.
4. Спочатку передбачте результат команди, потім виконайте її та порівняйте.
5. Записуйте результати та повідомлення про помилки у звіт.
6. Скрипти пишіть у каталозі `~/lab07/scripts` і запускайте на тестових даних.
7. Деякі помилки в цій роботі є навмисними: фіксуйте повідомлення та пояснюйте їх.
8. Обов'язково виконайте прибирання (завдання 12).

Усі приклади виведення команд у цій роботі є умовними. Результати у вашому середовищі можуть відрізнятися.

## Завдання 2. Образ диска, loop-пристрій і розмітка

**Теорія:** модуль 13, розділи 6.2 і 6.3.

### Мета

Навчитися безпечно створювати «диск» для експериментів і розмічати його.

### Порядок виконання

**Крок 1. Створіть образ і підключіть його.**

```bash
cd ~/lab07
truncate -s 200M disk.img
ls -lh disk.img
```

**Крок 2. Виконайте обов'язкову перевірку пристрою.**

```bash
[[ "$LOOP" == /dev/loop* ]] && echo "OK: $LOOP" || echo "СТОП: $LOOP не є loop-пристроєм"
losetup -j ~/lab07/disk.img
lsblk "$LOOP"
```

Якщо виведено `СТОП`, **не виконуйте жодних наступних команд**, а зверніться до викладача.

**Крок 3. Розмітьте образ.**

```bash
sudo parted -s "$LOOP" mklabel gpt mkpart data ext4 1MiB 120MiB mkpart fat fat32 120MiB 100%
sudo parted -s "$LOOP" print
lsblk "$LOOP"
```

Якщо розділи `loopNp1` і `loopNp2` не з'явилися, виконайте `sudo partprobe "$LOOP"` і повторіть `lsblk`.

## Завдання 5. Відмонтування, перевірка та обслуговування

**Теорія:** модуль 13, розділи 6.5 і 10; модуль 8.

### Мета

Навчитися діагностувати `target is busy`, перевіряти файлову систему й підтверджувати збереження даних.

### Порядок виконання

**Крок 1. Запишіть контрольні дані.**

```bash
cd ~/lab07
printf 'lab07 data\n' > /mnt/lab07/data/keep.txt
sha256sum /mnt/lab07/data/keep.txt | tee ~/lab07/keep.sha
```

**Крок 2. Спровокуйте `target is busy`.**

```bash
cd /mnt/lab07/data
sleep 300 &
SLEEP_PID=$!
cd ~/lab07
sudo umount /mnt/lab07/data
echo "$?"
ls -l /proc/$SLEEP_PID/cwd
fuser -vm /mnt/lab07/data
```

Команда `fuser` може бути недоступною: зазначте це у звіті.

**Крок 3. Усуньте причину й відмонтуйте.**

```bash
kill "$SLEEP_PID"
sleep 1
sudo umount /mnt/lab07/data
findmnt /mnt/lab07/data
echo "$?"
```

**Крок 4. Перевірте й дослідіть файлову систему.**

```bash
sudo e2fsck -f "${LOOP}p1"
sudo tune2fs -l "${LOOP}p1" | head -n 15
sudo tune2fs -l "${LOOP}p1" | grep -i 'block count'
sudo tune2fs -l "${LOOP}p1" | grep -i 'inode count'
```

**Крок 5. Змонтуйте знову й перевірте дані.**

```bash
sudo mount "${LOOP}p1" /mnt/lab07/data
sha256sum -c ~/lab07/keep.sha
df -i /mnt/lab07/data
ls -la /mnt/lab07/data
```

```bash
tar -tzf "$(ls -1t /mnt/lab07/data/backups/project-*.tar.gz | head -n 1)" | head -n 10
./diskcheck.sh /mnt/lab07/data 90
ls -d /tmp/tmp.* 2>/dev/null | wc -l
```

**Крок 5. Перевірте стійкість.**


Остання перевірка демонструє поведінку скрипта, коли призначення недоступне для запису. Опишіть, що саме сталося, який код повернув скрипт, і чи прибрано тимчасовий каталог.
