# Лабораторна робота № 4. Користувачі та процеси

## Тема

**Керування користувачами й групами та процесами в Linux. Створення облікових записів і груп, спільний доступ до каталогу, використання `sudo`; перегляд, моніторинг і керування процесами.**

## Пов'язані модулі

- Модуль 7. Користувачі та групи.
- Модуль 8. Процеси.

## Мета

Закріпити теоретичні знання про облікові записи, групи, `sudo`, процеси та сигнали, сформувати практичні навички адміністрування користувачів і керування процесами та навчитися пов'язувати права користувачів із можливостями керування файлами й процесами.

Під час виконання лабораторної роботи студент повинен:

- досліджувати облікові записи за допомогою `id`, `getent`, `/etc/passwd`, `/etc/group`;
- створювати тестових користувачів і групи та керувати членством у групах;
- налаштовувати спільний каталог із `setgid` та перевіряти доступ від імені різних користувачів;
- керувати паролями, блокуванням, оболонкою входу й термінами дії облікових записів;
- пояснювати поведінку `sudo`, `su` та перенаправлення під `sudo`;
- переглядати й інтерпретувати процеси, стани, навантаження;
- керувати фоновими завданнями оболонки та надсилати сигнали процесам;
- змінювати пріоритет процесів;
- виконувати діагностику сценарію з кількома проблемними процесами;
- повністю відновити початковий стан системи після виконання роботи.

## Вимоги

Для виконання лабораторної роботи необхідно мати:

- навчальну віртуальну машину з Ubuntu 24.04 LTS;
- обліковий запис, що має право на `sudo` (член групи `sudo`);
- доступ до командного рядка;
- доступ до навчальних матеріалів модулів 7 і 8;
- результати лабораторних робіт № 1–3 для довідки.

**Рекомендація:** створіть **знімок VM** перед початком роботи (модуль 2), щоб за потреби швидко повернути систему до початкового стану.

Допускається використання іншого дистрибутива Linux. Параметри `useradd`, назви груп і права домашніх каталогів можуть відрізнятися; такі відмінності необхідно зафіксувати у звіті.

**Важливо:** у цій роботі на відміну від попередніх **використовується `sudo`**. Усі зміни системи виконуються лише у навчальній VM. Створюються лише тестові облікові записи `labuser1` і `labuser2`, групи `labteam` і `labaudit` та каталог `/srv/lab04share`. Після завершення необхідно виконати обов'язкове прибирання (завдання 12).

## Правила виконання роботи

1. Уважно прочитайте умову кожного завдання.
2. Виконуйте команди послідовно, у порядку наведення: наступні завдання використовують результати попередніх.
3. Перед кожною командою з `sudo` переконайтеся, що розумієте, що вона змінює.
4. Спочатку передбачте результат команди, потім виконайте її та порівняйте.
5. Записуйте результати та повідомлення про помилки у звіт.
6. Не змінюйте облікові записи, групи та файли, які не створені в цій роботі.
7. Усі фонові процеси завершуйте за інструкціями: наприкінці роботи не повинно залишитися процесів `sleep` і `yes`.
8. Деякі помилки в цій роботі є навмисними: вони демонструють правила Linux. Фіксуйте повідомлення та пояснюйте їх.

Усі приклади виведення команд у цій роботі є умовними. Результати у вашому середовищі можуть відрізнятися.

## Початкова підготовка

### 1. Перевірте право на `sudo`

```bash
whoami
id
sudo -l
```

Команда `sudo -l` запитає ваш пароль і покаже, що вам дозволено. Якщо права на `sudo` немає, виконати роботу неможливо: зверніться до викладача.

### 2. Зафіксуйте початковий стан

Ці значення знадобляться під час перевірки прибирання.

```bash
id
getent passwd | wc -l
getent group | wc -l
ls /srv
pgrep -c sleep
pgrep -c yes
```

Запишіть у звіт результати.

### 3. Створіть знімок VM

Створіть знімок у засобах віртуалізації (VirtualBox) і назвіть його, наприклад, `before-lab04`.

- Чи входить ваш обліковий запис до групи `sudo`?

## Завдання 3. Членство в групах

**Теорія:** модуль 7, розділ 7.

### Мета

Навчитися керувати членством у групах і розуміти різницю між `usermod -aG` та `usermod -G`, а також момент набуття чинності змін.

### Порядок виконання

**Крок 1. Додайте `labuser1` до групи `labteam`.**

```bash
sudo usermod -aG labteam labuser1
id labuser1
getent group labteam
```

**Крок 2. Порівняйте `-aG` і `-G` на `labuser2`.**

```bash
sudo usermod -aG labteam,labaudit labuser2
id labuser2
sudo usermod -G labaudit labuser2
id labuser2
sudo gpasswd -d labuser2 labaudit
id labuser2
```

Порівняйте переліки груп `labuser2` після другої та третьої команд `id`.

**Крок 3. Перевірте, коли групи набувають чинності для поточного сеансу.**

**Увага:** для власного облікового запису використовуйте тільки `-aG`. Команда `usermod -G` без `-a` позбавила б вас групи `sudo`.

```bash
sudo usermod -aG labteam "$USER"
id
id "$USER"
groups
sudo gpasswd -d "$USER" labteam
id "$USER"
```

### Результати

Заповніть таблицю.

| № | Дія | Результат `id` або `getent` |
|---|---|---|
| 1 | `usermod -aG labteam labuser1` | |
| 2 | `usermod -aG labteam,labaudit labuser2` | |
| 3 | `usermod -G labaudit labuser2` | |
| 4 | `gpasswd -d labuser2 labaudit` | |
| 5 | `id` після додавання себе до `labteam` | |
| 6 | `id "$USER"` після додавання себе до `labteam` | |
| 7 | `id "$USER"` після видалення себе з `labteam` | |

Запишіть склад групи `labteam` за `getent group labteam` на початку й наприкінці завдання.

**Очікуваний кінцевий стан:** `labuser1` — у `labteam`; `labuser2` — без додаткових груп; ваш обліковий запис — не в `labteam`.

### Запитання для аналізу

1. Чим `usermod -aG` відрізняється від `usermod -G`?
2. Чому використання `-G` без `-a` на власному обліковому записі небезпечне?
3. Чому `id` без аргументів і `id "$USER"` показали різні переліки груп?

## Завдання 4. Спільний каталог і права

**Теорія:** модуль 7, розділ 7.2; модуль 6, розділи 3.4 і 8.

### Мета

Налаштувати спільний каталог для групи та перевірити доступ від імені різних користувачів, поєднавши права доступу, групи й біт `setgid`.

### Порядок виконання

**Крок 1. Створіть каталог і налаштуйте права.**

```bash
sudo mkdir /srv/lab04share
sudo chown root:labteam /srv/lab04share
sudo chmod 2770 /srv/lab04share
ls -ld /srv/lab04share
namei -l /srv/lab04share
```

**Крок 2. Перевірте доступ від свого імені.**

```bash
ls /srv/lab04share
echo "$?"
```

Ви не є членом `labteam`: команда має завершитися помилкою.

**Крок 3. Створіть файли від імені `labuser1` (член групи).**

```bash
sudo -u labuser1 touch /srv/lab04share/from-labuser1.txt
sudo -u labuser1 bash -c 'printf "data from labuser1\n" > /srv/lab04share/note1.txt'
sudo -u labuser1 ls -l /srv/lab04share
sudo -u labuser1 cat /srv/lab04share/note1.txt
```

Зверніть увагу на групу створених файлів. Права файлів залежать від `umask`: `sudo` за замовчуванням застосовує `umask 022`, тому права можуть бути `rw-r--r--`. Зафіксуйте фактичні значення та поясніть.

**Крок 4. Перевірте доступ від імені `labuser2` (не член групи).**

```bash
sudo -u labuser2 ls /srv/lab04share
sudo -u labuser2 cat /srv/lab04share/note1.txt
sudo -u labuser2 touch /srv/lab04share/from-labuser2.txt
```

Усі три команди мають завершитися помилками.

**Крок 5. Порівняйте поведінку з `setgid` і без нього.**

```bash
sudo chmod 770 /srv/lab04share
ls -ld /srv/lab04share
sudo -u labuser1 touch /srv/lab04share/no-setgid.txt
sudo chmod 2770 /srv/lab04share
ls -ld /srv/lab04share
sudo -u labuser1 touch /srv/lab04share/with-setgid.txt
sudo ls -l /srv/lab04share
```

Порівняйте групи файлів `no-setgid.txt` і `with-setgid.txt`.

## Завдання 5. Паролі, блокування, оболонка та терміни дії

**Теорія:** модуль 7, розділи 6.4, 6.5 і 8.

### Мета

Навчитися розрізняти блокування пароля, заборону оболонки та терміни дії облікових записів і перевіряти їхній вплив на вхід.

### Порядок виконання

**Крок 1. Задайте пароль і перевірте вхід.**

```bash
sudo passwd labuser1
sudo passwd -S labuser1
su - labuser1
```

Для `labuser1` використайте **навчальний пароль**, відмінний від ваших реальних паролів. Після запиту пароля `su` у новому сеансі виконайте:

```bash
whoami
pwd
id
exit
```

**Крок 2. Заблокуйте пароль і перевірте вхід.**

```bash
sudo passwd -l labuser1
sudo passwd -S labuser1
su - labuser1
```

Остання команда має завершитися помилкою автентифікації навіть після введення правильного пароля. Потім розблокуйте:

```bash
sudo passwd -u labuser1
sudo passwd -S labuser1
```

**Крок 3. Заборонте оболонку входу.**

```bash
sudo usermod -s /usr/sbin/nologin labuser2
getent passwd labuser2
sudo su - labuser2
sudo usermod -s /bin/bash labuser2
getent passwd labuser2
```

Команда `sudo su - labuser2` має вивести повідомлення про недоступність облікового запису.

**Крок 4. Перегляньте й змініть терміни дії пароля.**

```bash
sudo chage -l labuser1
sudo chage -M 90 labuser1
sudo chage -l labuser1
```

### Результати

Заповніть таблицю.

| № | Дія | Результат / повідомлення |
|---|---|---|
| 1 | `passwd -S labuser1` після встановлення пароля | |
| 2 | `su - labuser1` із правильним паролем | |
| 3 | `passwd -S labuser1` після `-l` | |
| 4 | `su - labuser1` після блокування | |
| 5 | `passwd -S labuser1` після `-u` | |
| 6 | `sudo su - labuser2` із `nologin` | |
| 7 | Максимальний термін пароля до та після `chage -M 90` | |

### Запитання для аналізу

1. Чим блокування пароля відрізняється від оболонки `nologin`?
2. Чи припиняє блокування пароля роботу процесів цього користувача?
3. Чому `sudo su - labuser2` не запитав пароль, а `su - labuser1` — запитав?
4. Чому система відмовляється розблоковувати обліковий запис без пароля?
5. Що означають стани `P`, `L` і `NP` у `passwd -S`?
6. Яку роль у безпеці відіграють терміни дії паролів?

5. Чому `/etc/shadow` недоступний звичайним користувачам?
6. Які параметри `useradd` потрібні для створення звичайного користувача в Ubuntu?
7. Чим `usermod -aG` відрізняється від `usermod -G`?
8. Коли набувають чинності зміни груп для поточного сеансу?
9. Для чого використовується біт `setgid` на каталозі? Як налаштувати спільний каталог групи?
10. Чим блокування пароля відрізняється від `nologin` і від закінчення терміну дії запису?
11. Чим `sudo` відрізняється від `su`? Чий пароль запитується в кожному випадку?
12. Чому `sudo echo test > file` не працює? Як це виправити?
13. Що таке `visudo` і для чого він потрібен?
14. Що видаляє `userdel -r`, а що залишає?
15. Чим програма відрізняється від процесу?
16. Що таке PID, PPID і яка роль процесу з PID 1?
17. Які бувають стани процесів? Що означають `R`, `S`, `D`, `T`, `Z`?
18. Що таке зомбі-процес і чому його не можна «вбити»?
19. Що показує `load average` і з чим його порівнюють?
20. Чим фонові завдання відрізняються від процесів у передньому плані? Які команди ними керують?
21. Чим `SIGTERM` відрізняється від `SIGKILL`? Які сигнали не можна перехопити?
22. Хто має право надсилати сигнали процесам?
23. Що означає значення `nice` і хто може його знижувати?

## Безпека

!!! warning "Правила безпечної роботи"

    - Виконуйте роботу лише у власній навчальній VM; створіть знімок перед початком.
    - Створюйте й змінюйте лише об'єкти, названі в роботі: `labuser1`, `labuser2`, `labteam`, `labaudit`, `/srv/lab04share`.
    - Не змінюйте власні групи командою `usermod -G` без `-a`.
    - Не редагуйте `/etc/passwd`, `/etc/shadow`, `/etc/group` і `sudoers` вручну; використовуйте спеціальні команди.
    - Використовуйте навчальні паролі, відмінні від реальних, і не включайте їх у звіт.
    - Перед `sudo rm`, `sudo kill`, `sudo userdel` перевіряйте шлях, PID чи ім'я.
    - Не надсилайте сигнали процесам, які ви не запускали, та не чіпайте процес PID 1.
    - Починайте з `SIGTERM`; `SIGKILL` застосовуйте лише коли м'яке завершення не допомогло.
    - Використовуйте для навантаження лише `sleep` і `yes` та завершуйте їх.
    - Обов'язково виконайте прибирання (завдання 12) і перевірте його результат.

## Висновок

У висновку необхідно коротко зазначити:

- які навички було отримано;
- які команди керування користувачами, групами та процесами виявилися найкориснішими;
- як групи, права каталогу та `setgid` забезпечують спільний доступ;
- чому `sudo` вимагає обережності й чим він відрізняється від роботи від імені `root`;
- як права користувача впливають на керування процесами;
- які помилки виникали та як їх було діагностовано;
- чи вдалося повністю відновити початковий стан системи;
- які питання залишилися незрозумілими та потребують додаткового опрацювання.
