# Лабораторна робота № 1. Linux та робоче середовище

## Тема

**Linux та робоче середовище. Первинне дослідження операційної системи за допомогою командного рядка.**

## Пов'язані модулі

- Модуль 1. Linux та операційні системи.
- Модуль 2. Підготовка Linux-середовища та основи віддаленого доступу.

## Мета

Закріпити теоретичні знання про операційні системи та Linux, сформувати практичні навички роботи з командним рядком і навчитися збирати та аналізувати основну інформацію про операційну систему, користувача, системні ресурси й мережеву конфігурацію.

Під час виконання лабораторної роботи студент повинен:

- ознайомитися з робочим Linux-середовищем;
- навчитися використовувати базові команди для отримання системної інформації;
- визначити версію дистрибутива Linux та ядра;
- перевірити характеристики процесора, оперативної пам'яті та дискового простору;
- отримати інформацію про мережеві інтерфейси й маршрути;
- навчитися документувати результати виконання команд;
- сформулювати висновок щодо стану та готовності Linux-середовища до подальшої роботи.

## Вимоги

Для виконання лабораторної роботи необхідно мати:

- робоче Linux-середовище;
- доступ до командного рядка;
- обліковий запис користувача Linux;
- можливість виконувати команди без адміністративних привілеїв;
- доступ до навчальних матеріалів курсу.

Рекомендоване середовище:

- Ubuntu LTS;
- віртуальна машина VirtualBox або інше погоджене середовище віртуалізації;
- термінал Linux.

Допускається використання іншого дистрибутива Linux, установленого на фізичному комп'ютері або у віртуальній машині.

**Важливо:** для основних завдань не потрібні права адміністратора. Не використовуйте `sudo`, якщо команда не потребує підвищених привілеїв.

## Правила виконання роботи

1. Уважно прочитайте умову кожного завдання.
2. Виконуйте команди послідовно.
3. Аналізуйте результат кожної команди, а не лише копіюйте його.
4. Записуйте отримані результати у звіт.
5. Якщо результат відрізняється від наведеного в прикладі, з'ясуйте причину.
6. Не змінюйте системні налаштування без необхідності.
7. У разі виникнення помилки зафіксуйте повідомлення та спробуйте визначити її причину.
8. Не використовуйте виробничі системи або сервери, на які у вас немає відповідного дозволу.

Усі приклади виведення команд у цій роботі є умовними. Результати у вашому середовищі можуть відрізнятися.

## Початкова підготовка

### 1. Відкрийте термінал

Увійдіть до Linux-системи та відкрийте термінал.

Якщо ви працюєте у віртуальній машині, переконайтеся, що Ubuntu успішно завантажилася.

### 2. Перевірте поточного користувача

Виконайте:

```bash
whoami
```

Команда показує ім'я користувача, від імені якого працює поточна оболонка.

Запишіть результат у звіт.

### 3. Визначте ім'я комп'ютера

Виконайте:

```bash
hostname
```

Команда виводить ім'я системи.

Запишіть результат у звіт.

### 4. Перевірте інформацію про ядро

Виконайте:

```bash
uname -a
```

Команда виводить основну інформацію про ядро Linux та архітектуру системи.

Запишіть результат у звіт.

### 5. Визначте поточний каталог

Виконайте:

```bash
pwd
```

Команда показує повний шлях до поточного робочого каталогу.

Запишіть результат у звіт.

### Контрольна перевірка

Після виконання початкових команд ви повинні вміти відповісти на запитання:

- Який користувач виконує команди?
- Як називається система?
- Яку версію ядра використано?
- У якому каталозі ви перебуваєте?

## Завдання 1. Ознайомлення з користувачем і робочим середовищем

### Мета

Навчитися отримувати базову інформацію про поточного користувача, його ідентифікатори та поточне розташування у файловій системі.

### Порядок виконання

**Крок 1. Визначте поточного користувача.**

```bash
whoami
```

Поясніть, що показує команда.

**Крок 2. Отримайте ідентифікатори користувача та груп.**

```bash
id
```

Команда показує UID, основний GID та інформацію про групи, до яких належить користувач.

Зверніть увагу на значення:

- `uid` — ідентифікатор користувача;
- `gid` — ідентифікатор основної групи;
- `groups` — перелік груп, членом яких є користувач.

**Крок 3. Перевірте поточний каталог.**

```bash
pwd
```

Поясніть, що означає шлях, який повернула команда.

**Крок 4. Перегляньте вміст поточного каталогу.**

```bash
ls -la
```

Команда показує файли та каталоги, включно з прихованими елементами.

Поясніть призначення параметрів:

- `-l` — формат докладного списку;
- `-a` — відображення всіх елементів, включно з прихованими.

## Завдання 2. Визначення характеристик операційної системи

### Мета

Навчитися визначати дистрибутив Linux, його версію, версію ядра та архітектуру системи.

### Порядок виконання

**Крок 1. Отримайте інформацію про дистрибутив.**

```bash
cat /etc/os-release
```

Знайдіть у результаті поля:

- `NAME`;
- `VERSION`;
- `ID`;
- `VERSION_ID`.

Залежно від дистрибутива набір полів може відрізнятися.

**Крок 2. Визначте версію ядра.**

```bash
uname -r
```

Запишіть отримане значення.

**Крок 3. Визначте архітектуру системи.**

```bash
uname -m
```

Поширені результати:

| Результат | Пояснення |
|---|---|
| `x86_64` | 64-бітна архітектура сімейства x86 |
| `aarch64` | 64-бітна архітектура ARM |

Це приклади. Фактичний результат залежить від обладнання та середовища виконання.

**Крок 4. Отримайте повну інформацію про ядро.**

```bash
uname -a
```

Порівняйте результат цієї команди з результатом `uname -r`.

## Завдання 3. Аналіз системних ресурсів

### Мета

Навчитися визначати основні характеристики процесора, стан оперативної пам'яті та доступний дисковий простір.

### Порядок виконання

**Крок 1. Отримайте інформацію про процесор.**

```bash
lscpu
```

Знайдіть і запишіть:

- архітектуру;
- кількість процесорів або логічних процесорів, наведену у виведенні;
- модель процесора, якщо вона відображається;
- кількість ядер, якщо вона відображається окремо.

Зверніть увагу: у віртуальній машині команда показує ресурси, доступні гостьовій системі, а не обов'язково повну конфігурацію фізичного процесора.

**Крок 2. Перевірте оперативну пам'ять.**

```bash
free -h
```

Знайдіть рядок `Mem` і зверніть увагу на:

- `total` — загальний обсяг пам'яті, доступний системі;
- `used` — використана пам'ять;
- `free` — невикористана пам'ять;
- `available` — оцінка пам'яті, доступної для запуску нових програм без інтенсивного використання підкачки.

Linux використовує оперативну пам'ять для кешування. Тому значення `used` не слід автоматично трактувати як пам'ять, яку неможливо використати повторно.

**Крок 3. Перевірте дисковий простір.**

```bash
df -h
```

Знайдіть файлову систему, яка відповідає кореневому каталогу `/`.

Запишіть:

- загальний розмір;
- використаний простір;
- доступний простір;
- відсоток використання.

**Крок 4. Перевірте обсяг домашнього каталогу.**

```bash
du -sh ~
```

Команда показує сумарний обсяг, який займають дані в домашньому каталозі користувача.

Зверніть увагу на різницю:

- `df -h` показує використання файлових систем;
- `du -sh ~` оцінює обсяг даних у домашньому каталозі.

## Завдання 4. Базова мережева діагностика

### Мета

Навчитися отримувати інформацію про мережеві інтерфейси, IP-адреси, маршрути та DNS.

### Порядок виконання

**Крок 1. Перегляньте мережеві інтерфейси.**

```bash
ip addr
```

Потім виконайте скорочений варіант:

```bash
ip -br addr
```

Визначте:

- назви мережевих інтерфейсів;
- стан інтерфейсів;
- IP-адреси, якщо вони призначені.

Зверніть увагу на інтерфейс `lo`, який використовується для локальної мережевої взаємодії.

**Крок 2. Перегляньте таблицю маршрутизації.**

```bash
ip route
```

Знайдіть маршрут за замовчуванням, якщо він є.

У записі на зразок:

```text
default via 192.168.1.1 dev enp0s3
```

- `default` означає маршрут за замовчуванням;
- `via` указує адресу наступного вузла;
- `dev` указує мережевий інтерфейс.

Це умовний приклад. У вашій системі значення можуть бути іншими.

**Крок 3. Перевірте перетворення доменного імені.**

```bash
getent hosts ubuntu.com
```

Команда перевіряє, чи може система отримати адресу для вказаного доменного імені.

Результат залежить від мережевої конфігурації та доступності відповідних служб.

**Крок 4. За наявності мережевого підключення перевірте доступність вузла.**

```bash
ping -c 4 1.1.1.1
```

Команда надсилає чотири ICMP-запити.

Після цього можна перевірити доменне ім'я:

```bash
ping -c 4 ubuntu.com
```

Якщо команди не отримують відповідей, зафіксуйте результат. Не робіть висновок про причину несправності лише на підставі `ping`: ICMP-запити можуть блокуватися мережею або самим вузлом.

Якщо мережа не працює, продовжуйте аналіз за результатами `ip addr`, `ip route` та `getent hosts`.

| 2 | IP-адреса основного інтерфейсу | `ip -br addr` | |
| 3 | Маршрут за замовчуванням | `ip route` | |

### Запитання для аналізу

1. Для чого потрібен мережевий інтерфейс?

```bash

```

## Завдання 6. Додаткове. Основи SSH

Це завдання виконується за наявності власного другого Linux-комп'ютера або навчального сервера, доступ до якого надано викладачем чи адміністратором.

Якщо такого середовища немає, достатньо відповісти на контрольні запитання до завдання.

### Мета

Ознайомитися з принципом віддаленого доступу до Linux через SSH.

### Порядок виконання

**Крок 1. Перевірте наявність SSH-клієнта.**

```bash
ssh -V
```

Зафіксуйте результат.

**Крок 2. Визначте параметри віддаленого вузла.**

Отримайте від адміністратора або викладача:

- адресу сервера;
- ім'я користувача;
- порт SSH, якщо він відрізняється від стандартного;
- інструкції щодо дозволеного способу автентифікації.

**Крок 3. Виконайте підключення.**

Загальний синтаксис:

```bash
ssh username@server_ip
```

Замініть `username` та `server_ip` реальними значеннями вашого навчального середовища.

Підключайтеся лише до вузлів, доступ до яких вам дозволено.

**Крок 4. Після підключення перевірте віддалену систему.**
