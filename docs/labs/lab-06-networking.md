# Лабораторна робота № 6. Мережі Linux

## Тема

**Конфігурація та діагностика мережі в Linux. Дослідження інтерфейсів, адресації, маршрутизації, DNS, портів і сокетів; використання мережевих інструментів; захоплення пакетів і послідовна діагностика несправностей.**

## Пов'язані модулі

- Модуль 11. Мережі Linux.
- Модуль 12. Мережеві інструменти.

## Мета

Закріпити теоретичні знання про мережу Linux та інструменти діагностики, сформувати практичні навички дослідження конфігурації мережі, розрахунку IPv4-адрес, роботи з DNS, портами й сокетами та навчитися послідовно діагностувати мережеві проблеми.

Під час виконання лабораторної роботи студент повинен:

- досліджувати мережеві інтерфейси, IP-адреси, MAC-адреси, стан і статистику;
- виконувати розрахунки IPv4-підмереж і класифікувати адреси;
- аналізувати таблицю маршрутизації, шлюз за замовчуванням і таблицю сусідів;
- досліджувати порядок розв'язання імен, `/etc/hosts`, `systemd-resolved` і DNS-запити;
- перевіряти доступність вузлів і маршрут за допомогою `ping`, `tracepath`, `traceroute`;
- аналізувати сокети, порти й процеси за допомогою `ss`;
- створювати локальний тестовий сервер і перевіряти його клієнтами `curl`, `wget`, `nc`;
- захоплювати й аналізувати пакети за допомогою `tcpdump` на loopback-інтерфейсі;
- виконувати тимчасову зміну конфігурації та переглядати конфігурацію Netplan;
- діагностувати типові мережеві симптоми за рівнями й повністю відновити початковий стан системи.

## Вимоги

Для виконання лабораторної роботи необхідно мати:

- навчальну віртуальну машину з Ubuntu 24.04 LTS;
- обліковий запис із правом на `sudo` (член групи `sudo`);
- робоче підключення VM до Інтернету;
- `python3` (входить до складу Ubuntu);
- доступ до навчальних матеріалів модулів 11 і 12;
- результати лабораторних робіт № 1–5 для довідки.

**Рекомендація:** створіть **знімок VM** перед початком роботи (модуль 2).

Допускається використання іншого дистрибутива Linux. Імена інтерфейсів, адреси мережі, склад пакетів і конфігурація Netplan залежать від середовища (режими NAT, Bridged, Host-only у VirtualBox); такі відмінності необхідно зафіксувати у звіті.

**Важливо:** у цій роботі використовується `sudo`, але лише для встановлення пакетів, захоплення пакетів, тимчасової адреси на loopback-інтерфейсі й читання конфігурації. Не змінюйте адресу, шлюз, DNS і правила брандмауера основного інтерфейсу. Усі мережеві експерименти виконуються в межах власної VM: з адресами loopback, локальним сервером і адресами документації (`192.0.2.0/24`). **Не скануйте й не перехоплюйте трафік чужих систем.**

## Завдання 4. DNS і порядок розв'язання імен

**Теорія:** модуль 11, розділ 9; модуль 12, розділ 7.

### Мета

Навчитися досліджувати механізм розв'язання імен, порівнювати інструменти й перевіряти вплив `/etc/hosts`.

### Порядок виконання

**Крок 1. Перегляньте конфігурацію резолвера.**

```bash
grep '^hosts:' /etc/nsswitch.conf
cat /etc/hosts
ls -l /etc/resolv.conf
cat /etc/resolv.conf
systemctl is-active systemd-resolved
resolvectl status | head -n 25
```

**Крок 2. Виконайте DNS-запити різними інструментами.**

```bash
getent hosts ubuntu.com
resolvectl query ubuntu.com
dig ubuntu.com
dig +short ubuntu.com A
dig +short ubuntu.com AAAA
dig +short MX ubuntu.com
dig @1.1.1.1 +short ubuntu.com
dig -x 1.1.1.1 +short
```

Зафіксуйте `status`, TTL і `SERVER` у виведенні `dig ubuntu.com`.

**Крок 3. Перевірте помилки DNS.**

```bash
getent hosts nonexistent.invalid
echo "$?"
dig nonexistent.invalid | grep status
dig @192.0.2.53 +time=2 +tries=1 ubuntu.com
echo "$?"
```

Остання команда звертається до недоступного DNS-сервера з адресою документації. Зафіксуйте повідомлення.

**Крок 4. Перевірте вплив `/etc/hosts`.**

```bash
sudo cp /etc/hosts ~/lab06/hosts.bak
echo "127.0.0.5 lab06.test" | sudo tee -a /etc/hosts
getent hosts lab06.test
resolvectl query lab06.test
ping -c 1 -W 2 lab06.test
dig +short lab06.test
```

Порівняйте результати `getent`, `ping` і `dig`. Потім **відновіть файл**:

```bash
sudo cp ~/lab06/hosts.bak /etc/hosts
getent hosts lab06.test
echo "$?"
sha256sum /etc/hosts
cmp ~/lab06/hosts.bak /etc/hosts && echo "hosts restored"
```

Команда `cmp` порівнює два файли й нічого не виводить, якщо вони однакові; `&&` виводить повідомлення лише тоді.

## Завдання 8. Захоплення пакетів

**Теорія:** модуль 12, розділ 12.

### Мета

Навчитися захоплювати пакети на loopback-інтерфейсі й розпізнавати тристороннє рукостискання TCP, ICMP та DNS-запити до локального резолвера.

### Порядок виконання

Усі захоплення виконуються **лише на інтерфейсі `lo`** з фільтрами й обмеженням кількості пакетів.

**Крок 1. Захопіть обмін із локальним сервером.**

```bash
cd ~/lab06
sudo -v
python3 -m http.server 8080 --bind 127.0.0.1 --directory ~/lab06 > server.log 2>&1 &
SERVER_PID=$!
sleep 1
sudo timeout 15 tcpdump -n -i lo -A -c 20 'tcp port 8080' > capture.txt 2>&1 &
DUMP_PID=$!
sleep 2
curl -s http://127.0.0.1:8080/ > /dev/null
wait "$DUMP_PID"
kill "$SERVER_PID"
cat capture.txt
```

Команда `timeout 15` перерве захоплення через 15 секунд, тому `wait` може тривати до цього часу.

**Крок 2. Захопіть ICMP.**

```bash
sudo timeout 10 tcpdump -n -i lo -c 6 icmp > icmp.txt 2>&1 &
DUMP_PID=$!
sleep 2
ping -c 2 127.0.0.1 > /dev/null
wait "$DUMP_PID"
cat icmp.txt
```

**Крок 3. Захопіть DNS-запит до локального резолвера.**

```bash
sudo timeout 10 tcpdump -n -i lo -c 4 'udp port 53' > dns.txt 2>&1 &
DUMP_PID=$!
sleep 2
dig +short ubuntu.com > /dev/null
wait "$DUMP_PID"
cat dns.txt
```
