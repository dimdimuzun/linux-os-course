# Права доступу

Докладніше: [модуль 6](../modules/06-permissions.md), [модуль 7](../modules/07-users-and-groups.md).

## Модель

```text
-rw-r----- 1 root shadow 1450 Oct 12 09:00 /etc/shadow
│└┬┘└┬┘└┬┘   │    │
│ │  │  │    │    └─ група
│ │  │  │    └────── власник
│ │  │  └─────────── права «інших»
│ │  └────────────── права групи
│ └───────────────── права власника
└─────────────────── тип (- файл, d каталог, l посилання)
```

Система перевіряє категорії **по черзі**: власник → група → інші. Права наступної категорії не додаються до попередньої. `root` обходить більшість перевірок.

## Значення `r`, `w`, `x`

| Право | Файл | Каталог |
|---|---|---|
| `r` | Читати вміст | Переглядати перелік імен (`ls`) |
| `w` | Змінювати вміст | Створювати, видаляти, перейменовувати об'єкти (разом із `x`) |
| `x` | Запускати як програму | «Проходити» через каталог: `cd` і доступ до об'єктів за іменем |

Важливо:

- для читання файла потрібне `x` на **кожному** каталозі шляху;
- видалення файла залежить від прав на **каталог**, а не на файл;
- права символічного посилання не використовуються — діють права цілі.

## Числовий запис

| `r` | `w` | `x` |
|---:|---:|---:|
| 4 | 2 | 1 |

| Режим | Запис | Типове застосування |
|---|---|---|
| `644` | `rw-r--r--` | Звичайні файли |
| `600` | `rw-------` | Приватні файли, SSH-ключі |
| `640` | `rw-r-----` | Файли для власника й групи |
| `755` | `rwxr-xr-x` | Програми, загальні каталоги |
| `700` | `rwx------` | Приватні каталоги (`~/.ssh`) |
| `775` | `rwxrwxr-x` | Каталоги, у які пише група |
| `777` | `rwxrwxrwx` | **Практично ніколи** |

## `chmod`

```bash
chmod u+x script.sh
chmod go-rwx secret.txt
chmod a+r file
chmod u=rw,g=r,o= file
chmod 644 file
chmod -R u+rwX,go-w dir
```

| Елемент | Значення |
|---|---|
| `u`, `g`, `o`, `a` | Власник, група, інші, усі |
| `+`, `-`, `=` | Додати, прибрати, задати точно |
| `X` | `x` лише для каталогів і вже виконуваних файлів |
| Числовий запис | Задає **всі** права точно (скидає попередні) |

Змінювати права може власник (або `root`). `chmod -R` застосовуйте обережно й лише після перевірки шляху.

## Власник і група

```bash
ls -l file
id
groups
chgrp група file
sudo chown користувач:група file
sudo chown -R користувач: dir
```

| Правило | Пояснення |
|---|---|
| Змінювати **власника** | Лише `root` (через `sudo`) |
| Змінювати **групу** | Власник файла, лише на групу, до якої сам належить |
| Зміна груп користувача | Набуває чинності після нового входу |

## `umask`

Нові файли починають із `666`, каталоги — із `777`; з них **вилучаються** біти `umask`.

| `umask` | Файли | Каталоги |
|---|---|---|
| `002` | `664` | `775` |
| `022` | `644` | `755` |
| `027` | `640` | `750` |
| `077` | `600` | `700` |

```bash
umask
umask -S
umask 027
```

У Ubuntu звичайно `0002`; зміна `umask` діє лише в поточному сеансі.

## Спеціальні біти

| Біт | Число | Позначення | Для файла | Для каталогу |
|---|---:|---|---|---|
| `setuid` | 4000 | `s` у позиції `x` власника | Програма працює з правами власника | — |
| `setgid` | 2000 | `s` у позиції `x` групи | Програма працює з правами групи | Нові файли успадковують групу каталогу |
| `sticky` | 1000 | `t` у позиції `x` інших | — | Видаляти можна лише власні об'єкти |

```bash
chmod 2775 shared
chmod +t shared
ls -l /usr/bin/passwd
ls -ld /tmp
```

Великі `S` і `T` означають, що біт установлено, а `x` немає.

## Діагностика `Permission denied`

| Крок | Команда | Запитання |
|---|---|---|
| 1 | `id`, `whoami` | Хто я й до яких груп належу? |
| 2 | `ls -ld шлях` | Власник, група й права об'єкта? |
| 3 | `namei -l шлях` | Є `x` на кожному каталозі шляху? |
| 4 | `ls -ld каталог` | Для створення/видалення потрібні `w` і `x` на каталозі |
| 5 | `findmnt -T шлях` | Чи не змонтовано `ro` або `noexec`? |
| 6 | `getfacl шлях` | Чи немає ACL? (позначка `+`) |
| 7 | `journalctl -k` | Чи не заблокував AppArmor? (`apparmor="DENIED"`) |

Відсутність об'єкта дає `No such file or directory`, відсутність права — `Permission denied`: це різні проблеми.

## Запуск скриптів

```bash
chmod u+x script.sh
./script.sh
bash script.sh
```

Без права `x` запуск `./script.sh` дає `Permission denied`; `bash script.sh` усе одно працює. На файлових системах із `noexec` прямий запуск заборонено. Поточного каталогу немає в `PATH`, тому потрібен `./`.

## Аудит прав (лише читання)

```bash
find /usr /bin /sbin -xdev -type f -perm -4000
find /etc -xdev -type f -perm -0002
find / -xdev -type d -perm -0002 ! -perm -1000 2>/dev/null
find /etc /usr /home -xdev \( -nouser -o -nogroup \) 2>/dev/null
stat -c '%A %a %U:%G %n' /etc/passwd /etc/shadow
```

| Пошук | Що означає |
|---|---|
| `-perm -4000` / `-2000` | Програми зі `SUID` / `SGID` |
| `-perm -0002` | Об'єкти, доступні для запису всім |
| `-type d -perm -0002 ! -perm -1000` | Каталоги з записом для всіх без `sticky` |
| `-nouser -o -nogroup` | Файли без власника чи групи |

!!! danger

    Не «виправляйте» проблеми доступу командою `chmod 777` і не запускайте служби від `root` без потреби. Визначте, кому саме потрібен доступ, і надайте мінімальні права.
