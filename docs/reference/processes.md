# Процеси

Докладніше: [модуль 8](../modules/08-processes.md), діагностика — [модуль 16](../modules/16-troubleshooting.md).

Починайте діагностику з безпечного **спостереження**: спершу подивіться, потім змінюйте.

## Перегляд

```bash
ps aux
ps -ef --forest
ps -p $$ -o pid,ppid,user,stat,ni,comm
ps -eo pid,user,stat,%cpu,%mem,comm --sort=-%cpu | head
pgrep -a nginx
pidof bash
pstree -p
top
```

| Команда | Дія |
|---|---|
| `ps aux` | Усі процеси (`USER PID %CPU %MEM VSZ RSS TTY STAT START TIME COMMAND`) |
| `ps -ef` | Усі процеси з PPID |
| `ps -o поля` | Власний набір стовпців |
| `--sort=-%cpu` | Сортування за зменшенням |
| `pgrep -a`, `pidof` | Пошук за іменем |
| `$$`, `$PPID`, `$!` | PID оболонки, її батька, останнього фонового процесу |

## Стани процесів

| Код | Стан |
|---|---|
| `R` | Виконується або готовий |
| `S` | Очікує (можна перервати) |
| `D` | Очікує введення-виведення (не переривається сигналами) |
| `T` | Зупинений (`Ctrl+Z`, `SIGSTOP`) |
| `Z` | Зомбі: завершений, батько не зчитав код |

Додатково в `STAT`: `s` — лідер сеансу, `+` — передній план, `<` — підвищений пріоритет, `N` — знижений, `l` — багатопотоковий.

## `top`

| Клавіша | Дія |
|---|---|
| `q` | Вийти |
| `P`, `M` | Сортування за процесором / пам'яттю |
| `1` | Кожне ядро окремо |
| `k` | Надіслати сигнал |
| `r` | Змінити `nice` |
| `u` | Фільтр за користувачем |

Шапка: `load average` (порівнюйте з `nproc`), `Tasks` (зокрема `zombie`), `%Cpu(s)` (`us`, `sy`, `id`, `wa`), `MiB Mem` (дивіться на `avail Mem`).

## Фонові завдання

```bash
sleep 300 &
jobs
fg %1
bg %1
kill %1
nohup команда > /dev/null 2>&1 &
```

| Клавіші / команда | Дія |
|---|---|
| `&` | Запустити у фоні |
| `Ctrl+Z`, `bg`, `fg` | Призупинити, продовжити у фоні, повернути на передній план |
| `jobs` | Завдання поточної оболонки (номер ≠ PID) |
| `nohup`, `disown` | Не завершувати після закриття термінала |

## Сигнали

| № | Назва | Призначення | Перехоплюється |
|---:|---|---|---|
| 1 | `SIGHUP` | Розрив з'єднання; перечитування конфігурації | Так |
| 2 | `SIGINT` | Переривання (`Ctrl+C`) | Так |
| 9 | `SIGKILL` | Примусове завершення | **Ні** |
| 15 | `SIGTERM` | Запит завершитися (за замовчуванням) | Так |
| 18 | `SIGCONT` | Продовжити | Так |
| 19 | `SIGSTOP` | Зупинити | **Ні** |
| 20 | `SIGTSTP` | Зупинка з клавіатури | Так |

```bash
kill PID
kill -9 PID
kill -STOP PID
kill -CONT PID
kill -0 PID
kill -l
pkill -u користувач ім'я
killall ім'я
```

**Порядок завершення:** визначити процес і власника → `SIGTERM` → зачекати й перевірити → `SIGKILL` лише у крайньому разі.

- `pkill` і `killall` діють на **всі** збіжні процеси: перед ними виконайте `pgrep -a ім'я`;
- звичайний користувач надсилає сигнали лише своїм процесам; чужі — `Operation not permitted`;
- `kill -0 PID` лише перевіряє існування й право.

Код завершення процесу, зупиненого сигналом, дорівнює `128 + N`: `143` — `SIGTERM`, `137` — `SIGKILL`, `130` — `Ctrl+C`.

## Пріоритети

```bash
nice -n 10 команда
renice -n 5 -p PID
ps -o pid,ni,pri,comm -p PID
```

`nice` від `-20` (найвищий) до `19`. Звичайний користувач може лише **збільшувати** значення для своїх процесів. Вплив видно лише за конкуренції за процесор.

## `/proc`

```bash
ls /proc/$$
readlink /proc/$$/exe
ls -l /proc/$$/cwd
head /proc/$$/status
ls -l /proc/$$/fd
cat /proc/PID/limits
```

## Перші хвилини діагностики

| Команда | Що з'ясовуємо |
|---|---|
| `uptime`, `nproc` | `load average` відносно ядер |
| `top`, `ps --sort=-%cpu` | Хто завантажує процесор |
| `ps --sort=-%mem`, `free -h` | Хто споживає пам'ять; дивіться на `available` |
| `vmstat 1 5` | `r`, `b`, `si`/`so`, `wa` |
| `df -h`, `df -i` | Місце й inode |
| `systemctl --failed` | Збійні служби |
| `journalctl -p err -b` | Помилки поточного завантаження |

| Симптом | Перевірка | Дія |
|---|---|---|
| Один процес ~100% CPU | `ps --sort=-%cpu` | З'ясувати призначення, `SIGTERM`, `renice` |
| Високе `wa`, процеси в `D` | `top`, `vmstat` | Проблема диска, а не процесора |
| Процес у `T` | `ps`, `jobs` | `kill -CONT` або `fg` |
| Багато `Z` | `ps -eo pid,ppid,stat,comm` | Виправити батьківський процес |
| Процеси «зникають» | `journalctl -k` | Можливий OOM killer |

## Процеси й користувачі

Кожен процес працює від імені користувача й має його права. Процеси служб мають працювати від окремих непривілейованих користувачів. Процес зі `setuid` працює з правами власника файла (так `passwd` змінює `/etc/shadow`).

```bash
sudo -u користувач команда
ps -eo user,pid,comm | head
```
