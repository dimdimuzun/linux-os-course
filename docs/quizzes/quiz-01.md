# Квіз 1

## Охоплення

Модулі 1–8.

## Теми

| Модуль | Ключові теми для підготовки |
|---|---|
| 1. Linux та операційні системи | призначення ОС, ядро й користувацький простір, дистрибутиви, відкрите ПЗ |
| 2. Робоче середовище Linux | віртуальна машина, режими мережі (NAT, Bridged, Host-only), знімки, SSH, перші команди |
| 3. Файлова система | дерево каталогів, FHS, абсолютні й відносні шляхи, типи файлів, символічні посилання, точки монтування, віртуальні файлові системи |
| 4. Shell та командний рядок | змінні, `PATH`, лапки, шаблони, перенаправлення, конвеєри, коди завершення, `&&` і `\|\|` |
| 5. Файли та каталоги | `mkdir`, `touch`, `cp`, `mv`, `rm`, перегляд вмісту, посилання, `find`, `grep`, `du`, `tar` |
| 6. Права доступу | `rwx` для файлів і каталогів, числовий і символьний `chmod`, `umask`, `setuid`/`setgid`/`sticky`, діагностика `Permission denied` |
| 7. Користувачі та групи | UID/GID, `/etc/passwd`, `/etc/shadow`, `useradd`, `usermod -aG`, `sudo`, `su` |
| 8. Процеси | PID/PPID, `ps`, `top`, стани процесів, сигнали, `jobs`/`fg`/`bg`, `nice` |

## Підготовка

1. Перегляньте розділи «Самоперевірка» модулів 1–8: запитання квізу ґрунтуються на тих самих поняттях.
2. Повторіть команди з [довідника](../reference/commands.md): [файлова система](../reference/filesystem.md), [права доступу](../reference/permissions.md), [користувачі](../reference/users.md), [процеси](../reference/processes.md).
3. Згадайте результати лабораторних робіт ЛР1–ЛР4: вони містять усі типові ситуації, які перевіряються.
4. Переконайтеся, що розумієте **результат** команд, а не лише їх запис: що виведе команда, що зміниться в системі, чому виникає помилка.
5. Повторіть вміння читати рядок `ls -l`, рядок `ps aux`, таблицю прав і `/etc/passwd`.

!!! tip "Як готуватися"

    Для кожної команди відповідайте на три запитання: що вона робить, який стан системи змінюється, як це перевірити. Запитання на розуміння («чому?») трапляються частіше, ніж на пам'ять («який параметр?»).

## Тренувальні запитання

Нижче наведено приклади запитань для самоперевірки. Вони не входять до тесту в Moodle.

**1.** Який шлях є **відносним**: `/etc/passwd`, `../etc`, `~/notes.txt`? Чому?

??? note "Відповідь"

    `../etc` — відносний, бо не починається з `/` і відраховується від поточного каталогу. `~/notes.txt` розгортається оболонкою до абсолютного шляху.

**2.** Чим `>` відрізняється від `>>`?

??? note "Відповідь"

    `>` перезаписує файл (стирає попередній вміст), `>>` додає в кінець файла.

**3.** Що виведе `echo $?` одразу після `ls /nonexistent`?

??? note "Відповідь"

    Ненульовий код (зазвичай `2`): команда завершилась помилкою. Код `0` означав би успіх.

**4.** Які права має файл із режимом `640`? Хто може його читати?

??? note "Відповідь"

    `rw-r-----`: власник читає й пише, група лише читає, інші не мають доступу. Читати можуть власник і група.

**5.** Чому для видалення файла потрібні права на **каталог**, а не на сам файл?

??? note "Відповідь"

    Видалення змінює запис у каталозі (ім'я файла), тому потрібні права `w` і `x` на каталог. Права на файл визначають читання, запис вмісту й запуск.

**6.** Що станеться, якщо виконати `sudo usermod -G labteam $USER` (без `-a`)?

??? note "Відповідь"

    Додаткові групи користувача буде **замінено** на `labteam`: користувач втратить інші групи, зокрема `sudo`. Для додавання потрібно `usermod -aG`.

**7.** Чим `SIGTERM` відрізняється від `SIGKILL` і який із них слід надсилати першим?

??? note "Відповідь"

    `SIGTERM` (15) просить процес завершитися й дозволяє йому прибрати за собою; `SIGKILL` (9) завершує примусово й не може бути перехоплений. Спершу `SIGTERM`, `SIGKILL` — крайній засіб.

**8.** Що означає стан `Z` у стовпці `STAT` команди `ps`?

??? note "Відповідь"

    Зомбі-процес: він уже завершився, але батьківський процес ще не прочитав його код завершення. Його не можна «вбити» сигналом; усувати треба причину в батьківському процесі.
